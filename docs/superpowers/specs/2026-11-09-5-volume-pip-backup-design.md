# 묶음 5: 볼륨 증폭 + PIP 깜빡임 창 + 설정 백업

작성 2026-11-09. 개요 `2026-11-09-feature-expansion-overview.md`의 3절(바꾸면 안 되는 전제)과 5절(작성 규칙)을 따른다. 코드 근거는 `index.html:행`이며 [확인]은 직접 열어 본 것, [추정]은 열어 보지 못했거나 외부 지식인 것이다. 참고한 도구(maple-timer.com)의 기능 설명은 글쓴이의 주장일 뿐이라 직접 써 보지 않았다 [추정].

작성 시점에 묶음 1·2 스펙 파일은 아직 없다 [확인: `ls docs/superpowers/specs`에 개요 파일만 있음]. 그래서 이 스펙은 개요 4절의 방향만 보고 쓴 초안이며, 기대는 내용은 맨 아래 "묶음 1·2에 기대는 가정"에 모았다.

## 1. 목표

1. 알림이 작게 들리는 환경(게임 소리가 큰 경우)에서 알림 소리를 100% 넘게 키울 수 있게 한다(최대 200%).
2. 소리를 못 쓰거나 놓친 경우를 위해, 작은 항상 위 창(PIP)에 대상·타이머 상태를 보여 주고 알림 때 깜빡인다.
3. 설정(대상 구성, 등록한 템플릿, 내 소리, 수동 타이머, 화면 상태)을 JSON 파일 하나로 내보내고 불러온다.

## 2. 범위와 범위 밖

범위: 헤더 음량 슬라이더 확장과 저장, 마스터 오디오 체인, PIP 창, 백업 내보내기·불러오기.

범위 밖:
- 기본 음성 문구 변경, 알림 정책 변경(개요 3절). PIP 깜빡임은 이미 울리는 알림을 눈으로도 보이게 할 뿐 새 알림을 만들지 않는다.
- 설정 "프리셋" 여러 개 관리(참고 도구에 있다고 하나 [추정]). 백업 파일을 여러 개 두는 것으로 대신한다.
- 서버·클라우드 동기화. 모든 것은 브라우저와 사용자가 고른 파일 안에서만 움직인다.
- PIP 창 안에서 알림 색·효과를 사용자가 꾸미는 기능("PIP 창 메이커" 류). 색은 알림 종류별 고정이다.
- 모바일·Firefox·Safari.

## 3. 사용자 흐름과 화면

### 3.1 볼륨

- 헤더의 `음량` 슬라이더를 0~200%로 넓힌다(현재 `min=0 max=1 step=0.05 value=0.8`, `index.html:99` [확인]). 새 값은 `min=0 max=200 step=5`, 기본 80. 읽는 값이 퍼센트 정수가 되고, 내부 배율은 `pct/100`이라 기존 "1.0 = 지금의 100%"와 같다. 기존 기본값 0.8도 80%로 그대로다.
- 슬라이더 옆에 `80%` 숫자를 보인다. 100% 자리에 눈금(`<datalist>`)을 둔다.
- 100%를 넘으면 숫자 옆에 보조 문구: `음성은 100%까지만 커져요. 소리가 갈라지면 줄여 주세요`. 100% 이하로 돌아오면 숨긴다.
- 슬라이더에서 손을 뗄 때(`change`) 짧은 확인음(`beep('sol')` 한 번, 음성 없음)을 낸다. 그래야 알림 없이 크기를 맞춰 볼 수 있다. 드래그 중(`input`)에는 소리를 내지 않는다.
- 값은 저장한다. 지금은 음량이 저장되지 않아 새로고침하면 80으로 돌아간다 [확인: `index.html`에서 `#vol`을 읽는 곳은 391·403·458행뿐이고 `localStorage` 쓰기는 282·294행뿐]. 새 저장 위치는 `ui.volumePct`(정수 0~200). `음성` 체크도 같은 이유로 `ui.voice`에 저장한다(현재 저장 안 됨, 100행 [확인]).

### 3.2 PIP 창

- 헤더 버튼 `작은 창 열기`(열려 있으면 `작은 창 닫기`). 클릭 한 번이 사용자 동작이라 `requestWindow`를 바로 부른다.
- 창은 가로 260×세로 `44 + 행수×34`px(최대 8행, 넘으면 스크롤)로 연다. 이후 크기는 사용자가 바꾸고, 닫을 때 `ui.pip={w,h}`로 기억해 다음에 그 크기로 연다.
- 내용(위에서 아래):
  - 한 줄 상태: `감시 중` / `연결 안 됨` / `화면 안 들어옴` (`watchStatus()`와 같은 말, `index.html:540` [확인]).
  - 행: `이름 · 상태 · 남은 시간`. 예) `솔 야누스 · 켜짐 · 03:12`, `부스터 · 곧 끝나요 · 00:08`, `룬 · 나왔어요 · 00:45`, `재획 타이머 · 사냥 · 12:30`.
  - 상태 말은 카드와 같은 어휘: `켜짐`, `꺼짐`, `곧 끝나요`, `아직 못 찾음`, `등록 필요`, `꺼둠`, `나왔어요`, `멈춰 있어요`(묶음 3이 쓰면).
- 읽기 전용이다. 창 안에 조작 버튼은 두지 않는다(PRODUCT: 화면은 주로 설정할 때 본다).
- 지원하지 않는 브라우저에서는 버튼을 `disabled`로 두고 이유를 보조 문구로 보인다: `이 브라우저는 작은 창을 지원하지 않아요`.
- 창을 닫는 방법: 창의 X 또는 `작은 창 닫기`. 닫으면 버튼 문구가 되돌아온다.
- 메인 탭을 새로고침하거나 닫으면 PIP도 닫힌다 [추정: Document PiP 창은 연 문서에 묶임]. 자동으로 다시 열지는 않는다(사용자 동작이 있어야 열 수 있음).

### 3.3 백업

설명서 아래 소리 설정 근처에 `설정 백업` 영역을 둔다.

- `설정 내보내기` 버튼 + 체크박스 `내 소리 파일 포함 (약 1.2MB)`. 크기는 현재 저장된 소리 합계로 미리 계산해 보인다. 기본 체크. 누르면 `maple-web-timer-backup-20261109-2130.json`을 내려받고 `설정을 파일로 저장했어요`를 띄운다.
- `설정 불러오기` 버튼 → 파일 선택 → 검사 → 확인 창 → 적용.
- 확인 창 문구(예):
  `이 파일에서 감지 대상 5개, 수동 타이머 2개, 내 소리 3개를 불러와요. 지금 설정은 이 내용으로 바뀌어요.` 아래 체크박스 4개(`감지 대상과 등록한 아이콘` `수동 타이머` `내 소리` `음량·화면 설정`), 기본 모두 체크. 버튼 `불러오기` `취소`.
- 적용 뒤: `설정을 불러왔어요. 화면을 새로 열어요`를 잠깐 보이고 `location.reload()`. 새로고침 직후 상단에 `되돌리기` 안내는 두지 않는다(아래 4절 참고).
- 화면 공유로 감시 중이거나 테스트 이미지가 열려 있으면 불러오기를 막는다: `감시 중에는 불러올 수 없어요. 감시를 끝낸 뒤 다시 해 주세요`. 이유: 적용에 새로고침이 필요하고, 새로고침하면 화면 공유가 끊긴다 [추정: 새로고침 시 `MediaStream`이 사라짐은 일반 동작].
- 불러오는 파일에 들어 있는 등록 템플릿은 `frameW/frameH`가 지금 화면 크기와 다르면 기존 규칙대로 `다시 등록` 표시가 된다 (`needsReregister`, `index.html:288` [확인]). 별도 처리 없음.
- 개인정보 안내 한 줄(내보내기 옆): `파일은 이 컴퓨터에만 저장돼요. 등록한 아이콘 이미지(게임 화면 일부)가 들어 있으니, 남에게 줄 때는 조심해 주세요.`

## 4. 데이터 모델과 저장

### 4.1 새 저장 항목

| 위치 | 키 | 형태 | 비고 |
|---|---|---|---|
| `maple-web-timer-ui` (`index.html:292` [확인]) | `volumePct` | 정수 0~200, 기본 80 | 범위 밖이면 80 |
| 위 | `voice` | boolean, 기본 true | |
| 위 | `pip` | `{w,h}` 정수, 기본 없음 | 닫을 때 갱신 |

새 `localStorage` 키는 만들지 않는다. 묶음 1이 `ui`를 다른 모양으로 바꾸면 이 세 필드만 옮긴다.

### 4.2 백업 파일 형식 (스키마 버전 1)

```json
{
  "schema": "maple-web-timer-backup",
  "version": 1,
  "exportedAt": "2026-11-09T21:30:00+09:00",
  "includes": ["targets","manualTimers","sounds","ui"],
  "data": {
    "targets":      { /* 묶음 1 저장 v2 객체를 그대로. 등록 템플릿 data URL 포함 */ },
    "manualTimers": { /* 묶음 2 저장 객체를 그대로 */ },
    "ui":           { "volumePct": 80, "voice": true, "pip": {"w":260,"h":200}, "...": "..." },
    "sounds": {
      "sol.pre": { "name": "알림.wav", "dur": 1.8, "mime": "audio/wav", "base64": "UklGR..." }
    }
  }
}
```

- `includes`에 없는 묶음은 불러올 때 건드리지 않는다.
- `targets`·`manualTimers`는 각 묶음의 저장 형식 버전을 안에 가진다(묶음 1의 `maple-web-timer-v2` 등). 백업 `version`은 이 파일 봉투의 버전이고, 안쪽 객체의 이전은 각 묶음의 이전 함수에 맡긴다(가정 A4).
- 소리는 IndexedDB `sounds` 스토어의 `{name, data:ArrayBuffer, dur}` (`index.html:488` 부근 `rec` [확인])를 `base64`로 바꿔 넣는다. `mime`은 저장하지 않으므로 `audio/wav`로 적는다 [추정: 받는 쪽이 `decodeAudioData`라 mime은 안 쓰임].
- 화면 이미지(캡처 프레임)는 저장하지 않는다. 템플릿(작은 PNG)만 들어간다 [확인: 저장되는 것은 `tpl:{url,w,h}`, `index.html:789`].
- 크기: 템플릿은 수 KB~수십 KB [추정]. 소리가 지배적이다. 소리 1개 최대 5MB(`SOUND_MAX_BYTES`, `index.html:442` [확인]) → base64로 약 6.7MB. 슬롯이 9개(`SLOTS`, `index.html:433~443`)에서 묶음 1~4가 늘리면 이론상 수십~100MB지만 실제 WAV는 보통 수백 KB~1MB [추정]. 그래서 소리 포함은 체크박스로 끄게 하고, 불러올 때 파일이 100MB를 넘으면 읽지 않고 거절한다.
- 파일명 `maple-web-timer-backup-YYYYMMDD-HHmm.json`(로컬 시각).

### 4.3 불러오기 처리 순서

1. `File.size` > 100MB면 거절. 아니면 `file.text()` → `JSON.parse`(try/catch).
2. `migrateBackup(obj)`: `version`이 현재보다 크면 거절(`더 새 버전에서 만든 파일이라 불러올 수 없어요`). 작으면 순서대로 `v1→v2…`를 올린다. 지금은 v1뿐이라 항등.
3. `validateBackup(obj)`(순수 함수, 아래 7절): 봉투 검사 → 그룹별로 검사해 `{ok, errors[], warnings[], groups:{targets,manualTimers,sounds,ui}, counts}` 반환. 알 수 없는 필드는 버리고 경고. 숫자는 기존 `clampInt`(`index.html:288` 부근 [확인]) 규칙으로 범위를 맞춘다. 값이 깨진 항목은 그 항목만 건너뛰고 경고하며, 봉투나 그룹 전체가 깨졌을 때만 그 그룹을 오류로 처리한다.
4. 소리는 순수 검사(base64 형태·길이·5MB)를 통과한 것만, 적용 직전에 `decodeAudioData`로 디코딩해 10초 이하인지 확인한다(`SOUND_MAX_SEC`, `index.html:442` [확인]). 이 단계는 브라우저 의존이라 순수 함수 밖이다. 실패한 소리는 건너뛰고 경고.
5. 확인 창에 `counts`와 경고 수를 보여 주고 사용자가 고른 그룹만 적용한다.
6. 적용은 "교체"다(그룹 안에서 병합하지 않는다). 순서: 바꿀 `localStorage` 키들의 지금 문자열을 메모리에 보관 → `localStorage` 쓰기(하나라도 실패하면 보관한 문자열로 모두 되돌림) → IndexedDB `sounds`를 한 트랜잭션으로 `clear` + `put`(트랜잭션 안에서 다른 `await` 없음, 디코딩 확인은 그 전에 끝냄) → `tx.oncomplete`를 기다린 뒤 `reload`. IndexedDB가 실패하면 보관한 `localStorage` 문자열로 되돌리고 `설정을 불러오지 못했어요. 지금 설정은 그대로예요`. 적용 시작부터 `reload`까지 `importing` 플래그로 모든 저장(`save`, `saveUi`, 수동 타이머 저장)을 막는다.

되돌리기: 적용 직전 현재 상태를 한 번 더 내보내 파일로 자동 저장하지는 않는다(원치 않는 다운로드). 대신 확인 창에 `먼저 지금 설정 내보내기` 링크를 둔다. 이유는 6절 추천 결정 4.

### 4.4 볼륨의 저장과 마스터 체인

`unlockAudio`(`index.html:385` [확인])에서 `actx`를 만들 때 한 번 만든다:

```
(비프/내 소리 노드들) → master: GainNode(pct/100) → limiter: DynamicsCompressorNode → actx.destination
```

- 지금 비프는 노드마다 `amp=(s.gain||.18)*vol`로 음량을 직접 곱하고(391행), 내 소리는 `GainNode.gain.value=vol`(458행) [확인]. 이 곱셈을 모두 빼고 `master.gain`에서 한 번만 곱하도록 바꾼다. 비프 `amp`는 `s.gain||.18`만 남는다. 값은 `master.gain.setTargetAtTime(pct/100, now, 0.01)`로 갱신해 딱딱 소리를 피한다.
- 리미터: `threshold -3dB, knee 0, ratio 20, attack 0.003s, release 0.1s`. 이 값은 출발점이고 실제 청취·진폭 측정으로 조정한다 [추정]. `DynamicsCompressorNode`는 완전한 벽돌 리미터가 아니라 극단 피크가 아주 짧게 넘길 수 있다 [추정]. 그래서 마지막에 `WaveShaperNode`(부드러운 `tanh` 곡선)를 한 단 더 둘지는 청취 확인 뒤 결정한다(열린 질문 아님, 구현 검증 항목으로 둠).
- 100% 이하에서는 리미터가 거의 개입하지 않아야 한다. 기본 비프 진폭 `0.18`은 낮아 200%에서도 0.36으로 클리핑 아래다 [확인: `SOUNDS` gain 값은 `index.html` 앞부분에 있음, 대표 값만 봄 / 정확한 값은 구현 때 재확인]. 문제는 사용자 WAV가 이미 최대 크기로 녹음된 경우다. 이 경우 200%에서 리미터가 일한다.
- `AudioContext`가 `suspended`이면 `master`도 소리가 안 난다. 기존 `unlockAudio`가 처리 중 [확인: 385행].

### 4.5 TTS와 증폭

- `SpeechSynthesisUtterance.volume`은 0~1이며 1을 넘길 수 없다 [추정: Web Speech API 명세의 정의. 구현 때 MDN/명세로 재확인]. `speechSynthesis`의 출력은 Web Audio에 연결할 수 없어 증폭도 불가능하다 [추정].
- 결정: `u.volume = Math.min(1, pct/100)` (현재 403행은 `+$('#vol').value` 그대로 [확인]). 100% 이상에서 음성은 최대(1.0)로 고정되고, 비프와 내 소리만 더 커진다.
- 부작용: 150%에서는 비프가 음성보다 크게 들린다. 음성 앞의 경고음이 먼저 울리는 구조(`playDefault`, `index.html:416` [확인])라 "경고음으로 주의를 끌고 음성으로 내용을 알리는" 용도에는 맞다. 소리 안 들릴 때 의지하는 쪽이 음성이라면 100%를 넘겨도 음성은 안 커진다는 점을 보조 문구로 알린다(3.1).
- 대안(채택 안 함): 음성을 `AudioBuffer` 파일로 대체. 이는 "기본 음성 문구 유지" 정책과 외부 TTS 서버 금지에 걸린다.

## 5. 감지·계산 방법과 알림 동작

### 5.1 순수 함수 (모두 DOM·오디오 없이 node에서 테스트)

```
clampVolumePct(v)            → 정수 0..200, 이상값이면 80
volumeToGain(pct)            → pct/100
ttsVolume(pct)               → min(1, pct/100)
pipLevel(row, now)           → 'idle'|'ok'|'warn'|'alert'|'bad'   // 상태에서 계산. 깜빡임 여부
buildPipRows(snapshot, now)  → [{id,label,stateText,remainText,level,flashKind}]
```

`snapshot`은 묶음 1·2가 주는 읽기 전용 객체(가정 A2·B2): 대상 목록과 각 상태(`present`, `seen`, 남은 시간 또는 종료 예정 시각, 등록 필요 여부), 수동 타이머 목록과 상태, 감시 상태(`watchStatus`).

### 5.2 PIP 창이 갱신되는 방법

- 갱신 주체는 메인 탭의 `tick()`이다. Worker가 500ms마다 `tick()`을 부르므로(`index.html:798` [확인]) 탭이 숨겨져도 계속 돈다. `renderWatch()`가 "탭 제목은 숨겨져 있어도 갱신"하는 자리(`index.html:718` [확인])에 `pip.update(now)`를 한 줄 붙인다.
- 카드는 숨겨졌을 때 그리지 않지만(`if(!document.hidden) renderCard(d)`, `index.html:716` [확인]) PIP는 숨겨진 동안이 주 사용 조건이므로 이 조건과 무관하게 그린다.
- `update`는 `buildPipRows` 결과를 직전 결과와 비교해 바뀐 행의 텍스트·클래스만 바꾼다. 남은 시간은 초 단위라 500ms 두 번에 한 번만 바뀐다. 화면 낭독기가 매번 읽지 않도록 PIP 루트에 `aria-live`는 두지 않는다(`renderWatch`의 기존 방침과 같음, 541행 주석 [확인]).
- 알림이 울리는 순간 `notify()` 경로에서 `pip.flash(kind, id)`를 부른다(가정 A1). 깜빡임 시작은 `notify()`와 같은 호출에서 일어나므로 소리와 어긋나지 않는다.
- PIP DOM은 PIP 창의 `document`에 만들고, 메인 `document`의 스타일시트는 PIP 창에 복사한다(`<style>`을 복제하거나 PIP 전용 작은 CSS를 인라인). 복사 대신 전용 CSS를 새로 쓰는 쪽을 택한다(색 대비·크기를 PIP에 맞게 정하기 쉬움).

### 5.3 깜빡임 규칙

- 알림 종류별 색(밝은 면이 아닌 배경 전체 + 글자 대비 4.5:1 이상 유지): 미리 알림 호박색, 꺼짐 빨강, 룬 파랑, 연결·화면 문제 회색 줄무늬. 색만으로 구분하지 않도록 행 앞에 기호를 붙인다(`!` 미리 알림, `✕` 꺼짐, `◆` 룬, `⚠` 연결).
- 주기: 1초에 1번 켜졌다 꺼지는 정도(켜짐 0.5s/꺼짐 0.5s). 초당 3회 넘는 번쩍임은 만들지 않는다(WCAG 2.3.1의 일반 기준 [추정: 아래 기준 문서 직접 확인은 안 함]).
- 구현은 CSS 애니메이션이며, 배경색 자체를 애니메이션하지 않고 행 위에 얹은 오버레이의 `opacity`만 바꾼다(페인트 대신 합성만 일어남 [추정]).
- `prefers-reduced-motion: reduce`이면 깜빡이지 않고 강조색을 고정으로 칠한다. 판정은 PIP 창 자신의 `matchMedia`로 한다(PIP는 별도 윈도우 컨텍스트).
- 언제 깜빡이고 언제 멈추나:
  - 상태에서 계산되는 것(가려 놓고 놓치면 안 됨): 미리 알림 구간(켜진 대상의 남은 시간 ≤ `leadSec`), 룬이 화면에 있는 동안, 연결 끊김·화면 안 들어옴 중.
  - 사건에서 오는 것: `gone`·`unread`는 10초간.
  - 어느 경우든 연속 깜빡임은 최대 60초이며, 이후에는 강조색 고정으로 바꾼다. 알림 종료 조건(대상이 꺼지거나 룬이 사라지거나 재연결)이 되면 즉시 멈춘다.
- 알림 정책(개요 3절)은 그대로다. 예: 미리 알림이 울린 대상은 꺼질 때 `gone` 사건이 오지 않으므로 PIP도 `gone` 깜빡임을 만들지 않는다(알림 경로에서 오는 사건만 따른다). 연결 끊김 재알림이 2번에서 멈추는 것과 별개로 `연결 안 됨` 상태 표시는 계속 보인다. 이것은 알림이 아니라 상태 표시다.

### 5.4 열고 닫는 코드 수준 계약

```
pipSupported() → 'documentPictureInPicture' in window
pip.open()     → Promise<void>   // 클릭 핸들러에서만 호출
pip.close()
pip.update(now)
pip.flash(kind, id)
```

`pagehide`(PIP 창)에서 상태를 정리하고 버튼 문구를 되돌린다.

## 6. 추천 결정 (사용자가 고르지 않아 에이전트가 정함)

1. 증폭 범위 0~200%, 단위 5%, 기본 80%. 이유: 참고 도구의 200% 설명과 맞고, 기존 0.8 기본값을 보존해 기존 사용감이 안 바뀐다.
2. 증폭은 Web Audio `GainNode` + `DynamicsCompressorNode`. 음성은 100%에서 고정. 이유: TTS는 증폭 경로가 없다 [추정]. 한계를 UI 문구로 알린다.
3. PIP는 Document Picture-in-Picture API. 영상(`<video>`+캔버스) PiP로는 대체하지 않는다. 이유:
   - 문서 PiP는 일반 DOM·CSS를 그대로 쓰므로 텍스트·행·`prefers-reduced-motion`·`aria` 접근성을 쓰기 쉽다.
   - 영상 PiP 방식은 캔버스를 그려 `captureStream()`으로 내보내야 하는데, 숨겨진 탭에서 `requestAnimationFrame`이 멈추므로 `tick()`에서 직접 그려야 한다. 글자가 영상이라 선명도·접근성이 떨어지고, 크기 조절 시 해상도 문제도 있다 [추정].
   - 지원 대상이 데스크톱 Chrome·Edge뿐이라(PRODUCT [확인]) 두 방식을 모두 유지할 이유가 약하다. Document PiP는 Chrome 116+ 계열에서 지원된다 [추정: 외부 지식, 구현 때 MDN·caniuse로 확인].
4. 백업 불러오기는 "교체"만, 그룹별 선택. 병합은 하지 않는다. 이유: 대상 id가 같고 내용이 다를 때 어느 쪽이 맞는지 정하기 어려워 조용히 틀린 설정이 생긴다("틀린 알림보다 확인이 먼저" 원칙). 되돌리기 자동 저장은 두지 않고 `먼저 지금 설정 내보내기` 링크로 대신한다. 이유: 개인 도구라 파일 하나 더 내려받기가 번거롭지 않고, 메모리에 소리 전체를 들고 있다가 새로고침으로 날리는 것은 의미 없다.
5. 불러오기는 감시 중이 아닐 때만, 적용 후 새로고침. 이유: 이미 만들어진 카드·상태·Worker를 제자리 교체하려면 묶음 1의 모든 렌더 경로를 알아야 해 위험하다. 새로고침이 가장 단순하고 확실하다.
6. 내보내기 기본에 소리 포함, 체크 해제 가능. 이유: 사용자가 원하는 "설정 전체 백업" 의미에 맞추되, 파일 크기가 클 때 줄일 수 있어야 한다.
7. 백업 파일에 개인 식별 정보는 넣지 않는다(이름·계정 없음). 등록한 템플릿 이미지는 게임 화면 일부이므로 안내 문구를 넣는다.

## 8. 성능

- 볼륨: 마스터 체인은 오디오 스레드에서 도는 노드 두 개로 `tick()`에 비용이 없다.
- PIP: `tick()`이 하는 일은 `buildPipRows`(대상 수 N개, 수십 개 이하) + 바뀐 텍스트 비교다. 대상이 없을 때 감지 한 번이 솔 야누스 214~460ms, 부스터 약 275ms(개요 4절 [추정: 개요의 측정값을 인용])인 데 비해 마이크로초~밀리초 수준이어야 한다. 500ms 예산에 영향 없음. 구현 후 `performance.now()`로 `pip.update` 한 번을 재서 1ms 미만인지 확인한다.
- 깜빡임은 CSS `opacity` 애니메이션으로 메인 스레드 JS 없이 돈다.
- 백업: 내보내기 시 소리 base64 인코딩은 `Blob`→`FileReader.readAsDataURL`로 하고(`btoa(String.fromCharCode(...bytes))`는 큰 배열에서 호출 스택이 터짐) 소리는 하나씩 순서대로 처리한다. 이 작업은 사용자가 누른 뒤 한 번 일어나며 감시 `tick()`과 겹칠 수 있으므로, 인코딩 중에는 UI에 `저장 파일을 만들고 있어요…`를 보이고 소리 1개마다 `await`로 이벤트 루프에 양보한다.

## 9. 테스트 계획

### 9.1 node 단위 테스트 (순수 함수, 의존성 없음)

- `clampVolumePct`: `-1→0`, `250→200`, `'abc'→80`, `80.4→80`, `null→80`.
- `volumeToGain`/`ttsVolume`: 0, 80, 100, 200에서 `0, 0.8, 1, 2` / `0, 0.8, 1, 1`.
- `buildPipRows`: 켜짐/곧 끝남(`remain ≤ leadSec`)/꺼짐/아직 못 찾음/등록 필요/꺼둠/룬 있음/수동 타이머 상태 각각의 `stateText`, `remainText`(`fmt`와 같은 `mm:ss`), `level`. 경계값 `remain == leadSec`. 대상 0개.
- `pipLevel`: 알림 종료 조건에서 `ok`로 돌아가는지.
- `buildBackup(snapshot, {includeSounds})` → `validateBackup`: 왕복(round trip) 후 `normalized`가 원본과 같음.
- `validateBackup`: 스키마 이름 틀림, `version` 미래값, `data` 없음, 그룹 일부 깨짐(일부 항목 건너뛰고 경고), 알 수 없는 필드 제거, 템플릿 `url`이 `data:image/png;base64,`가 아님, `sounds[*].base64` 형식 오류·5MB 초과(디코딩한 길이 기준), 값 범위(`threshold` 0.40~0.98 등)가 `clampInt`로 맞춰지는지.
- `migrateBackup`: v1 항등, 미래 버전 거절. 이전 함수가 추가될 때마다 이전 버전 고정 파일(fixture)을 하나씩 둔다.
- base64 왕복: `Buffer`와 브라우저용 인코더가 같은 결과를 내는지(작은 배열·0바이트·5MB).

테스트 파일은 순수 함수를 `<script>` 하나로 분리한 파일에서 `require`/`vm`으로 읽는다(개요 4절의 파일 분리와 맞춤, 가정 A5).

### 9.2 브라우저 확인 (가짜 화면 스트림)

- 소리 크기: `AnalyserNode`를 `destination` 앞에 붙여 100%·200%에서 `내 소리` 피크를 측정. 200%에서 피크가 0dBFS를 넘지 않는지(리미터 동작), 비프는 음량 비례하는지. 최대 크기로 정규화된 WAV로도 청취 확인.
- 100% 이하에서 이전과 같은 크기인지(기존 0.8 설정 기준) 귀로 비교.
- 슬라이더 값이 새로고침 후에도 유지되고, 헤더 문구가 100% 초과에서만 보이는지.
- 음성이 150%에서도 1.0으로 들리는지(`u.volume`을 로그로 확인).
- PIP: 클릭으로 열림/닫힘, 창 X로 닫았을 때 버튼 복귀, 탭을 다른 창 뒤로 숨긴 채(`document.hidden === true`) 가짜 스트림으로 남은 시간이 줄고 미리 알림 시 깜빡이는지, `prefers-reduced-motion`(개발자 도구 에뮬레이션)에서 깜빡임 대신 고정 색인지, 지원 안 하는 상태(`documentPictureInPicture`를 지워서) 문구.
- PIP가 열려 있을 때 메인 탭이 `hidden`이어도 Worker `tick()`이 도는지 [추정: 현재 동작대로이며 PIP가 이를 바꾸지 않는다고 봄. 실제 확인 필요].
- 백업: 소리 3개를 등록하고 내보내기 → 저장소 삭제(개발자 도구) → 불러오기 → 같은 설정·소리가 복원되는지. 파일을 손으로 고쳐 오류 문구 각각 확인. 5MB 소리 포함 파일의 내보내기·불러오기 시간.
- 감시 중 불러오기 차단 확인.

## 검토 반영 (2026-11-09)

독립 검토를 원문·코드와 대조해 받아들인 것. 본문·"맞춘 결과"와 다르면 이 절이 우선한다.

1. **[중간] 대상과 내 소리는 한 묶음으로 불러온다.** 슬롯 키가 대상 id에 묶여 있어 따로 고르면 묶음 1의 고아 정리가 소리를 지운다 [확인 묶음 1 4.4·4.5]. 그룹 체크박스는 `감지 대상과 내 소리`를 하나로 둔다. 소리를 뺀 백업으로 대상을 교체하면 확인 창에 `지금 내 소리 N개가 지워져요`.
2. **[중간] 적용 순서와 원자성.** 4.3 6번을 고쳤다: `localStorage` 먼저(이전 문자열 보관, 실패 시 되돌림) → IndexedDB 한 트랜잭션 → `oncomplete` 뒤 `reload` [확인 원래 순서는 105·207행].
3. **[중간] 적용 중 저장 막기와 실행 중 타이머.** `importing` 플래그로 모든 저장을 막는다(4.3 6번). 실행 중인 수동 타이머가 있으면 확인 창에 `실행 중인 타이머 N개가 멈춰요`.
4. **[중간] 수동 타이머 검사.** `validateBackup`이 `manualImport` 전에 버전과 모양을 검사한다(`manualImport`는 깨진 입력을 빈 목록으로 돌려줌 [확인 묶음 2]). 확인 창에 `타이머 N개`를 보인다.
5. **[중간] 100% 이하에서 이전과 같은 크기.** 리미터(`DynamicsCompressorNode`)는 볼륨이 100%를 넘을 때만 경로에 넣는다(100% 이하는 `GainNode`만). 9.2에 "100%에서 이전 대비 dB 차이"를 측정 항목으로 더한다.
6. **[중간] PIP 깜빡임은 알림에서만 시작.** 깜빡임은 `Alerts.listen`으로 받은 알림에서만 시작한다. 상태(연결 끊김·화면 안 들어옴·룬 있음)는 깜빡이지 않고 고정 강조로만 보인다. 이벤트→종류 표: `pre`·`manual.pre` → 미리 알림, `gone`·`end`·`next1/2` → 꺼짐, `appear`·`remind` → 룬, `lost`·`stall`·`unread`·`alarm` → 문제, `back` → 문제 강조 해제. 순수 함수는 `pipLevel(row, flashState, now)`.
7. **[중간] 접근성: 연속 깜빡임 5초 상한.** 깜빡임은 최대 5초 뒤 고정 색으로 바뀐다(움직임 줄이기 설정이면 처음부터 고정 색). 60초 상한은 버린다.
8. **[중간] 슬라이더 확인음.** `change` 핸들러는 `unlockAudio()`를 먼저 부르고, 마스터 체인은 묶음 1의 `Alerts.onAudioReady`에서 만든다 [확인 `beep`은 `actx`가 없으면 아무것도 안 함 `index.html:390`].
9. **[낮음] PIP 세부.** `requestWindow`는 사용자 클릭 안에서만 부른다. 열려 있는지는 `documentPictureInPicture.window`로 판단한다. 창 크기는 `resize`를 디바운스해 저장한다. 보안 컨텍스트가 필요하다(`file://`에서 되는지는 [추정], 9.2에서 확인).
10. **[낮음] 크기 제한.** 불러오기 파일 상한은 50MB. 템플릿 data URL은 500KB 이하, `w/h` 4~512px.
11. **[낮음] `ui`는 허용 목록만.** 백업의 `ui`는 `volumePct`, `voice`, `pip`만 옮긴다(`connectedOnce`·`open` 같은 화면 상태는 제외). `data.targets`가 v1 모양이면 4.3 3번 검사 전에 `migrateV1`을 부른다. 모르는 `kind`는 건너뛰고 확인 창에 경고한다.
12. **[낮음]** 인용 행: `needsReregister` `:296`, `SOUND_MAX_*` `:446`, IndexedDB 저장 `:479`, `SLOTS` `:435-445`.
