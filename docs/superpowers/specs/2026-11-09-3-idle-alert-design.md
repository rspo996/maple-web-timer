# 묶음 3: 사냥 멈춤 알림 (새 대상 종류 `idle`)

작성 2026-11-09. 개요(`2026-11-09-feature-expansion-overview.md`) 3절(전제)과 5절(작성 규칙)을 따른다. 묶음 1 스펙(`...-1-target-list-buffs-design.md`)은 이 문서를 쓰는 시점에 아직 없었다. 그래서 묶음 1에 기대는 내용은 전부 7절에 가정으로 모았다. 묶음 1이 나오면 7절부터 맞춘다.

근거 표기: [확인] = 이 문서를 쓰며 `index.html`이나 PRODUCT.md를 직접 열어 확인함. [추정] = 코드·문서로 확인하지 못했거나 게임 화면에 대한 짐작. 이 저장소에는 게임 스크린샷 샘플이 없다(PRODUCT.md:93 [확인]). 그래서 픽셀 수·기준값 같은 숫자는 전부 [추정]이고, 실제 화면으로 맞추는 절차를 9절에 넣었다.

참고한 도구(maple-timer.com "동꼽방지")의 동작은 글 작성자의 설명일 뿐이고 직접 써 보지 않았다. 설명은 "경험치 막대를 화면에서 보다가 숫자가 일정 시간 안 변하면 알림", 나중에 "스킬 쿨타임 모드" 추가, "막대가 45%를 넘으면 버그가 있었다"는 작성자 메모다. 모두 [추정]이다. 45% 버그의 원인은 알 수 없고, 아래 방식과의 관련도 확인할 수 없다.

## 1. 목표

- 사냥 중 경험치가 일정 시간 안 변하면 소리·음성으로 알려, 캐릭터가 죽었거나 튕겼거나 멈춘 걸 놓치지 않게 한다. (PRODUCT.md 원칙 1: 귀로 쓰는 도구)
- 화면 캡처만 쓴다. 경험치를 게임에서 읽어 오지 않고 화면의 막대 영역이 바뀌었는지만 본다. (PRODUCT.md:58-59)
- 틀린 알림보다 확인이 먼저다. 맵 이동 암전, 화면 안 들어옴, 영역 등록 중, 해상도 변경 중에는 울리지 않는다. (원칙 3)

## 2. 범위와 범위 밖

범위
- 새 대상 종류 `idle` 하나, 인스턴스는 1개(id는 묶음 1 규칙의 `u<n>`, 15절).
- 영역 드래그 1회 등록, 멈춤 시간·반복 설정, 쉬기(스누즈), 카드·상태줄 표시, 내 소리 슬롯 1개.

범위 밖
- 경험치 숫자 읽기(OCR)와 증가량 계산.
- 스킬 쿨타임 모드. 묶음 4가 `cooldown` 종류로 다룬다. 영역 변화 감지 부품은 나중에 다른 종류가 재사용할 수 있게 순수 함수로 분리한다.
- 마을·메뉴 자동 인식(쉬기는 사용자가 누른다).
- 사냥 결산, 서버·외부 API.

## 3. 감지 방법 비교와 추천

| 방법 | 어떻게 | 장점 | 단점 |
|---|---|---|---|
| (a) 숫자·퍼센트 OCR | 경험치 글자를 읽어 값이 바뀌었는지 | 값이 정확하면 증가량까지 안다 | 글꼴·UI 배율·해상도마다 글자 모양이 달라 새 OCR이 필요하다. 지금 OCR은 7세그먼트 전용이다(`index.html:216-244` [확인]). 쉼표·괄호·% 섞인 글자는 오독이 잦을 것이다 [추정]. 오독 하나가 "변했다"로 보여 알림을 놓치고, 못 읽으면 판단 자체가 불가능하다 |
| (b) 영역 이미지 변화(추천) | 사용자가 드래그한 영역을 회색조로 줄여 기준 프레임과 비교, 달라진 픽셀 수를 센다 | 글자를 해석하지 않으므로 글꼴·배율·언어와 무관. 막대 길이와 숫자 글자가 모두 바뀌므로 어느 쪽이 변해도 잡는다. 구현이 작고 비용이 낮다 | "경험치가 올랐다"가 아니라 "영역이 바뀌었다"만 안다. 영역에 움직이는 그림이 있으면 항상 변함으로 오판한다 |
| (c-1) 막대 채움 길이만 측정 | 막대 색 픽셀의 끝 위치를 찾음 | 숫자 글자 영향 없음 | 해상도 1920 기준 한 칸이 약 0.05%라 작은 경험치는 한동안 안 변한다 [추정]. 막대 색·배경 대비 가정이 필요하고, 막대가 반쯤 찬 뒤에 틀린다는 작성자 메모와 겹칠 수 있다 |
| (c-2) 캐릭터·몹 움직임, 미니맵 점 | 다른 신호로 사냥 중인지 추정 | 없음 | 경험치와 직접 관계가 없고 영역이 넓어 비용·오판이 크다 |

추천: (b). 막대와 숫자 글자를 함께 포함한 좁은 영역을 등록한다. 이유는 다음과 같다.
- 한 번 잡은 몹의 경험치는 숫자의 끝자리가 바뀌므로, 막대 길이가 안 변해도 글자가 바뀌어 잡힌다 [추정, 실제 화면으로 확인 필요].
- 해석이 없으니 "잘못 읽은 값"이 생기지 않는다. 오판은 "변했다/안 변했다" 두 가지뿐이라 연속 확인으로 막을 수 있다.
- 해상도·UI 배율이 바뀌면 영역도 다시 등록하는 기존 규칙(PRODUCT.md:33)으로 충분하다.

한계는 숨기지 않고 화면에 쓴다: 이 알림은 "영역이 그대로"를 알리는 것이지 "사냥을 안 한다"를 보증하지 않는다. 경험치가 안 오르는 정상 상황(보스 대기, 경험치가 더 안 오르는 구간 등)에서는 쉬기를 쓴다.

### 3.1 변화 지표

- 입력: 등록 영역을 프레임에서 잘라 회색조(`toGray`, `index.html:148-152`)로 만든 값. 영역이 12만 픽셀을 넘으면 비율을 유지해 줄인다(등록 단계에서 영역 높이를 제한하므로 거의 안 일어난다).
- 비교 기준은 직전 프레임이 아니라 **기준 프레임(anchor)** 이다. 비교 대상이 직전 프레임이면 한 번 바뀐 값이 다음 틱에는 사라져 연속 확인이 안 된다.
- 지표 `changedPx` = 기준 프레임과 현재 프레임에서 회색조 값 차이가 24 이상(0~255)인 픽셀 수. 차이 24는 압축 잡음을 무시하기 위한 값이다 [추정].
- "변함" 판정: `changedPx >= minPx`(기본 8, 설정 범위 3~60). 숫자 끝자리 한 글자가 바뀔 때 달라지는 픽셀을 1080p에서 15~40개 정도로 본 값이다 [추정]. 비율이 아니라 개수로 둔 이유는, 영역이 가로로 길면 비율 기준이 글자 한 자리 변화를 놓치기 때문이다.
- 연속 확인: `changedPx >= minPx`가 **2틱 연속**(약 1초)이면 변화로 확정하고, 그때 기준 프레임을 현재 프레임으로 교체한다. 한 프레임짜리 번쩍임은 무시된다. 실제 변화는 기준과 계속 달라서 두 번째 틱에도 남는다. (원칙 3의 "연속으로 확인한 뒤에 반응", `index.html:119` 근거와 같은 취지)
- 샘플링: 매 틱(500ms, `index.html:798` [확인]). 화면 공유는 5fps 요청(`index.html:594` [확인])이라 틱마다 새 프레임이 있을 수도 없을 수도 있고, 같은 프레임을 두 번 봐도 비교 결과는 같으므로 문제없다.

### 3.2 잡음·애니메이션 처리

- 압축 잡음: 픽셀 차이 24 미만은 무시. 그래도 정지 영상에서 8픽셀 이상 흔들리면 기준값(`minPx`) 슬라이더로 올린다. 카드에 실시간 "변화량 N픽셀"을 보여 줘서 맞출 수 있게 한다(일치도 표시와 같은 방식, `index.html:354`).
- 번쩍임: 연속 확인 + 기준 프레임 비교로 대부분 걸러진다.
- 항상 변하는 영역: 영역 안에 움직이는 그림(이펙트 등)이 들어 있으면 경험치가 안 변해도 계속 변함으로 판정돼 알림이 영영 안 울린다. 최근 60초(120틱) 중 90% 이상에서 `changedPx >= minPx`이면 카드에 "영역이 계속 변해요 · 경험치 막대와 숫자만 드래그해 주세요"를 표시한다. 소리는 내지 않는다. [추정: 90%·60초는 정할 근거가 없는 시작값]
- 영역 가림: 다른 창이 막대를 가리면 바뀐 것으로 보여 알림이 안 울린다. 안전한 쪽의 오류라 허용한다.

## 4. 사용자 흐름과 화면

### 4.1 등록

기존 흐름(영역 → 아이콘 두 번 드래그, `index.html:761-792`)을 쓰되 `idle`은 **영역 한 번**으로 끝난다.

1. 카드의 "등록" → 배너 "사냥 멈춤 · 경험치 막대와 숫자를 한 번에 꼭 맞게 드래그하세요".
2. 드래그가 끝나면 바로 저장한다. 템플릿(`tpl`)은 만들지 않는다. 그 순간의 영역 이미지를 카드 미리보기(`thumb`, PNG 데이터 URL)로 저장하고 `frameW/frameH`를 기록한다. 여기까지 `index.html:786-791`의 "영역 넓히기 + tpl 저장" 대신 아래 검증을 한 뒤 저장한다.
3. 검증(저장 전). 통과하지 못하면 저장하지 않고 배너에 이유를 쓰고 다시 드래그를 받는다.
   - 너무 작음: 가로 40px 미만 또는 세로 6px 미만 → "영역이 너무 작아요".
   - 너무 큼: 세로가 화면 높이의 8%를 넘음 → "영역이 너무 넓어요. 경험치 막대와 숫자만 드래그해 주세요". 넓으면 화면의 다른 움직임이 섞여 영영 안 울린다. [추정: 8%는 막대 높이를 모른 채 정한 값. 실제 화면에서 확인]
4. 저장 후 노트: "사냥 멈춤 등록했어요 · 사냥하면서 변화량 숫자가 움직이는지 확인해 주세요".

프리셋(화면 아래 자동 영역)은 두지 않는다. 막대의 위치·두께가 설정마다 다를 수 있는데 확인할 화면이 없다. (추천 결정 12-2, 열린 질문 Q2)

### 4.2 해상도·창 크기가 바뀔 때

기존 규칙과 같다. `frameW/frameH`가 현재 프레임과 다르면 카드는 "다시 등록 필요 · 등록 당시 화면 W×H, 지금 W×H"(`index.html:359` 문구 재사용)를 보이고, 상태줄에는 "사냥 멈춤 다시 등록" 버튼이 나온다(`index.html:550`). 감지는 쉬고, 다시 등록하기 전까지 알림이 없다. 소리는 내지 않는다(기존 대상과 동일). 영역을 비율로 저장해 자동 보정하는 방식은 쓰지 않는다. UI 배율이 바뀌면 막대 두께·글자 크기가 달라져 비율 보정이 맞지 않는다 [추정].

기존 카드 틀을 따른다(`index.html:299-347`). 이름 "사냥 멈춤", 아이콘 자리에 영역 미리보기(`thumb`).

### 4.4 쉬기(스누즈)

마을·메뉴·자리 비움처럼 일부러 경험치를 안 올릴 때를 위한 버튼. "쉬기"를 누르면 3가지를 고른다.

- 10분
- 30분
- 다시 변할 때까지: 확정된 변화가 쉬기 시작 15초 뒤 이후에 한 번 나오면 자동으로 끝난다(시작 직후 화면 전환 잔상으로 끝나지 않게 15초는 무시).

쉬기가 끝나면 시간은 처음부터 다시 센다. 쉬기 상태는 저장하지 않고 새로 고침이나 다시 연결하면 사라진다(실수로 계속 꺼 둔 채 사냥하는 일을 막는다). 쉬기 중에도 카드에 남은 시간을 보여 주고, 상태줄에는 "사냥 멈춤 쉬는 중"을 보인다. 쉬는 도중 "쉬기 끝내기" 버튼이 같은 자리에 나타난다.

### 4.5 상태줄

`renderWatch`(`index.html:539-559`)의 대상 목록 칸에 `idle`이 일반 대상처럼 이름으로 나온다. 상태 값이 늘어난다.

| 값 | 표시 | 비고 |
|---|---|---|
| ok | 사냥 멈춤 | 기본 |
| reg / rereg | 사냥 멈춤 등록하기 / 다시 등록 | 기존 버튼 규칙 그대로 |
| off | 사냥 멈춤 꺼둠 | 기존 |
| snooze | 사냥 멈춤 쉬는 중 | 새로 추가. 회색 |
| idle | 사냥 멈춤 · 경험치 그대로 | 새로 추가. 경고 색. 알림이 울린 뒤 변하면 ok로 돌아감 |
| unseen | 해당 없음 | `unseen`은 `kind!==rune`이면 붙는 조건(`index.html:542`)이라 `idle`은 제외해야 함 |

상태줄 키(`watchKey`, `index.html:543`)에 idle 값이 들어가므로, 경과 초 같은 매초 바뀌는 값은 넣지 않는다(화면 낭독기가 매 틱 읽는 걸 막으려는 기존 의도).

미리보기 캔버스(`drawPreview`, `index.html:726-755`): 등록 영역을 하늘색 테두리로 그리고 그 아래에 "사냥 멈춤 변화 N / 기준 8" 라벨을 붙인다. 일치도 라벨과 같은 방식이라 기준값을 맞출 때 카드와 캔버스를 오가지 않아도 된다.

## 5. 알림 동작

### 5.1 언제 울리는가

- 확정된 마지막 변화(`lastChangeAt`)로부터 `idleSec`(기본 120초)가 지나면 **한 번** 울린다.
- 다시 울리는 규칙: 기본 설정에서 처음 알림 뒤 `repeatSec`(기본 120초)마다 최대 2번 더 울리고 **멈춘다**. 연결 끊김 재알림이 "즉시 1번 + 2분 간격 2번에서 멈춤"(PRODUCT.md:53, `index.html:525` [확인])인 것과 같은 모양이다. 룬의 무한 반복(`index.html:205`)과는 다르다. `repeatSec`가 0이면 처음 한 번만 울린다. (열린 질문 Q1)
- 다시 걸기: 변화가 한 번 확정되면 알림 상태가 풀리고 횟수가 0으로 돌아가 다음 멈춤에서 다시 울린다. 울림 뒤 아무 변화도 없으면 3번(처음+2번) 이후로는 조용히 기다린다.
- "다시 움직여요" 같은 회복 소리는 내지 않는다. 사냥을 다시 시작한 사람은 이미 알고 있고, 소리가 늘면 귀에 거슬린다. 카드 sub에 "N분 멈췄다가 다시 변했어요"를 몇 분간 남긴다. (열린 질문 Q4)

### 5.2 소리·음성

- 문구(해요체): "경험치가 2분째 그대로예요". 반복할 때는 실제 경과 시간으로 "경험치가 4분째 그대로예요". 60초 미만이면 "N초째", 이상이면 분 단위(내림), 10분 이상도 분 단위. 문구가 달라서 음성 중복 방지(같은 문구 8초 안 건너뜀, `index.html:401`)에도 걸리지 않는다.
- 경고음: 새 `SOUNDS.idle`을 둔다. 기존과 겹치지 않는 느린 두 음 왕복(삼각파, 예: 587Hz·440Hz·587Hz·440Hz, 음마다 0.3초 안팎). 솔(딩딩-동), 부스터(딱딱딱-동), 꺼짐(내려가는 두 음), 룬(올라가는 세 음), 시스템(낮은 톱니파 3번, `index.html:377-383`)과 구분돼야 한다. 음은 시작값이고 직접 들어 보고 정한다.
- 내 소리 슬롯 키: `<대상id>.alarm`, 예 `u4.alarm` (규칙 `대상id.이벤트`, `index.html:428`). 반복 알림도 같은 슬롯을 쓴다. 슬롯 표시: 그룹 "사냥 멈춤", 항목 "멈춤 알림". 알림 소리 바꾸기 목록(`SLOTS`, `index.html:435`)에 한 줄이 추가된다.
- 브라우저 알림(탭이 숨겨졌을 때)과 탭 제목 깜빡임은 `notify`가 처리한다(`index.html:421-423`). 알림 `tag`는 대상 id를 써서 반복 알림이 서로 덮어쓰게 한다.

### 5.3 알림 테스트

카드의 "알림 테스트"는 "경험치가 2분째 그대로예요" 문구(설정한 멈춤 시간 기준)로 `<대상id>.alarm` 슬롯 경로를 그대로 탄다.

## 6. 다른 상태와의 관계 (이중 알림·오경보 방지)

원칙: `idle` 감지기는 "믿을 수 없는 프레임"을 만나면 **시간을 처음부터 다시 센다**(멈추는 게 아니라 초기화). 화면이 안 들어오거나 맵이 바뀌는 동안은 경험치가 어떻게 됐는지 모르므로 쌓인 멈춤 시간을 버리는 게 안전한 쪽이고, 맵 이동은 대체로 사냥 중의 일이다.

| 상황 | 코드 근거 | idle 동작 |
|---|---|---|
| 검은 프레임·맵 이동 암전 | `isBlank`, `ok=false` (`index.html:682-695` [확인]) | 샘플 없음(null). 돌아오면 첫 프레임을 새 기준으로 삼고 시간 초기화 |
| 화면이 안 들어옴(timeout) | `grab()`이 null (`index.html:580` [확인]), 10초 뒤 `fireSystem('stall')` (`index.html:698` [확인]) | 같다. idle 알림은 울리지 않고 stall 알림 하나만 간다. 돌아오면 초기화 |
| 연결 끊김 | `track.onended` → 상태 초기화 (`index.html:600-604`, `608` [확인]) | 대상 상태가 새로 만들어져 처음 프레임부터 다시 시작 |
| 등록 중 | 감지는 `!reg`일 때만 (`index.html:704` [확인]) | 샘플 없음. 등록이 끝나면 초기화 |
| 해상도 달라짐 | `detect`의 프레임 크기 비교 (`index.html:657` [확인]) | 샘플 없음, 카드는 "다시 등록 필요" |
| 사용 꺼짐 | `c.enabled` (`index.html:704` [확인]) | 샘플 없음. 다시 켜면 초기화 |
| 스크린샷 테스트 | `src.type==='image'` (`index.html:623` [확인]) | 감지 안 함. 한 장짜리 이미지는 영원히 안 변해서 알림이 울리기 때문 |
| 탭 숨김 | `grab()`은 숨겨졌을 때 `ImageCapture.grabFrame`을 쓰고, 에러(타임아웃 외)면 `video`로 돌아감 (`index.html:578-582` [확인]) | 프레임이 새로 온 것이 확실할 때만 샘플. 아래 6.1 |
| 다른 대상 알림과 겹침 | `beepEnd` 순서 예약 (`index.html:384-396`, `459` [확인]) | 별도 처리 없음. 순서대로 이어서 울림 |

### 6.1 숨겨진 탭에서 오래된 프레임

탭이 숨겨졌을 때 `grabFrame`이 타임아웃이 아닌 에러를 내면 코드가 `src.video`로 돌아간다(`index.html:580-582` [확인]). 백그라운드 탭의 `video` 요소가 새 프레임 없이 마지막 화면을 돌려줄 수 있다는 것은 [추정]이다. 그 프레임을 기준과 비교하면 "안 변했다"로 보이고 가짜 멈춤 알림이 울린다. 대책: `grab()`이 프레임을 `grabFrame`으로 받았는지 `video`로 받았는지 구분하는 표시를 남기고, 숨김 상태에서 `video`로 받은 프레임은 `idle`에 null로 넘긴다. 구현할 때 `grab()` 반환 형태를 바꾸지 않고 모듈 변수(예: `lastGrabFresh`)로 알리는 쪽이 `grab()`의 기존 호출부(`index.html:693`, `758`)를 안 건드린다. 구현 전에 실제로 확인할 일이다(9절).

### 6.2 알림 종류 구분

- 화면 문제(stall, lost)는 시스템 알림(낮은 경고음)이고 idle은 게임 알림(새 경고음). 한 사건에서 둘이 같이 울리지 않는다. stall이 먼저 떠 있는 동안은 idle이 샘플을 못 받기 때문이다.
- 가까운 알림 묶기(묶음 1)는 버프 종료 알림용이다. idle은 묶기 대상에서 제외하고 그대로 따로 울린다(가정 7-8).

## 7. 묶음 1에 기대는 가정

> 2026-11-09: 묶음 1 스펙과 대조한 결과는 15절에 있다. 아래 가정과 다르면 그 절이 우선한다.

묶음 1 스펙이 확정되면 하나씩 맞춰 본다. 어긋나면 이 문서를 고친다.

1. **대상 종류 추가 방식.** 대상 목록의 각 항목이 `kind`를 갖고, 새 종류를 추가하는 방법이 "종류 정의" 한 묶음이다. 종류 정의가 다음을 제공한다. 이름 기본값, 카드 필드 구성(설정 칸 목록), 알림 이벤트 목록(슬롯 키와 라벨), 등록 단계 목록(`area` 하나만 있는 종류도 가능), `isRegistered`와 `needsReregister` 판정, 틱 처리 함수.
2. **등록 판정이 종류별.** 현재 `needsRegister`·`needsReregister`·`detect`는 `tpl`이 있는지를 본다(`index.html:295-296`, `657` [확인]). `idle`은 `tpl`이 없고 `area`만 있으므로 판정을 종류별로 바꿔야 한다.
3. **틱 호출 형태.** 종류의 틱 처리가 "대상, 설정, 상태, 프레임 소스, 현재 시각, 건강 상태"를 받아 이벤트 목록을 돌려준다. 그리고 **건강 문제나 등록 모드로 감지를 건너뛰는 틱에도 종류에게 알려 준다**(`null` 샘플). 지금은 `ok && enabled && !reg`가 아니면 아예 호출하지 않는다(`index.html:704`). `idle`은 건너뛴 틱을 알아야 시간을 초기화할 수 있다.
4. **알림 경로.** `fire(d, kind)`/`notify(msg, sound, tag, slot)` 경로(`index.html:418-430`)가 유지되고, 문구 함수가 이벤트에 붙은 값(경과 시간)을 받을 수 있다. 지금 `MSG[kind](d, c)`는 설정만 받으므로 세 번째 인자(이벤트 정보)가 필요하다.
5. **내 소리 슬롯.** 슬롯 키 `대상id.이벤트`, 슬롯 목록이 종류 정의의 이벤트에서 만들어진다(`SLOTS`, `index.html:435`). `idle`의 이벤트는 `alarm` 하나. 기본 소리 이름은 종류 정의가 정하고, `SOUNDS`에 `idle`이 한 줄 추가된다.
6. **저장.** 대상별 설정은 `maple-web-timer-v1` 아래 대상 id 키의 객체이고, `kind`가 객체에 들어간다(`index.html:280` [확인]). `idle` 객체는 `{kind:'idle', enabled, area, frameW, frameH, thumb, idleSec, repeatSec, minPx}`. 기존 v1 설정과 충돌하지 않게 새 대상은 사용자가 "대상 추가"를 눌렀을 때만 만든다(그 전에는 목록에 없음). 인스턴스는 1개만 허용하는 종류 속성이 필요하다.
7. **등록 흐름 재사용.** 드래그 배너·좌표 변환·저장 흐름(`index.html:761-792`)이 종류가 단계 목록을 주는 방식으로 일반화되고, 마지막 단계에서 종류가 저장 내용을 만드는 훅이 있다. 지금은 두 번째 드래그에서 `tpl`을 만드는 것이 하드코딩돼 있다(`index.html:785-791`).
8. **묶기 제외.** 가까운 알림 묶기는 종류가 "묶을 수 있음" 표시를 가진 이벤트(버프 `pre`, `gone` 등)만 모은다. `idle.alarm`은 표시가 없어 묶이지 않는다.
9. **파일 구성.** 순수 함수(`stepIdle`, `lumaDiffRatio`)는 첫 번째 `<script>`에 있는 `stepDetector`류(`index.html:147-264`)처럼 DOM 의존이 없는 일반 `<script>` 파일에 두고, node에서 불러 쓸 수 있는 형태(`module.exports` 조건부 내보내기)로 만든다. `file://`로 열리는 조건 때문에 ES 모듈은 쓰지 않는다(개요 4절).
10. **상태줄·카드 갱신 확장.** `renderCard`와 `renderWatch`의 분기가 종류 정의에서 상태 문구와 상태줄 값을 받는 방식이다. `idle`의 `snooze`·`idle` 상태줄 값은 종류가 돌려준다.
11. **샘플 소스 접근.** 종류의 틱 처리에서 공유 `work` 캔버스(`index.html:565`)로 영역을 잘라 읽을 수 있다. 틱이 직렬이라 충돌하지 않는다(`busy` 가드, `index.html:691`).

```
        idleSec:120, repeatSec:120, minPx:8 }
```

런타임 상태(저장 안 함): `{phase:'init'|'watch'|'idle'|'snooze', anchor:Uint8Array|null, lastChangeAt, diffStreak, gap, alertCount, nextAlertAt, snoozeUntil, snoozeMode, snoozeStartAt, lastPx, recent:[ticks], seen}`.

## 9. 감지·계산 구조와 순수 함수 인터페이스

감지의 비순수 부분(영역 자르기, 회색조 변환, 기준 프레임 저장)과 상태기계(순수)를 나눈다.

```
// 두 회색조 배열에서 차이가 minDelta 이상인 픽셀 수
function lumaDiffCount(a: Uint8Array, b: Uint8Array, minDelta: number): number

// obs: {px:number} | null (null = 믿을 수 없는 틱). 돌려주는 이벤트:
//   'rebase'  호출자가 기준 프레임을 현재 프레임으로 교체
//   'confirm' 변화 확정, 호출자가 기준 프레임 교체
//   {idle:{elapsedSec,repeat:boolean}}  알림
//   'resume'  알림 뒤 변화가 다시 확정됨
//   'snooze-end'
function stepIdle(st, cfg, obs, now): Event[]

function startSnooze(st, mode:'10m'|'30m'|'until-change', now): void
function endSnooze(st, now): void
```

`stepIdle` 규칙(요약):
1. `obs==null`이면 `st.gap=true`, 아무 이벤트 없이 돌아간다. 쉬기 시간(`snoozeUntil`) 점검은 이 경우에도 한다.
2. 처음 유효 샘플이거나 `st.gap`이면: `'rebase'`, `lastChangeAt=now`, 연속 카운트 0, `gap=false`, `phase`가 `idle`이면 `watch`로 되돌리고 횟수 0. 이 틱은 변화로 세지 않는다.
3. `obs.px >= cfg.minPx`면 연속 카운트를 올리고 아니면 0. 카운트가 2이면 `'confirm'`(`lastChangeAt=now`, 카운트 0). `phase`가 `idle`이었다면 `'resume'`을 더하고 `watch`로 되돌리며 횟수를 0으로 한다. `until-change` 쉬기이고 쉬기 시작 15초 뒤 이후이면 `'snooze-end'`.
4. `phase==='watch'`이고 `now-lastChangeAt >= idleSec*1000`이면 `idle`로 바꾸고 `{idle:{elapsedSec, repeat:false}}`, 횟수 1, `nextAlertAt=now+repeatSec*1000`(`repeatSec`가 0이면 `Infinity`).
5. `phase==='idle'`이고 `now >= nextAlertAt`이고 횟수 < 3이면 `{idle:{..., repeat:true}}`, 횟수+1, `nextAlertAt` 갱신.
6. `phase==='snooze'`이고 `now >= snoozeUntil`이면 `watch`로 돌아가고 `lastChangeAt=now`, `'snooze-end'`.

쉬기 중(`phase==='snooze'`)에는 4·5번 알림이 나가지 않는다. 기준 프레임 갱신(2·3번)은 계속하되 알림은 없다.

호출자(틱 안의 `idle` 종류 코드)가 하는 일: `ok && enabled && !reg && 프레임 크기 일치 && 신선한 프레임 && 스트림 소스`이면 영역을 잘라 회색조로 만들어 기준과 `lumaDiffCount`를 구해 `{px}`로 넘기고, 아니면 `null`. 이벤트 `'rebase'`/`'confirm'`이면 기준을 교체. 알림 이벤트면 `fire`.

## 10. 성능

- 틱마다 비용(`idle`): 영역 `drawImage` + `getImageData`(영역 약 700×16에서 최대 약 120k 픽셀) + 회색조 변환 + 차이 세기 한 번. 약 1~3ms를 예상한다 [추정, 이 문서에서 재지 않음].
- 비교 대상: 대상이 없을 때 기본 아이콘 검색이 솔 야누스 214~460ms, 부스터 약 275ms(개요 4절 [추정: 인용, 이 Mac에서 측정했다는 값]). 그래서 `idle`의 추가분은 주기 500ms에 비해 작다.
- 메모리: 기준 프레임 최대 120KB, 영역 읽기 버퍼 재사용.
- 숨겨진 탭: `grabFrame` 비트맵은 틱마다 한 장이고 모든 대상이 공유한다(`index.html:579`).
- 구현 뒤 확인: `performance.now()`로 `idle` 처리 시간을 재서 틱 합계가 500ms를 넘지 않는지 본다. 영역이 상한(높이 8%)일 때를 최악으로 잰다.

## 11. 오류·예외 정리

- 영역이 프레임 밖이 되는 경우(해상도 변경): 4.2와 같다.
- `getImageData` 예외나 크기 0: 샘플 `null`로 처리하고 카드에 "영역을 읽지 못했어요"를 보인다. 소리 없음.
- 기준 프레임이 없는 첫 유효 틱: 알림 없이 기준만 저장한다.
- 이미 알림이 울린 뒤에 화면 문제가 생기면 `gap`으로 알림 상태가 풀린다(위 2번). 화면이 돌아온 뒤 다시 `idleSec`가 지나야 다시 울린다.
- 게임이 완전히 얼어서 화면은 오는데 그림이 안 바뀌는 경우: 영역이 그대로이므로 idle이 울린다. 이 경우는 알림이 맞다.
- 최고 레벨 등 경험치가 오르지 않는 상황: 알림이 울릴 수 있다. 쉬기나 사용 끄기를 쓴다. 이 도구가 알 방법이 없다.

## 13. 테스트 계획

### 13.1 순수 함수 단위 테스트 (node)

`lumaDiffCount`와 `stepIdle`을 시각(`now`)과 `obs`를 직접 넣어 검증한다. 실제 화면 없이 돌아간다.

- 차이 개수: 동일 배열 → 0, 24 미만 흔들림 → 0, 정확히 임계값 24 → 센다, 8픽셀만 크게 다름 → 8.
- 변화가 계속되면 안 울림(10분 분량 틱).
- 정지: 마지막 변화 + 120초에 알림 1번, 그 전 틱에는 없음.
- 반복: 120, 240초에 2번 더, 이후 없음. `repeatSec=0`이면 1번만.
- 재무장: 알림 뒤 변화 2틱 연속 → `resume`, 다음 정지에서 다시 울림.
- 1틱짜리 번쩍임(변함 → 안 변함)은 확정되지 않아 `lastChangeAt`이 바뀌지 않음.
- 샘플 `null`이 끼면 시간 초기화: 100초 정지 중 `null` 한 틱 → 그 뒤 다시 120초가 지나야 알림.
- 알림이 울린 뒤 `null` → `watch`로 복귀, 횟수 0, 이전 알림 반복이 나가지 않음.
- 쉬기: 10분 쉬기 중 알림 없음, 끝난 뒤 시간 초기화, `until-change`는 시작 15초 안의 변화는 무시하고 그 뒤 변화에서 풀림, 쉬기 중 `null`이 와도 쉬기 시간 점검은 계속.
- 첫 유효 샘플은 `'rebase'`만 내고 알림 계산은 이 시각부터.
- 문구 함수: 90초 → "경험치가 1분째 그대로예요", 45초 → "45초째", 240초 → "4분째".

### 13.2 브라우저 확인 (가짜 화면 스트림)

`navigator.mediaDevices.getDisplayMedia`를 덮어써 `canvas.captureStream(5)`를 돌려주는 시험 페이지를 쓴다(페이지 로드 전에 주입). 캔버스에 막대·숫자를 그린다. 멈춤 시간을 `0:10`, 반복을 `5`로 두고 진행한다.

1. 숫자를 2초마다 바꿈 → 알림 없음.
2. 숫자 고정 → 약 10초(±1초) 뒤 알림, 5초 간격 2번 더, 이후 없음.
3. 정지 중 숫자 한 번 바꿈 → 알림 상태 해제, 다시 정지하면 10초 뒤 다시 울림.
4. 정지 중 캔버스를 5초 검게 → 시간 초기화, stall 알림(10초 기준)과 겹치지 않음. 화면을 20초 이상 멈추면 stall만 울리고 idle은 안 울림.
5. 캔버스 크기 변경 → "다시 등록 필요", 알림 없음.
6. 등록 모드 진입 → 감지 쉼.
7. 탭을 숨긴 채(다른 탭 활성) 2번 반복 → 가짜 멈춤이 6.1처럼 숨은 탭에서 `video` 대체 프레임으로 오는지 관찰해서 오경보 여부를 기록한다. 이 확인으로 6.1의 [추정]을 [확인]이나 오류로 바꾼다.
8. 쉬기 누름 → 정지해도 알림 없음, 끝난 뒤 시간 초기화.
9. 영역에 계속 움직이는 그림을 넣음 → "영역이 계속 변해요" 표시.
10. `performance.now()`로 `idle` 처리 시간 측정(10절).

실제 게임 화면 확인(스크린샷 샘플 확보 뒤): 경험치가 오르기 전후 두 장을 불러와 `lumaDiffCount`가 몇 픽셀인지 재고, `minPx`와 높이 상한 8%가 맞는지 정한다. 두 장 모두 같은 화면에서 잡은 정지 상태의 압축 잡음도 같이 잰다. 이 숫자들이 이 문서의 가장 약한 부분이다.

## 17. 검토 반영 (2026-11-09)

독립 검토를 원문·코드와 대조해 받아들인 것. 본문·15절과 다르면 이 절이 우선한다.

1. **[중간] 영역 검사는 묶음 1의 `register.validate`로.** 40×6px 미만, 높이가 프레임의 8% 초과, **너비가 프레임의 40% 초과**면 거절하고 이유를 배너에 보인다. 너비 상한을 두므로 3.1의 "12만 픽셀 넘으면 축소"는 뺀다(축소하면 `minPx` 개수 기준이 흔들림).
2. **[중간] 숨은 탭에서 화면이 완전히 멈춘 경우.** `grabFrame` 시간 초과로 프레임이 없으면 사냥 멈춤이 아니라 연결 문제("게임 화면이 들어오지 않아요")가 울린다 [확인 `index.html:575-583`, `:698`]. 같은 상황이라도 탭이 보일 때는 사냥 멈춤이 울릴 수 있다. 의도된 동작으로 6절 표에 한 줄 적고, 13.2에 "정지 화면 + 숨은 탭" 확인을 더한다.
3. **[중간] 감지 책임.** `idle`의 `detect`는 쓰지 않고, `step(t, st, null, source, now)`가 `source`에서 영역을 잘라 `lumaDiffCount`를 구한다(묶음 1의 `step` 시그니처에 `source`가 있음). `stepIdle`의 내부 이벤트(`rebase`, `confirm`, `resume`, `snooze-end`)는 밖으로 내지 않고, `KINDS.idle.step` 감싸개는 `{key:'alarm', info:{elapsedSec}}`만 돌려준다. 9절 시그니처도 이 모양으로 읽는다.
4. **[중간] 깜빡이거나 계속 변하는 영역.** 등록 직후 10초 동안 `changedPx`를 재서 틱의 절반 넘게 변하면 `이 영역은 계속 변해요. 경험치 숫자와 바만 들어가게 다시 잡아 주세요`로 경고한다. 감시 중 "계속 변함" 상태가 되면 무음으로 두지 않고 한 번 음성으로 알린다(`사냥 멈춤 영역이 계속 변해서 감시할 수 없어요`, 슬롯 없음).
5. **[중간] 측정 표시.** 카드에 최근 60초의 `changedPx` 최대·중앙값과 변화 확정 횟수를 보여 준다(저장하지 않음). 사용자가 실제 사냥 중 이 값을 보고 `minPx`를 정한다. 등록 배너와 도움말에 "경험치 숫자나 퍼센트가 영역에 들어가야 해요"를 넣는다.
6. **[낮음] 반복 뒤 재무장.** 3번 울린 뒤에는 **변화가 확정될 때만** 다시 준비한다. 끊김이나 건너뛴 틱으로는 재무장하지 않는다(같은 멈춤에 3번 더 울리지 않게).
7. **[낮음] 쉬기 규칙.** `until-change`는 `snoozeUntil=Infinity`. 쉬기를 시작하면 알림 횟수와 `nextAlertAt`을 초기화한다. 쉬기가 끝나면 `phase='watch'`, `lastChangeAt=now`.
8. **[낮음] 스크린샷 테스트 모드.** `src.type==='image'`이면 `step`이 `null` 샘플로 다룬다(정지 이미지라 항상 울리는 것을 막음).
9. **[낮음] 기타.** 3.1의 `index.html:119` 인용은 `stepDetector`의 연속 판정(`:181`)으로 고친다. 6절 "연결 끊김" 근거는 "끊김 중에는 `ok=false`로 건너뛴 틱, 다시 연결하면 `newState()`(`:608`)". 6.1의 `lastGrabFresh`는 묶음 1의 `fresh` 표시로 부른다. `p.thumb`는 너비 200px 이하로 줄여 저장하고, 카드 썸네일은 `KINDS.idle.status`/카드 공통 코드에서 `p.thumb`를 쓴다.
