# 묶음 4: 설치기 쿨타임 알림 (`cooldown` 대상)

작성 2026-11-09. 공통 전제는 `2026-11-09-feature-expansion-overview.md`(3절 고정 전제, 5절 규칙). 묶음 1 스펙은 이 글을 쓰는 시점에 파일이 없어서(`ls` 확인), 아래 "묶음 1에 기대는 가정"을 따로 모았다. 묶음 1이 확정되면 그 절만 대조해 고친다.

표기: [확인] = 직접 연 `index.html:행`이나 명령 출력. [추정] = 코드로 확인하지 못한 것(게임 UI 동작, 참고 도구의 설명 포함).

## 1. 목표

퀵슬롯에 올려 둔 설치기(예: 파운틴류 설치 스킬)를 쓴 뒤, 화면만 보고 두 가지를 소리로 알린다.

1. **다시 쓸 수 있어요**: 쿨타임이 끝나 아이콘이 다시 밝아진 것을 **직접 본 순간**.
2. **곧 사라져요**: 사용자가 지속시간을 적어 둔 경우, 쓴 시각 + 지속시간 - 미리 알림 초.

숫자를 읽지 않는다. 아이콘이 어두워진 시각으로 쓴 때를 알고, 어두움이 풀린 것으로 쿨타임 끝을 안다.

## 2. 범위와 범위 밖

범위: 새 대상 종류 `cooldown`, 카드, 등록(아이콘 한 번 드래그 + 선택 보정), 상태기계 `stepCooldown`, 알림 이벤트 `pre`·`ready`, 아이콘 못 찾음 알림 `unread`, 테스트.

범위 밖:
- 퀵슬롯 쿨타임 **숫자 OCR**(4절에서 비교하고 미룸).
- 내장 설치기 아이콘(솔 야누스 새벽, 파운틴, 러쉬 등). 퀵슬롯 아이콘 샘플이 이 저장소에 없고 [확인: PRODUCT.md "없는 것"], 지어내지 않는다. 사용자가 직접 등록한다.
- 쿨타임·지속시간 게임 수치 내장. 입력은 사용자가 한다.
- 쿨타임이 없는 설치기(참고 도구도 미지원 [추정]).
- "N초 전 다시 쓸 수 있어요"(쿨타임 끝 예고). 열린 질문 1.
- 솔 야누스 대체. 솔 야누스는 계속 버프 바의 `buff` 대상이 맡는다([확인] `index.html:277-284` DEFS의 `sol` kind `buff`). 같은 스킬을 두 방식으로 등록해도 되지만 서로 알지 못한다.

## 3. 사용자 흐름과 화면

### 3.1 카드(묶음 1의 대상 카드 틀 위에)
- 제목: 사용자가 정한 이름(기본 "설치기 1"). 썸네일은 등록한 아이콘.
- 상태줄(`status`, 기존 클래스 재사용 [확인 `index.html:372`]):

| 상황 | 상태 | 보조 줄 |
|---|---|---|
| 등록 전 | 등록 필요 | 퀵슬롯의 스킬 아이콘을 드래그 |
| 화면 해상도 바뀜 | 다시 등록 필요 | 등록 당시 W×H, 지금 W×H (기존과 같은 형식 [확인 `:359`]) |
| 밝음 | 쓸 수 있음 | 일치도·밝기 |
| 어두움, 시작 시각 앎 | 쿨타임 중 · 00:42 경과 | 지속시간을 적었으면 "사라지기까지 01:20" |
| 어두움, 시작 시각 모름(연결 때 이미 어두움) | 쿨타임 중 | 시작을 몰라서 사라짐 알림은 다음 사용부터. "방금 썼어요"로 직접 지정 |
| 아이콘이 가려짐·다른 슬롯 | 아이콘 확인 중 | 퀵슬롯 페이지가 바뀌었는지 보세요 |
| 연결 뒤 한 번도 못 봄 | 아직 못 찾음 | 기존 문구와 같은 형식 [확인 `:362`] |

- 입력: 이름, 지속시간 `분:초`(비우면 사라짐 알림 끔), 미리 알림 N초 전(기본 10), 기준값 슬라이더(구조 일치도, `threshold`).
- 버튼: **등록**, **쿨타임 중 찍기**(선택 보정, 3.3), **방금 썼어요**(수동 시작, `index.html:333`의 "방금 켰어요"와 같은 역할), **알림 테스트**(`pre`를 울림), 삭제(묶음 1).
- 보조 표시: 일치도(`ncc`)와 밝기(`gain`) 두 값을 함께 보여 준다(기준값 맞출 때 필요).

### 3.2 등록
기존은 ① 영역 → ② 아이콘 두 번 드래그다([확인] `index.html:774-791`, `reg.step`). cooldown은 **아이콘 한 번**만 드래그한다.

- 배너: "① 퀵슬롯에서 쿨타임 없이 밝게 보이는 스킬 아이콘 하나만 꼭 맞게 드래그하세요".
- 검색 영역은 자동: 드래그한 사각형을 사방 8px(프레임 기준) 넓힌 것. 영역 단계가 없는 이유: 퀵슬롯은 화면에 붙은 고정 UI라 한 자리만 보면 된다 [추정].
- 저장하는 것은 5절 데이터 모델.

### 3.3 쿨타임 중 찍기(선택 보정)
스킬을 한 번 쓰고 카드의 "쿨타임 중 찍기"를 누르면 그 프레임 한 장을 재서 `gainLo`(어둠 판정 상한)와 `nccDim`을 정한다.
- 결과 문구: 밝기 0.38이면 "쿨타임 때 밝기가 0.38로 내려가요. 구분할 수 있어요". 0.8 이상이면 "쿨타임 때 밝기 차이가 작아요(0.82). 이 아이콘은 구분하기 어려워요. 알림이 틀릴 수 있어요". 이 경고가 노란색이 많은 아이콘이 불안정하다는 참고 도구 설명 [추정]에 대한 우리 쪽 대응이다.
- 안 눌러도 기본값으로 동작한다. 이 경우 카드에 "쿨타임 기준 미확인"을 작게 표시한다.

### 3.4 문구(해요체, 음성으로 읽힘)
- `pre`: "{이름} {N}초 뒤 사라져요"
- `ready`: "{이름} 다시 쓸 수 있어요"
- `unread`: "{이름} 아이콘이 안 보여요"

## 4. 감지 방법: 세 가지 비교와 추천

핵심 사실 두 가지.
1. `matchTemplate`은 윈도 평균을 빼고 분산으로 나눈다([확인] `index.html:160-178`, `v=sq-sum*sum/n`, `sc=cr/(norm*sqrt(v))`). 그래서 **전체가 같은 비율로 어두워진 아이콘도 점수는 거의 그대로 높다**. "아이콘이 어두워지면 NCC가 떨어진다"는 전제는 틀린다 [확인: 수식. 실제 게임 화면의 쿨타임 가림 방식은 [추정]]. 어두움은 NCC가 아니라 **밝기 비**로 따로 재야 한다.
2. 부스터 숫자 읽기 `ocrSevenSeg`는 7세그먼트 세 구획 판정이라 다른 글꼴에 쓸 수 없다([확인] `index.html:216-243`, `SEG_DIGITS`, 세그먼트 7칸 비율). 퀵슬롯 숫자 글꼴이 다르고 작다 [추정].

| 항목 | (a) 쿨타임 숫자 OCR | (b) 시작 감지(밝기 비) + 입력 시간 | (c) 혼합 |
|---|---|---|---|
| 새로 필요한 것 | 숫자 글리프 인식기. 글꼴 샘플이 없어 사용자 화면에서 만들어야 함 | 아이콘 템플릿 + 밝기 비 계산 | (a)+(b) |
| 해상도·UI 배율 | 글자 높이가 10px 안팎 [추정]이라 배율에 민감 | 등록한 한 자리만 보므로 해상도가 같으면 안정. 달라지면 재등록 | 둘 다 |
| 오인식 위험 | 숫자 한 자리 틀림이 곧 시간 오류. 노란 아이콘 위 흰 숫자가 불안정하다는 설명 [추정] | 어두움/밝음은 이진 판정. 2프레임 연속 확인으로 거름 | 가장 낮지만 복잡 |
| 쿨타임 감소·초기화 효과 | 직접 읽어서 따라감 | 밝아지는 것을 직접 보므로 `ready`는 정확. 사라짐 알림은 쓴 시각 기준이라 영향 없음 [추정] | 가장 정확 |
| 지속시간 | 숫자로 알 수 없음(쿨타임만 보임) | 사용자 입력 | 입력 |
| 비용 | 숫자 영역 잘라 이진화·분할·분류, 대상마다 매 틱 | 아이콘 한 칸 크롭과 NCC 소영역 | 큼 |
| 구현·검증 부담 | 큼. 글꼴 fixture 없음 | 작음. 순수 함수로 합성 테스트 가능 | 큼 |

**추천: (b)**. 이유:
- "틀린 알림보다 확인이 먼저"에 맞는다. 판정이 어두움/밝음 두 값이라 연속 프레임 확인으로 거르기 쉽다(켜짐 2·꺼짐 4회 연속 관행 [확인 `index.html:181`]).
- 사용자가 원하는 두 알림 중 `ready`는 **입력 없이** 관측만으로 정확하다. 쿨타임 값을 사용자가 적을 필요도, 게임 수치를 앱이 알 필요도 없다.
- 글꼴 샘플이 없는 지금 OCR은 만들어도 검증할 근거가 없다.
- (c)는 (b)가 실제로 쓰이고 틀리는 사례가 쌓인 뒤 판단한다. 열린 질문 2.

(b)의 한계: 사라짐 알림은 사용자가 지속시간을 알아야 하고, 쓴 시각은 최대 약 0.5초(틱) + 확인 2프레임만큼 늦게 잡힌다. 이 오차(1초 안팎 [추정])는 10초 미리 알림에 영향이 작다.

### 4.1 두 측정값
등록한 아이콘 템플릿 `tpl`과 현재 프레임의 같은 자리를 비교한다.
- `ncc`: 기존 `matchTemplate`을 아이콘 주변 ±8px 영역에서 실행(위치 흔들림 허용). 템플릿은 `scaleFor`로 줄인 것을 쓴다([확인] `index.html:635`, 짧은 변 14px 안팎).
- `gain`: 정렬된 위치에서 `현재 밝기 / 템플릿 밝기`의 **중앙값**(템플릿 밝기가 일정 값 이상인 픽셀만). 평균 대신 중앙값을 쓰는 이유는 어두운 아이콘 위에 흰 숫자가 얹혀도(소수 픽셀) 값이 덜 흔들리게 하려는 것이다 [추정: 숫자가 아이콘 일부만 덮는다는 가정].

### 4.2 판정과 상태
`classifyIcon(ncc, gain, cfg)`:
- `ready`: `ncc >= threshold` 그리고 `gain >= gainHi`(기본 0.85 [추정])
- `dim`: `ncc >= nccDim`(기본 0.45 [추정], 숫자가 얹혀 점수가 낮아지므로 별도) 그리고 `gain <= gainLo`(기본 0.65 [추정], 보정하면 중간값 기준으로 갱신)
- `unknown`: 그 밖. **가려짐·다른 아이콘·페이지 전환은 모두 여기**로 가며 알림 근거가 되지 않는다.

이것이 오경보 방어선이다. 어둡기만 하고 구조가 안 맞으면(다른 스킬이 그 자리에 왔거나 창이 덮음) `dim`이 아니라 `unknown`이다.

`stepCooldown(st, cfg, obs, now)` (순수 함수, `stepDetector` 자리 [확인 `:180`]에 같은 형태):
- 입력 `obs`는 `classifyIcon` 결과 또는 `null`(프레임 없음).
- `ready → dim` 2프레임 연속: 시작. `st.usedAt=now`(첫 dim 프레임 시각), `alertedPre=false`. 이전 주기의 대기 중 `pre`는 **취소**(새로 쓰면 이전 설치물은 대체된다고 본다 [추정]).
- `dim → ready` 2프레임 연속: `ready` 이벤트 1회. 쿨타임 길이 `now-usedAt`을 `st.lastCdSec`로 기록(표시용).
- `usedAt`이 있고 `durationSec`이 있고 `now >= usedAt + dur - lead` 이고 아직 안 울림: `pre` 1회.
- 알림 뒤 되돌림 없음. `pre` 뒤에 "사라졌어요"류 알림은 없다(정해 둔 정책: 미리 알림 뒤 꺼짐 알림 없음 [확인 PRODUCT.md]).
- 연결 시점에 이미 `dim`: `usedAt=null`. 다음에 `ready`가 되면 `ready`는 울리되 `pre`는 이번 주기 없음. 기존 `appear-unknown`과 같은 취급([확인] `:186`, `:200`의 `armed`).
- `unknown` 구간은 상태 변화 없음. 구간 뒤 `ready`로 돌아오면: 직전 확인이 `dim`이었고 `unknown`이 `GAP_MS`(기본 10초 [추정]) 이하일 때만 `ready` 울림. 더 길면 조용히 다시 맞춘다(오래 전에 끝났을 수 있어 "지금 막 쓸 수 있다"는 말이 틀릴 수 있음).
- `unknown`이 `UNREAD_MS_CD`(기본 90초 [추정]) 넘게 이어지면(직전에 한 번이라도 본 뒤) `unread` 1회. 에피소드마다 한 번. 부스터의 20초 규칙 [확인 `:246`]을 따르되 퀵슬롯 페이지 전환을 고려해 더 길게 잡았다.

## 5. 데이터 모델과 저장

대상 한 건(묶음 1 목록의 한 항목으로, 아래 필드는 cooldown 고유):

```
{ id:'u<n>', kind:'cooldown', name, preset:null, enabled,   // 묶음 1의 Target (13절)
  threshold,                              // ready NCC 기준값(기본 0.7 [추정])
  area:{x,y,w,h},                         // 아이콘 사각형을 사방 8px 넓히고 프레임 안으로 자른 검색 영역 (15절)
  tpl:{url,w,h},                          // 밝을 때 등록한 아이콘
  frameW, frameH,                         // 등록 당시 프레임 크기
  hint:null,
  p:{ gainHi, gainLo, nccDim, calibrated:bool, durationSec|null, leadSec:10 } }
```

- `id`는 한 번 정하면 바꾸지 않고 재사용하지 않는다(내 소리 슬롯 키가 `id.이벤트`라서 [확인 `:428`, `:435-445`]).
- 런타임 상태(`usedAt`, 연속 횟수, `alertedPre` 등)는 저장하지 않는다(기존과 동일. 연결 때 `newState()` [확인 `:608`]).
- 기존 데이터 이전: 없음. 새 종류라 v1 설정에 영향이 없다. 묶음 1의 이전 규칙을 그대로 받는다.
- 해상도 변경: `frameW/H`가 현재 프레임과 다르면 `다시 등록 필요`로 두고 감지하지 않는다. `needsReregister` 규칙과 같다([확인] `index.html:296`, `detect` 초입 `:657`). 같은 해상도에서 퀵슬롯 크기·UI 배율만 바뀐 경우는 `ncc`가 떨어져 `unknown`이 되고 90초 뒤 `unread`로 알게 된다. 다배율 검색은 하지 않는다(비용, 8절).
- 지속시간·쿨타임 기본값은 **넣지 않는다**. `durationSec`은 비어 있으면 사라짐 알림 꺼짐. 입력 안내 예시 문구도 숫자를 단정하지 않는다("사용한 스킬의 지속시간을 분:초로"). 솔 야누스 새벽 2분/1분, 파운틴 등 참고 도구의 내장값은 [추정]이라 이 앱의 기본값으로 쓰지 않는다.

| `pre` 곧 사라짐 | `<id>.pre` | 새 패턴 `cooldown`(룬·솔 야누스·부스터와 구분되는 음) | 묶음 1이 정하는 "끝나기 임박" 종류로 묶임. 미리 계산된 시각이라 가까운 다른 알림과 묶을 수 있음 |
| `ready` 다시 쓸 수 있음 | `<id>.ready` | `pre`와 다른 올라가는 두 음 | **묶지 않음**(이미 일어난 일을 즉시 알림) |
| `unread` 아이콘 안 보임 | `<id>.unread` | 시스템 낮은 경고음 [확인 `:382`, `:425`의 `unread`→`system`] | 묶지 않음 |

- 정책 충돌 점검: 미리 알림 뒤 꺼짐 알림 없음 → `pre` 뒤 "사라졌어요"를 만들지 않는다. `ready`는 꺼짐 알림이 아니라 쿨타임 끝 알림이라 이 정책과 별개라고 본다 [추정, 사용자 확인 필요 시 열린 질문 3].
- 반복 알림 없음. `ready`는 주기마다 한 번. 연결 끊김 재알림 정책은 건드리지 않는다.
- 같은 문구 8초 중복 억제 [확인 `:401`]가 그대로 적용된다. 주기가 아주 짧은 스킬은 그 안의 `ready`를 건너뛸 수 있다 [추정].
- 일찍 다시 쓴 경우(쿨타임 감소로 일찍 밝아진 뒤 재사용, 또는 기능으로 초기화): 밝아지면 `ready`는 실제로 울린다. 다시 어두워지면 새 주기가 시작되고 이전 `pre`는 취소된다. 어두운 채로 밝아지지 않았는데 쓴 시각을 바꿀 방법은 없다(관측 불가).
- 쿨타임이 지속시간보다 짧은 스킬(쓴 시각에서 지속시간 전에 다시 밝아짐)이어도 `pre`는 마지막 사용을 기준으로 한 번만 울린다.
- 카드는 `fire()`처럼 깜빡인다([확인] `:429`). 토스트·탭 제목·브라우저 알림은 `notify` 경로 그대로([확인] `:418-424`).

## 7. 오류·예외 상태

- **아이콘 일부가 가려짐**(채팅창, 툴팁, 다른 UI): `ncc`가 낮아져 `unknown`. 알림 없이 유지. 가려진 채로 쿨타임이 끝났다가 풀리면 4.2의 10초 규칙.
- **퀵슬롯 페이지 전환·스킬 위치 바꿈**: 같은 자리에 다른 아이콘이 오므로 `unknown`. 90초 넘으면 `unread` 한 번.
- **MP 부족·사용 불가로 아이콘이 어두워짐** [추정, 게임에서 쿨타임 없이도 어두워질 수 있음]: 구조는 같고 어둡기만 하므로 `dim`으로 보일 수 있다. 오경보 가능. 대응: ① 보정(3.3)에서 쿨타임 때만 나오는 밝기를 기준으로 삼고, ② 어두운 상태가 `MIN_CD_SEC`(기본 3초 [추정])보다 짧으면 주기로 치지 않고 알림도 안 낸다. 이것으로 완전히 막지는 못한다(한계로 적어 둠, 열린 질문 4).
- **검은 프레임·화면 끊김**([확인] `isBlank`·`ok` 게이트 `:682`, `:703-704`): 관측이 없는 동안 `stepCooldown`을 부르지 않는다. 시각 기반 `pre`는 마지막 정상 프레임이 `STALL_MS`(10초 [확인 `:525`]) 이내일 때만 울린다. 복구해 보니 이미 `pre` 시각을 `leadSec` 넘게 지났으면 늦은 "곧"은 틀린 말이라 건너뛴다.
- **탭 숨김**: 감지는 Worker 500ms 틱과 `grabFrame` 경로를 그대로 쓴다([확인] `:575-583`, `:798-799`). 결정에 렌더링이 필요 없다.
- **스크린샷 테스트 모드**(`src.type==='image'`): 정지 화면이라 시간 변화를 못 본다. 밝기·일치도 표시와 "쿨타임 중 찍기" 보정 확인만 한다. 이 모드에서는 `pre`/`ready`를 자동으로 울리지 않는다.
- **등록 중**(`reg`): 감지 쉼 [확인 `:704`].
- **쿨타임 중 찍기 때 실제로 밝은 상태**: 게인 0.85 이상이면 위 경고 문구로 거절하고 값을 바꾸지 않는다.

## 8. 성능

- 틱마다 대상 하나당: ① 소영역(아이콘 + 사방 8px)을 `work` 캔버스에 `drawImage` + `getImageData`, ② 14px급 템플릿으로 NCC(소영역 안에서만), ③ 중앙값 한 번. 기존 기본 아이콘 검색(큰 영역 × 여러 배율)과 달리 영역이 작고 배율도 하나다. 대상 하나 1~2ms 안팎 [추정, 구현 때 측정해야 함].
- 측정 가능한 상한: 대상 수 상한 8개(묶음 1이 정하는 목록 상한과 함께 조정)로 16ms 안팎 [추정]. 기존 측정(1920×1080, 대상이 없을 때 솔 야누스 214~460ms, 부스터 약 275ms. 개요 4절, 이 Mac)과 합쳐도 우리 몫이 작다는 뜻이며, 합계가 500ms를 넘을 수 있는 기존 문제는 이 스펙이 해결하지 않는다.
- 같은 퀵슬롯 줄에 대상이 여러 개면 합친 사각형을 한 번만 `drawImage`해 나눠 쓰는 최적화는 가능하지만(구현 판단), 필수 아님.
- 배율 다중 검색을 하지 않는 것이 성능을 지키는 이유이자 5절·7절의 재등록 규칙의 이유다.
- 구현 후 acceptance: 대상 8개를 등록한 합성 스트림에서 cooldown 감지 합계 시간이 틱당 30ms 이하(예산의 6%). 넘으면 영역 합치기를 적용한다.

## 9. 테스트 계획

순수 함수(node, `vm`으로 로드 가능한 일반 스크립트 가정. 자동 테스트가 현재 없다 [확인 PRODUCT.md]):
- `iconGain`/`classifyIcon`: 질감 있는 32×32 합성 아이콘 → 게인 0.4로 곱한 이미지는 `ncc≈1`, `gain≈0.4`(NCC 게인 불변을 증명하는 테스트). 중앙 20% 픽셀에 흰 숫자 → `gain` 중앙값이 거의 불변, `ncc` 하락. 다른 질감 → `ncc` 낮음 → `unknown`. 부분 가림 → `unknown`.
- `stepCooldown` 시나리오(시각을 주입):
  - dim 1프레임 → 시작 안 함. 2프레임 → `usedAt`.
  - `usedAt + dur - lead`에 `pre` 정확히 1회. 이후 `gone` 계열 이벤트 없음.
  - 쓰던 중 다시 쓴 경우(ready→dim→ready→dim) → 이전 `pre` 취소, 새 시각 기준.
  - dim→ready 2프레임 → `ready` 1회.
  - 연결 시점에 dim → `pre` 없음, `ready`만.
  - dim→unknown(5초)→ready → `ready` 울림. unknown 30초 → 울리지 않음.
  - unknown 90초 → `unread` 1회, 에피소드 안에서 반복 없음.
  - 정지 구간 뒤 늦은 `pre`(lead 초과) → 건너뜀.
  - `MIN_CD_SEC` 미만으로 어두웠다 밝아지면 `ready` 없음.
  - 지속시간 비어 있음 → `pre` 없음.
- 보정: 게인 0.38 샘플 → `gainLo` 설정. 0.82 샘플 → 경고 반환, 값 불변.

브라우저(가짜 화면 스트림): 페이지에 `navigator.mediaDevices.getDisplayMedia`를 덮어쓰는 스크립트를 넣어 `<canvas>.captureStream(5)`를 돌려준다(캔버스 1920×1080, 알려진 자리에 합성 아이콘).
- 스크립트: 밝음 → (2초 뒤) 곱 0.4 + 흰 숫자 얹힘 → (지속시간을 6초, lead 2초로 설정) → 밝음 복귀. `notify` 호출을 감싸 기록해 `pre`가 약 4초 시점, `ready`가 복귀 시점에 각 1회인지 확인.
- 아이콘을 다른 그림으로 교체해 `unknown` 유지·`unread`(시간 단축 설정)·무알림 확인. 검은 프레임 삽입 시 감지 정지 확인.
- 해상도 바꿔(캔버스 크기 변경) "다시 등록 필요" 확인.
- 대상 8개 성능: `performance.now()`로 cooldown 감지 구간 측정.
- 탭 숨김은 합성 스트림만으로 믿기 어려워 [추정], 실제 게임 창을 공유하고 탭을 뒤로 숨겨 `ready`가 울리는지 사람이 한 번 확인한다. 이 확인 전에는 숨김 탭 동작을 [확인]으로 쓰지 않는다.

## 10. 추천 결정

## 12. 묶음 1에 기대는 가정

> 2026-11-09: 묶음 1 스펙과 대조한 결과는 13절에 있다. 아래 가정과 다르면 그 절이 우선한다.

묶음 1 스펙 파일이 아직 없어(확인: `ls`) 아래를 가정했다. 하나라도 다르면 이 스펙의 해당 절을 고친다.

1. **대상 목록**: 대상이 `kind`를 가진 사용자 편집 목록이고 `kind:'cooldown'`을 추가할 수 있다. 항목 id는 불변·재사용 없음.
2. **저장**: 대상 목록 항목에 임의의 kind별 필드를 둘 수 있다(5절 필드). 런타임 상태는 저장하지 않는다.
3. **카드 UI**: kind마다 카드 입력/버튼을 다르게 그릴 수 있다. 현재 `buildCards`가 `kind`로 분기하는 것과 같은 방식 [확인 `:301-347`]. 삭제·이름 편집 버튼은 묶음 1이 제공.
4. **등록 흐름**: kind마다 등록 단계 수가 다를 수 있다(cooldown은 아이콘 한 단계, 검색 영역 자동). 현재는 `reg.step`이 `area`→`icon` 고정 [확인 `:725`, `:781-791`].
5. **감지 호출 모양**: `tick()`이 대상마다 kind에 맞는 감지 함수를 부르고 이벤트 배열(문자열 또는 객체)을 받아 `fire`로 넘긴다. 현재 형태 [확인 `:702-714`]. cooldown은 `detect`를 쓰지 않고 자체 측정 함수를 쓴다.
6. **알림 파이프라인**: 모든 알림이 한 경로(`notify` 또는 그 뒤계)를 지나며 `(대상, 이벤트, 문구, 슬롯 키)`를 넘긴다. 이벤트 이름은 `pre`·`ready`·`unread`를 쓸 수 있고, 묶기 대상 여부는 이벤트 종류로 구분할 수 있다(`pre`는 묶기 대상, `ready`·`unread`는 즉시).
7. **슬롯 키와 소리 목록**: 슬롯은 `대상id.이벤트`이고 `SLOTS`가 대상 목록에서 만들어진다(고정 배열 [확인 `:435`]이 아니라). 대상 삭제 때 그 슬롯의 내 소리도 정리한다.
8. **소리 패턴**: 새 기본 비프 패턴을 추가할 수 있다(`SOUNDS` [확인 `:377`]에 해당하는 자리).
9. **재등록 규칙**: `frameW/frameH` 불일치 시 `다시 등록 필요`로 두는 공통 규칙이 유지된다 [확인 `:296`].
10. **연결/상태 공통 처리**: 검은 프레임·끊김 시 대상 감지를 건너뛰는 `ok` 게이트와 연결 시 상태 초기화는 kind와 무관하게 적용된다 [확인 `:603-608`, `:703`].
11. **파일 분리**: 순수 함수(`classifyIcon`, `stepCooldown` 등)를 일반 `<script src>` 파일에 두고, node에서 `vm`으로 로드할 수 있다.
12. **대상 수 상한**: 묶음 1이 목록 크기 상한을 정하고 있으면 cooldown 8개 가정과 맞춘다.

## 14. 사용자 결정 (2026-11-09)

- **열린 질문 3 → "`pre`를 울린 주기는 `ready`를 끈다".** "미리 알림 뒤에는 꺼짐 알림 없음" 정책을 설치기에도 적용한다. 한 사용 주기에서 `pre`("N초 뒤 사라져요")가 울렸으면 그 주기의 `ready`("다시 쓸 수 있어요")는 소리·음성을 내지 않는다. 지속시간을 비워 `pre`가 없는 대상, 또는 `pre`가 울리기 전에 다시 밝아진 주기에서는 `ready`가 울린다. 카드 상태 표시는 그대로 바뀐다.
- **나머지 열린 질문은 추천대로**: 1 → 쿨타임 끝 N초 전 알림 없음, 2 → (b)로 써 보고 틀리는 사례가 보이면 OCR 혼합 검토, 4 → 보정과 최소 3초 어두움 조건만 쓰고 한계로 둠, 5 → 솔 야누스는 버프창 감지 유지.

## 15. 검토 반영 (2026-11-09)

독립 검토를 원문·코드와 대조해 받아들인 것. 본문·13절과 다르면 이 절이 우선한다.

1. **[중간] 템플릿 원본 밝기 보관.** 지금 `prepTemplate`은 평균을 뺀 값과 `norm`만 남긴다 [확인 `index.html:153-158`, `:636-645`]. `loadTpl`이 같은 배율의 원본 회색값 `ent.gray`를 함께 보관한다. 가림 판단에 쓰는 "템플릿 밝기 하한"은 상수 `TPL_MIN_LUMA=40` [추정]으로 둔다.
2. **[중간] 부분 어두움(방사형 스윕)에 맞춘 비대칭 판정.** `ready`는 밝기 비의 하위 20% 값(p20)이 `gainHi` 이상일 때(아이콘 전체가 밝음), `dim`은 중앙값(p50)이 `gainLo` 이하일 때. 9절에 "절반만 0.4배" 합성 사례를 더한다.
3. **[중간] 14절 결정을 상태기계에.** 억제 판정은 공통 플래그 `alertedPre`(묶음 1의 `markPre`가 켬. 당겨 알림으로 묶인 주기도 포함). 새 사용(`ready→dim` 확정) 때 끈다. 9절 시험: 미리 알림이 울린 주기는 `ready` 무음(카드는 바뀜) / 미리 알림 전에 밝아지면 `ready` 울림 / 당겨진 주기도 `ready` 무음. 6절의 "별개라고 본다" 문장은 14절 결정으로 바뀌었다.
4. **[중간] 보정 공식.** "쿨타임 중 찍기"는 연속 3프레임을 재어 `gainLo = min(0.65, 최대 gain × 1.3)`, `nccDim = clamp(최소 ncc × 0.8, 0.40, threshold − 0.1)`. `ncc < 0.4`면 `아이콘을 못 찾았어요`로 거절한다. `normalizeTarget`이 `gainHi > gainLo`, `nccDim < threshold`, `durationSec > leadSec`를 검사한다.
5. **[중간] 상태기계의 모호한 곳.** `ready→dim` 연속 판정 사이에 낀 `unknown`은 세지도 지우지도 않는다. 시각 기반 `pre`는 `unknown` 중에도 울린다. `MIN_CD_SEC` 미만으로 버리는 주기는 `usedAt`·`alertedPre`도 지운다. 일찍 다시 썼는데 `ready` 2프레임을 못 봤으면 `pre`가 이를 수 있다(한계 문구에 명시).
6. **[중간] 묶음 1 계약의 빈칸.** `remainSec = usedAt && durationSec && !alertedPre && 어두움 ? (usedAt + durationSec*1000 − now)/1000 : null`. `events`: `pre`(`group:'pre'`, 경고음 `buff`, `{이름} {N}초 뒤 사라져요`), `ready`(`group:null`, 새 경고음 `ready`), `unread`(`group:null`, `system`). 묶인 문구는 묶음 1의 "곧 끝나요"를 그대로 쓴다. `p.rect`는 쓰임이 없어 뺐다(5절 데이터 모델을 v2 모양으로 고침).
