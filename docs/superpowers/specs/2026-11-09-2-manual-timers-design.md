작성 2026-11-09. 공통 전제는 `2026-11-09-feature-expansion-overview.md`(3·5절)를 따른다. 묶음 1 스펙은 이 문서를 쓰는 시점에 아직 없었다. 그래서 묶음 1에서 가져다 쓰는 것은 "묶음 1에 기대는 가정"(12절)에 모았다.

표기: [확인] = 직접 연 `index.html:행` 또는 PRODUCT.md 원문. [추정] = 코드로 확인하지 못했거나 참고 도구 작성자의 설명. 행 번호는 파일 분리(묶음 1) 전 기준이다.

## 1. 목표

화면 감지 없이 사용자가 직접 시작하는 타이머를 만든다. 경험치 쿠폰, 일정 시간 뒤 할 일, 사냥·회수를 번갈아 하는 반복 루틴을 탭을 숨긴 채 소리와 음성으로 알려 준다. 알림은 기존 `notify` 경로를 탄다. [확인] `notify`가 이미 모든 알림의 단일 경로다(`index.html:418`).

성공 기준: 탭이 숨겨져 있고 화면 공유가 없어도 정해 둔 시각 ±1초 안에 알림이 울리고, 새로고침해도 남은 시간이 틀어지지 않는다.

## 2. 범위와 범위 밖

범위: 타이머 두 종류(카운트다운, 반복 루틴), 프리셋, 시작·일시정지·처음부터·시간 조절·삭제, 상태줄·탭 제목 표시, 미리 알림·끝 알림·구간 전환 알림, 내 소리 슬롯 4개, 새로고침·자리 비움 처리.

범위 밖(YAGNI):
- 경험치 쿠폰 전용 타입. 쿠폰은 이름만 다른 카운트다운이다. 게임 안 지속시간을 앱이 사실로 알고 있지 않는다.
- 3구간 이상 루틴, 요일·시각 지정 알람, 타이머 간 연결.
- 끝난 뒤 반복 재알림(열린 질문 2).
- 여러 탭 사이 알림 중복 제거(10절 한계로 기록).
- 게임 안 상태 감지. 이 타이머는 화면을 보지 않는다.

## 3. 타이머 종류 (추천 최소 세트)

| 종류 | 동작 | 구간 |
|---|---|---|
| 카운트다운 | 정한 시간이 지나면 끝 알림 후 `끝남`으로 멈춤 | 1개 |
| 반복 루틴 | 구간 1(기본 이름 "사냥")과 구간 2(기본 "회수")를 멈출 때까지 번갈아 반복. 구간이 끝날 때마다 전환 알림 | 2개 |

공통: 미리 알림 N초 전(기본 10초, 0이면 끔). 기본값 10초는 기존 대상의 기본값과 맞춘 것이다 [확인 PRODUCT.md:41].

프리셋: 5·10·15·20·30분, 1·2시간 [추정: 참고 도구에 있다는 작성자 설명]. 목록은 편집·추가·삭제할 수 있고 저장된다. 경쿠용 프리셋은 시드하지 않는다. 사용자가 이름 "경쿠"와 시간을 넣어 "프리셋으로 저장"한다. 게임 안 시간을 앱이 단정하지 않기 위해서다.

구간 길이 하한 10초 [추정], 타이머 개수 상한 8개 [추정]. 하한은 같은 문구가 8초 안에 다시 오면 음성을 건너뛰는 규칙 때문이다 [확인 `index.html:401`].

## 4. 사용자 흐름과 화면

### 4.1 패널 위치

현재 레이아웃은 `main`이 두 열이고 `grid-template-areas`가 `"stage cards" "help cards" "sounds cards"`다 [확인 `index.html:47`]. `#cards`(감지 카드)가 오른쪽 열 전체를 쓴다. 새 `#manual` 패널을 왼쪽 열의 stage와 help 사이에 둔다.

- 넓은 화면: `"stage cards" "manual cards" "help cards" "sounds cards"`.
- 좁은 화면(980px 이하) [확인 `index.html:52-54`]: stage, cards, manual, help, sounds 순.
- `<details>`로 접지 않고 기본으로 펼친다. 시작 버튼이 주된 조작이어서다. 접는 것은 "프리셋 편집"과 "고치기"만 한다. 접는 패턴은 기존 `details` 스타일을 쓴다 [확인 `index.html:77-78`].
- 이유 [추정]: 오른쪽 열은 묶음 1에서 대상 목록이 늘어 길어진다. 왼쪽 열은 미리보기 아래가 비어 있다. 최종 배치는 묶음 1의 레이아웃에 맞춘다(열린 질문 3).

### 4.2 만들기와 시작

패널 맨 위, 한 줄씩:

1. 프리셋 칩 `[5분] [10분] [15분] [20분] [30분] [1시간] [2시간] [+ 내 프리셋]`. 칩을 누르면 그 길이의 카운트다운을 만들어 바로 시작한다(한 번 클릭). 이름은 "5분 타이머".
2. 직접 입력: 이름(선택), `분:초`, `[시작]`, `[프리셋으로 저장]`. 기존 지속시간 입력과 같은 `분:초` 형식을 쓴다 [확인 PRODUCT.md:41].
3. `[사냥·회수 반복 만들기]`를 누르면 인라인 폼이 열린다. 구간 1 이름·`분:초`, 구간 2 이름·`분:초`, 미리 알림 초, `[시작]`.

시작 버튼은 모두 `unlockAudio()`를 먼저 부른다. 오디오는 사용자 조작으로만 켜지기 때문이다 [확인 호출 지점 `index.html:344,467,473,503,592,627`].

### 4.3 타이머 카드

한 카드 = 한 타이머. 목록은 만든 순서다.

```
경쿠 30분                              [고치기]
 24:10                       (큰 글씨, tabular-nums)
 카운트다운 · 10초 전 알림
[일시정지] [처음부터]  [-1분][-10초][+10초][+1분]  [삭제]
```

루틴 카드: 큰 글씨 위에 현재 구간 이름과 "3바퀴째". 보조줄 "사냥 12분 ↔ 회수 3분 · 10초 전 알림".

- 일시정지 ↔ 계속은 같은 버튼이다. 처음부터는 구간 1의 전체 길이로 되돌리고 멈춘 상태로 둔다(바로 시작하지 않는다). 처음부터를 누른 뒤 "계속"을 누르면 시작한다.
- 시간 조절 ±10초·±1분은 지금 구간의 남은 시간에 더하고 뺀다. 실행 중이어도 되고 멈춘 상태여도 된다. 남은 시간이 0 아래로 가면 0으로 둔다(다음 틱에 끝). 구간 전체 길이는 안 바뀐다.
- 끝난 카운트다운: 큰 글씨가 "끝났어요", 보조줄 "3분 전에 끝났어요"(경과), 버튼은 `[다시 시작] [삭제]`.
- 삭제: 실행 중이면 버튼이 "정말 지울까요?"로 바뀌고 3초 안에 다시 누르면 지운다. 멈춤·끝남은 바로 지운다. 패널 머리에 "끝난 것 모두 지우기".
- 고치기(멈춤·끝남·대기 상태에서만 길이 수정, 이름과 미리 알림 초는 언제든): 이름, 구간 길이, 미리 알림 초.
- 개수가 8개면 만들기 버튼을 끄고 "타이머는 8개까지 만들 수 있어요"를 보인다.

### 4.4 상태줄과 탭 제목

현재 상태줄은 `watchState`와 `watchTargets`가 감지 대상 상태를 그리고, `renderWatch`가 키가 바뀔 때만 다시 그린다. 이유는 `.live`가 `aria-live="polite"`라서 화면 낭독기가 매 틱 읽지 않게 하려는 것이다 [확인 `index.html:104,539-554`]. 초 단위로 바뀌는 남은 시간을 이 키에 넣으면 안 된다.

- `.live` 바깥(`.end` 왼쪽)에 `<span id="watchManual" role="timer">`를 둔다. `role="timer"`는 암묵적으로 live가 꺼져 있다 [추정: ARIA 명세 기준, 낭독기 실제 동작은 미확인].
- 내용: 실행 중인 타이머 중 남은 시간이 짧은 것 2개까지. "⏱ 사냥 12:30 · 경쿠 4:10", 3개 이상이면 "+1". 멈춤은 "(멈춤)". 실행 중인 게 없으면 빈 칸. 화면 연결이 없어도 보인다.
- 문자열이 바뀔 때만 `textContent`를 쓴다(`watchBeat`와 같은 방식 [확인 `index.html:558`]).
- 탭 제목: `baseTitle()`이 `감시 상태 · 메이플 재획 알리미` 형태다 [확인 `index.html:533`]. 맨 앞에 가장 짧게 남은 실행 중 타이머를 붙인다. 예: `⏱ 12:30 · 감시 중 · 메이플 재획 알리미`. 알림 깜빡임은 `baseTitle()`과 `⚠ 문구`를 번갈아 쓰므로 자동으로 따라온다 [확인 `index.html:422`].
- 탭 제목 갱신은 숨겨져 있어도 한다 [확인 `renderWatch`는 숨김 여부와 무관하게 호출 `index.html:718`].

### 4.5 문구 (해요체, 음성으로 읽힘)

| 이벤트 | 문구 | 예 |
|---|---|---|
| 미리 알림(카운트다운) | `{이름} {N}초 전` | "경쿠 30분 10초 전" |
| 끝(카운트다운) | `{이름} 끝났어요` | "경쿠 30분 끝났어요" |
| 미리 알림(루틴) | `{다음 구간} {N}초 전` | "회수 10초 전" |
| 구간 전환(루틴) | `{새 구간} 시간이에요` | "회수 시간이에요", "사냥 시간이에요" |

기본 이름은 소리 내어 읽어도 이상하지 않게 "N분 타이머"로 한다. 정해 둔 정책에 따라 앱이 문구를 바꾸는 설정은 두지 않고, 바꾸고 싶으면 내 소리 파일을 쓴다 [확인 PRODUCT.md:55]. 이름은 사용자가 정하므로 이 정책의 대상이 아닌 값이다 [추정].

### 4.6 탭을 숨긴 사용자가 듣는 것

- 구간·타이머 끝 10초 전: 기존 미리 알림과 같은 "경고음 → 음성"(비프 후 `speak`, 내 소리가 있으면 그것) [확인 `index.html:416-419`].
- 끝·전환: 같은 경로, 다른 경고음. 소리 이름은 기존 `SOUNDS`에서 고른다(14-1절 구현 메모, 새 소리 정의가 필요하면 묶음 1의 `SOUNDS` 확장 방식을 따른다).
- 탭이 숨겨져 있으면 브라우저 알림(`tag`는 타이머 id)도 뜬다 [확인 `index.html:423`].
- 새로고침 직후 오디오가 잠긴 상태면 7절 참고.

## 5. 데이터 모델과 저장

저장 키: `maple-web-timer-manual-v1` (localStorage). 기존 `maple-web-timer-v1`(대상 설정)과 `maple-web-timer-ui`는 건드리지 않는다 [확인 `index.html:277,292`]. 분리 이유: 대상 목록의 v1→v2 이전(묶음 1)과 독립이고, 백업이 이 키만 따로 다루기 쉽다.

```
Store = {
  v: 1, seq: 3,
  prefs: { preSec: 10 },
  presets: [{ id, label, sec }],
  timers: [Timer]
}
Timer = {
  id: 'm1', label, kind: 'countdown' | 'routine',
  phases: [{ name, sec }],            // countdown 1개, routine 2개
  idx: 0, cycles: 0,                  // idx = 현재 구간, cycles = 완료한 바퀴
  status: 'idle' | 'running' | 'paused' | 'done',
  endAt: epochMs | null,              // running일 때만. 구간 끝 시각
  remainMs: number,                   // idle·paused일 때 남은 시간
  preSec: 10, preFired: false,        // 이번 구간의 미리 알림을 이미 울렸는지
  doneAt: epochMs | null              // 끝난 시각(경과 표시용)
}
```

- 카운터가 아니라 끝 시각(`endAt`)을 저장한다. 남은 시간 = `endAt - Date.now()`. 새로고침·탭 숨김·틱 지연에 영향받지 않는다.
- 저장은 상태가 바뀔 때만 한다(시작, 멈춤, 조절, 구간 전환, 미리 알림 울림, 끝, 편집). 틱마다 쓰지 않는다. `preFired`도 저장하므로 새로고침 뒤 미리 알림이 중복되지 않는다.
- 구간 끝 시각은 이전 `endAt`에 다음 구간 길이를 더해 만든다(`now`에서 다시 만들지 않는다). 틱 지연이 쌓여 어긋나지 않는다.
- 저장 실패(`localStorage` 예외)는 기존처럼 무시한다 [확인 `index.html:282`]. 이때 새로고침하면 타이머를 잃는다.
- 읽을 때 방어: `v` 불일치·JSON 오류면 빈 저장소로 시작하고 상태줄 안내 "수동 타이머 저장값을 읽지 못했어요".
- 내 소리는 타이머별이 아니라 이벤트별 4개 슬롯(6절). 소리 파일은 기존 IndexedDB를 쓰고 이 키에는 안 들어간다 [확인 `index.html:448-450`].

백업(묶음 5)과의 관계: 백업은 이 키의 JSON을 그대로 내보낸다. 단, 내보낼 때 `prefs`·`presets`·타이머의 정의(`kind`, `label`, `phases`, `preSec`)만 쓰고 실행 상태(`status`, `endAt`, `remainMs`, `idx`, `cycles`, `preFired`, `doneAt`)는 빼는 것을 추천한다. 며칠 전 파일을 불러왔을 때 오래된 `endAt`이 살아나면 안 되기 때문이다. 불러오면 모든 타이머는 `idle`이고 `remainMs = phases[0].sec * 1000`이다. 이를 위해 순수 함수 `manualExport(store)`와 `manualImport(json)`를 이 묶음에서 제공한다(소리 파일은 묶음 5가 따로 다룬다).

## 6. 알림 동작

### 6.1 이벤트와 슬롯 키

슬롯 키 규칙은 `대상id.이벤트`를 유지한다 [확인 `index.html:435-445` 및 overview 4절]. 수동 타이머는 감지 대상이 아니므로 가상의 대상 id `manual`을 쓴다. 타이머별 id로 슬롯을 만들면 개수만큼 늘어나 설정 화면이 복잡해지므로 이벤트 종류별로만 둔다(전부 한 타이머 종류의 이벤트이므로 사용자는 보통 이것으로 충분하다 [추정]).

| 슬롯 키 | 화면 라벨(그룹 "수동 타이머") | 언제 |
|---|---|---|
| `manual.pre` | 미리 알림 | 카운트다운·루틴 구간 끝 N초 전 |
| `manual.end` | 타이머 끝 | 카운트다운이 끝났을 때 |
| `manual.next1` | 구간 1 → 구간 2 | 루틴에서 첫 구간(기본 "사냥")이 끝났을 때 |
| `manual.next2` | 구간 2 → 구간 1 | 루틴에서 둘째 구간(기본 "회수")이 끝났을 때 |

`SLOTS`에 이 4개를 한 그룹으로 추가한다 [확인 `SLOTS` 배열 형태 `index.html:435`]. 내 소리 슬롯 용량·길이 제한(10초, 5MB)은 그대로다 [확인 `index.html:446`].

### 6.2 발생 규칙 (순수 함수 `manualStep`이 판정)

- 미리 알림: 남은 시간이 `preSec*1000` 이하가 되고 `preFired`가 거짓일 때 한 번. 다음 경우는 울리지 않고 `preFired`만 참으로 둔다.
  - `preSec`가 0이거나 구간 길이가 `preSec`+3초 이하(시작하자마자 창 안에 들어감).
  - 이미 남은 시간이 `preSec*1000 - 3000`보다 작다(틱이 늦어서 "10초 전"이 실제로는 6초 전이 되는 경우). 3초는 [추정] 기본값이고 상수로 둔다.
- 끝(카운트다운): `now >= endAt`일 때 한 번. 이후 `done`.
- 구간 전환(루틴): `now >= endAt`일 때 전환 알림, 다음 구간 `idx` 시작, `cycles`는 구간 2에서 1로 돌아갈 때 1 증가.
- 늦은 판정: `now - (지난 경계 시각)`이 15초(`LATE_MS`, [추정]) 넘으면 소리 없이 상태만 따라잡는다(8절). PRODUCT.md 원칙 3 "틀린 알림보다 확인이 먼저"와 같은 판단이다 [확인 PRODUCT.md:99].

### 6.3 정해 둔 정책과의 관계

| 정책 [확인 PRODUCT.md:51-55] | 수동 타이머 적용 |
|---|---|
| 미리 알림 뒤에는 꺼짐 알림 없음 | **충돌 가능, 열린 질문 1.** 이 정책은 감지 대상이 "꺼졌을 때"에 관한 것이다. 수동 타이머의 끝·전환은 행동 신호(회수하러 가야 해요)이므로 미리 알림 뒤에도 울리는 것을 추천한다. 사용자 확인 필요 |
| 연결 끊김 재알림 2번에서 멈춤 | 연결 알림과 무관. 수동 타이머 알림은 재알림이 없다(한 번만). 재알림 도입 여부는 열린 질문 2 |
| 기본 음성 문구 유지, 바꾸려면 내 소리 | 4.5의 문구를 기본값으로 고정하고 문구 편집 설정은 두지 않는다. 이름은 사용자 값 |

### 6.4 묶기(묶음 1)와의 관계

묶음 1이 "가까운 알림을 한 번에" 묶는 단계를 알림 경로에 둔다고 가정한다. 수동 타이머는 기본적으로 묶기에 참여시키지 않는다(`group: null`).

- 이유 [추정]: 구간 전환은 "지금 회수하라"는 지시라 지연·합치기가 바람직하지 않다. 두 타이머가 같은 순간 끝나도 기존 장치가 순서대로 처리한다(비프는 `beepEnd`로 이어 붙이고, 음성은 큐에 쌓인다 [확인 `index.html:384-395,399-405`]).
- 미리 알림만 묶기에 참여시키는 선택지는 묶음 1 확정 뒤 재검토(12절 가정 4).

### 6.5 반복·에스컬레이션

없음. 이벤트마다 한 번만 울린다. 루틴은 구간마다 새 이벤트가 생기는 것이지 같은 이벤트의 반복이 아니다. 내가 자리에 없어도 소리가 계속 커지거나 반복되는 동작은 넣지 않는다. 필요하면 열린 질문 2.

## 8. 시간 정확도

### 8.1 구조

- 현재 틱 구조: Worker가 500ms마다 메시지를 보내고 `tick`이 받는다. Worker 생성에 실패하면 `setInterval(tick,500)`으로 대체한다 [확인 `index.html:797-800`]. 숨긴 탭에서 이 Worker 방식이 감지에 충분하다는 가정으로 만든 앱이고, 숨긴 탭의 메인 스레드 `setTimeout`/`setInterval`은 Chrome이 느리게 만든다(약 1초 단위, 5분 이상 숨기면 더 느려질 수 있음) [추정: Chrome 타이머 조절 동작, 이 환경에서 측정 안 함]. Worker 안의 타이머는 이 조절을 덜 받는다 [추정].
- **중요:** `tick`은 `if(busy) return`으로 겹쳐 실행을 막고 [확인 `index.html:691`], 숨긴 탭의 화면 소스에서 새 프레임을 최대 1.5초 기다린다(`grabFrameWithin(src.cap,1500)`) [확인 `index.html:569-580`]. 그러면 수동 타이머 판정을 `tick` 안에 두면 화면이 멈춘 상태에서 1.5초 이상, 감지가 오래 걸리면 더 늦어질 수 있다 [추정: 이 조합에서의 지연은 측정 안 함].
- 결정: 수동 타이머 판정 `manualTick(now)`를 `tick`과 분리해 Worker 메시지에서 먼저, 동기로 부른다(`await` 없음). Worker가 없는 대체 경로(`setInterval`)에서도 같은 순서. 판정 시각은 항상 `Date.now()`.
- 해상도: 500ms 틱이므로 알림은 목표 시각보다 0~500ms 늦다. 목표는 ±1초다. 음성은 비프가 끝난 뒤 `setTimeout`으로 이어 붙이므로 [확인 `index.html:416`] 비프 길이만큼 더 늦는다(기존 알림과 같다). 한 번의 알림에서 소리가 들리기까지 정확한 지연은 측정 전이다.

### 8.2 경계 상황

| 상황 | 처리 |
|---|---|
| 시스템 잠자기 후 복귀 | 복귀 직후 첫 틱에서 `now - endAt`이 크다. 15초 초과면 "늦은 판정": 소리 없이 따라잡고, 카운트다운은 `done`+"N분 전에 끝났어요", 루틴은 지난 경계를 모두 건너뛰어 현재 구간으로 맞춘다(경계를 `endAt`에 구간 길이를 더해 반복 계산해 `cycles`·`idx`를 구한다). 상태줄 알림 "자리를 비운 사이 지난 알림이 있어요: 경쿠 30분, 사냥·회수" (info, 8초). 그 뒤 새 경계부터 정상 알림 |
| 15초 이하 지연 | 정상 알림(약간 늦은 것일 뿐) |
| 시계가 앞으로 바뀜(수동 변경·NTP) | 잠자기와 구분할 수 없다. 같은 규칙으로 처리 |
| 시계가 뒤로 바뀜 | 보정하지 않는다(알려진 한계: 그만큼 늦게 끝난다). 처음 설계의 "남은 시간이 구간 길이를 넘으면 줄인다" 규칙은 ±조절(4.3)로 늘린 시간과 구분할 수 없어 뺐다(검토 반영 17절) |
| 미리 알림 창 안에서 새로고침 | `preFired`가 저장돼 있으면 중복 없음. 없고 남은 시간이 6.2의 허용 안이면 울림, 밖이면 건너뜀 |
| ±조절로 미리 알림 창을 벗어남 | 남은 시간이 다시 `preSec`보다 길어지면 `preFired=false`로 되돌려 다시 울린다. 창 안으로 들어가면 `true`로 두고 울리지 않는다 |
| 음성 큐 막힘 | 기존 규칙(15초 넘게 막히면 비움)을 따른다 [확인 `index.html:402`] |
| 같은 문구 8초 안 중복 | 기존 `speak`가 건너뛴다 [확인 `index.html:401`]. 다른 타이머가 같은 이름이면 문구가 같으므로 이름을 구분해 쓰도록 안내하거나 이름 중복을 막는다(추천: 기본 이름에 번호) |

## 9. 성능

- `manualTick`: 최대 8개 타이머에 대한 뺄셈·비교. 틱당 마이크로초 수준 [추정, 측정 안 함]. 감지(솔 야누스 214~460ms 등, overview 4절)와 비교해 무시할 수 있다. 감지 틱 시간 예산(500ms)에 영향 없음이라고 본다 [추정].
- DOM: 상태줄·탭 제목은 문자열이 바뀔 때만 쓴다(초당 1번). 카드 시간 표시는 `document.hidden`이 아닐 때만 갱신한다. 기존 `renderCard`와 같은 패턴 [확인 `index.html:716`].
- 저장: 상태 변화 때만. 틱마다 쓰지 않는다.
- Worker는 하나 그대로. 새 Worker·새 타이머를 만들지 않는다.

## 10. 알려진 한계

- 같은 페이지를 두 탭에서 열면 두 탭이 같은 저장값을 읽고 각각 알림을 울려 중복된다. 감지 쪽도 한 탭에서만 쓰는 것을 전제로 한다 [추정]. 이번 묶음에서는 처리하지 않는다(필요하면 `storage` 이벤트로 다른 탭 화면 동기화 정도만).
- 작은 시계 후퇴는 못 알아본다(8.2).
- 오디오 잠금 해제에 사용자 조작이 한 번 필요하다(7절).

## 11. 테스트 계획

### 11.1 순수 함수 단위 테스트 (node)

대상 함수(모두 `now`를 인자로 받고 `Date.now()`를 직접 부르지 않는다. 입력 타이머를 바꾸지 않고 새 객체와 이벤트 목록을 돌려준다):

```
manualStart(t, now) -> t'
manualPause(t, now) -> t'
manualReset(t) -> t'
manualAdjust(t, deltaMs, now) -> t'
manualStep(t, now) -> { t', events: [{type:'pre'|'end'|'switch', idx, late:boolean, lateMs}] }
manualRemainMs(t, now) -> number
manualFmt(ms) -> '12:30' | '1:02:03'
manualExport(store) / manualImport(json)
```

기대 동작을 확인할 사례:
- 카운트다운: 시작 → 남은 시간 계산, `preSec` 경계 직전·직후 `pre` 정확히 1번, `end` 1번 뒤 `done`, `done`에서 다시 `manualStep`해도 이벤트 없음.
- 구간 길이 ≤ `preSec`+3초일 때 `pre` 없이 `end`만.
- 일시정지 → 계속: 멈춘 동안 시간이 안 줄고 `endAt`이 `now + remainMs`로 맞춰진다.
- ±조절: 창 안/밖 이동 시 `preFired` 변화, 0 아래로 내려가도 음수가 안 됨.
- 루틴: 구간 1→2→1, `cycles` 증가, 경계에서 `endAt`이 `now`가 아니라 `이전 endAt + 구간 길이`(드리프트 없음).
- 늦은 판정: 지연 14.9초는 `late:false`, 15.1초는 `late:true`. 루틴 1시간 건너뜀 때 `idx`·`cycles`·`endAt`이 수식과 일치, 이벤트는 하나(`late:true`).
- 시계 후퇴 보정.
- `manualImport`: 실행 상태가 `idle`로 초기화된다. 잘못된 JSON·`v` 불일치는 빈 저장소.
- 한 틱에 두 경계(큰 지연)가 지난 경우 이벤트가 하나만 나온다.

실행 방식: 순수 함수는 별도 파일(`manual-core.js`, 12절 가정 5)에 두고 `node` 또는 `node --test`로 `require` 한다. 빌드 도구를 쓰지 않는다는 전제에서 파일 맨 끝에 `if (typeof module !== 'undefined') module.exports = {...}`를 두는 방식을 추천한다(구체 방식은 묶음 1의 파일 분리 규칙에 맞춘다).

### 11.2 브라우저 확인 (수동)

1. 숨긴 탭: 30초 타이머(미리 알림 10초)를 시작하고 다른 창으로 전환해 1분 둔다. 20초 지점 "N초 전", 30초 지점 "끝났어요"가 ±1초 안에 들리는지, 탭 제목이 줄어드는지 확인한다.
2. 화면 공유 없음·화면 공유 중 모두 확인. 특히 공유 중 탭을 숨겨 프레임이 안 오는 상태(감지 `tick`이 1.5초 지연되는 경로)에서 수동 알림 지연이 줄었는지 비교한다.
3. 새로고침: 실행 중에 새로고침 → 남은 시간 연속, 미리 알림 창 안에서 새로고침 → 중복 없음, 오디오 잠김 안내가 뜨고 `[소리 켜기]`로 해결.
4. 루틴: 사냥 20초·회수 10초로 3바퀴, 전환 문구와 `cycles`.
5. 잠자기: 노트북 덮개를 30초 닫았다 열기 → 소리 없이 따라잡고 안내가 뜬다.
6. 시스템 시계를 앞으로·뒤로 바꿔 보기.
7. 내 소리 슬롯 4개 지정·알림 테스트, 기본 소리와 구분 확인.
8. 8개 상한, 삭제 확인, 상태줄에 여러 타이머가 쌓일 때 폭.
9. 상태줄 `role="timer"`가 화면 낭독기에서 초마다 읽히지 않는지 확인(가능하면). 틱마다 `renderWatch`가 불필요하게 다시 그리지 않는지는 DevTools로 확인.

감지 쪽 "가짜 화면 스트림"(overview 5절)은 이 기능의 필수 조건이 아니다. 단, 2번처럼 공유 중 상태가 필요하므로 기존 스크린샷 테스트 모드(`src.type==='image'`)나 가짜 스트림에서 함께 돌려 본다 [확인 스크린샷 모드 존재 `index.html:96`, `grab`이 이미지 소스를 즉시 돌려줌 `index.html:577`].

## 12. 묶음 1에 기대는 가정

> 2026-11-09: 묶음 1 스펙과 대조한 결과는 15절에 있다. 아래 가정과 다르면 그 절이 우선한다.

묶음 1 스펙(`2026-11-09-1-target-list-buffs-design.md`)이 아직 없어서 아래는 전부 이 문서의 가정이다. 나중에 묶음 1 확정 내용과 맞춘다.

1. **알림 경로 모양:** 현재 `notify(msg, sound, tag, slot)` [확인 `index.html:418`]이 유지되거나, 같은 정보를 담은 객체 `alert({text, sound, tag, slot, group})`로 바뀐다. 수동 타이머는 `text`, `sound`, `tag`(타이머 id), `slot`(`manual.pre` 등)과 `group: null`(묶기 제외 표시)을 넘긴다. `group` 같은 필드가 없으면 기본이 "묶기 제외"여야 한다.
2. **슬롯 키 규칙:** `대상id.이벤트`가 유지된다. 가상 대상 id `manual`을 대상 목록(`DEFS`)에 넣지 않고도 `SLOTS`에 그룹을 추가할 수 있다. `SLOTS`가 동적으로 만들어지더라도 고정 4개 항목을 정적으로 추가할 수 있어야 한다.
3. **저장 키:** `maple-web-timer-v1`은 묶음 1이 이전(v2 등)할 수 있지만 `maple-web-timer-manual-v1`과 겹치지 않는다. 묶음 1의 저장 형식 변경이 이 키에 영향을 주지 않는다. 묶음 5 백업이 이 키를 별도 항목으로 다룰 수 있다.
4. **묶기 단계:** 묶음 1의 묶기가 `notify` 앞단에서 일정 시간 알림을 보류해 합치는 방식이라면, 수동 타이머 이벤트(특히 구간 전환·끝)는 보류 대상에서 제외된다. 미리 알림만 참여시키려면 묶음 1이 "그룹 키"를 알림 입력으로 받아야 한다.
5. **파일 이름·구성:** 일반 `<script src>`로 나눈다는 overview 4절을 따르고, 이 묶음은 새 파일 둘을 추가한다고 가정한다: `manual-core.js`(순수 함수, node 테스트 가능), `manual-ui.js`(패널·상태줄·Worker 연결 코드). 정확한 폴더(`js/` 등)·로드 순서·전역 노출 방식은 묶음 1이 정한 것을 따른다. `index.html`의 `main` 그리드·`renderWatch`·`baseTitle`·`SLOTS`·Worker 연결부 수정이 필요하다.
6. **공통 유틸 공유:** `fmt`(`분:초` 표시)·`$`·`unlockAudio`·`setNote`·`save` 류 도우미가 분리 후에도 수동 타이머 코드에서 쓸 수 있는 전역 또는 공유 모듈이다. `fmt`의 시간 표시 형식이 시간 단위(1:02:03)를 지원하지 않으면 `manualFmt`가 따로 필요하다 [확인 `fmt`는 `mm:ss`만 만든다 `index.html:286`; 1시간 이상은 `manualFmt`가 필요].
7. **상태줄·탭 제목 확장점:** `renderWatch`/`baseTitle`에 수동 타이머 한 줄을 끼울 자리(`#watchManual`, 제목 접두)를 묶음 1이 허용한다. 묶음 1이 상태줄 구조를 바꾸면 그에 맞춘다.
8. **틱 연결:** 묶음 1이 Worker 메시지 처리부를 그대로 두거나 `onTick` 같은 훅을 준다. 수동 타이머는 감지 `tick`보다 먼저, `busy`와 무관하게 동기로 불려야 한다.
9. **`SOUNDS`(기본 경고음) 확장:** 끝·전환용 경고음 이름을 `SOUNDS`에 추가할 수 있다(또는 기존 `sol`/`gone` 재사용).

## 14. 열린 질문

1. **끝·전환 알림과 "미리 알림 뒤에는 꺼짐 알림 없음" 정책.** 이 정책은 감지 대상이 꺼졌을 때에 관한 것으로 읽었다 [추정: 정책의 의도는 이 문서에서 해석한 것].
   - A. 수동 타이머의 끝·전환은 항상 울린다. **추천.** 이유: 이것은 해야 할 행동을 알리는 신호이고 미리 알림은 준비 신호다.
   - B. 정책을 그대로 적용해 미리 알림이 울렸으면 끝 알림을 생략한다. 위험: 카운트다운이 끝났는데 아무 소리도 안 난다.
   - C. 타이머마다 선택하게 한다. 설정이 늘어난다.
2. **끝난 카운트다운의 재알림.**
   - A. 없음(한 번). **추천.** 일관성과 단순함. 쿠폰 같은 용도는 급하지 않다.
   - B. 끝난 뒤 60초 간격으로 최대 2번(연결 끊김 재알림과 같은 모양 [확인 PRODUCT.md:53]).
   - C. 타이머별 "다시 알림" 스위치.
3. **패널 위치.**
   - A. 왼쪽 열 미리보기 아래(펼침). **추천.**
   - B. 오른쪽 열 맨 위(감지 카드 위).
   - C. 상태줄 바로 아래 전체 폭 한 줄(컴팩트 모드). 묶음 1의 레이아웃 확정 뒤 결정해도 된다.
4. **자리 비운 뒤 늦은 알림 처리.**
   - A. 15초 넘게 늦으면 조용히 따라잡고 안내만. **추천.**
   - B. 늦어도 항상 한 번 울린다("회수 시간이에요"가 한참 뒤).
   - C. 늦었다고 알리는 음성 한 번("경쿠 30분이 3분 전에 끝났어요"). 잠자기 복귀 때 갑자기 말한다는 단점. 문구 설계가 늘어난다.

## 16. 사용자 결정 (2026-11-09)

- **열린 질문 1 → B(정책 적용).** "미리 알림 뒤에는 꺼짐 알림 없음"을 수동 타이머에도 적용한다. 한 주기(카운트다운 한 번, 루틴의 한 구간)에서 `pre`가 울렸으면 그 주기의 `end`·`next1`·`next2`는 소리·음성을 내지 않는다. `pre`가 꺼져 있거나(미리 알림 0초) 주기가 미리 알림 초보다 짧아 `pre`가 울리지 않은 주기에서만 `end`·`next*`가 울린다. 화면 표시(상태줄·카드의 구간 전환, 남은 시간)는 그대로 바뀐다.
- **나머지 열린 질문은 추천대로**: 2 → A(끝난 뒤 재알림 없음), 3 → A(왼쪽 열, 미리보기 아래), 4 → A(15초 넘게 늦은 알림은 조용히 따라잡고 상태줄에 표시).

## 17. 검토 반영 (2026-11-09)

독립 검토를 스펙 원문과 대조해 받아들인 것. 본문·15절과 다르면 이 절이 우선한다.

1. **[중간] "미리 알림을 울렸다"와 "미리 알림 창을 지났다"를 나눈다.** 지금 `preFired`는 울리지 않고 건너뛴 경우에도 참이 된다(6.2) [확인]. 그대로 16절 결정에 쓰면 미리 알림이 없었던 주기의 끝·전환까지 무음이 된다. 수정: `preDone`(창 처리 끝, 지금의 `preFired`)과 `preHeard`(실제로 `Alerts.fire`에 보냈고 그때 오디오가 `running`이었음)를 둔다. 끝·전환의 무음 판정은 `preHeard`만 본다. `preHeard`는 구간 전환, 처음부터·다시 시작, ±조절로 창 밖으로 나갈 때 거짓이 된다. 둘 다 저장한다. 무음 처리된 이벤트는 `{key, silent:true}`로 화면만 바꾼다.
2. **[중간] 시계 후퇴 보정 삭제.** ±조절로 늘린 시간과 구분할 수 없어 8.2에서 뺐다(알려진 한계로 남김) [확인 72·208행 충돌].
3. **[중간] 오디오가 잠긴 상태.** 판정은 `!actx || actx.state!=='running'`. 상태줄에 사라지지 않는 `#soundLock`(문구 `소리가 꺼져 있어요` + `[소리 켜기]` 버튼)을 둔다(8초 뒤 사라지는 `setNote`가 아님). 페이지에 `pointerdown`·`keydown` 리스너를 `{once:true}`로 한 번 달아 `unlockAudio()`를 부른다. 잠긴 동안 울린 미리 알림은 `preHeard`로 치지 않는다(끝 알림 기회를 남김). 숨은 탭이면 `Alerts`의 브라우저 알림이 대신 남는다.
4. **[중간] 16절을 본문에 반영.** 4.5·6.1의 끝·전환 알림과 `manual.end`·`next1`·`next2` 슬롯은 "그 주기에 미리 알림이 들리지 않았을 때만 울림"이다. 11.1에 다음 시험을 더한다: 미리 알림이 들렸으면 끝 무음 / 미리 알림 0초면 끝 울림 / 구간이 `preSec+3초` 이하면 끝 울림 / 틱이 늦어 미리 알림을 건너뛰면 끝 울림 / ±조절로 창 밖에 나갔다 들어오면 다시 미리 알림 / 구간 전환 뒤 `preHeard` 초기화 / 오디오 잠김 중 미리 알림이면 끝 울림.
5. **[중간] 늦음·여러 경계.** 늦음은 **마지막으로 지난 경계**에서 잰다. 한 틱에 경계가 여럿 지나면 지금 구간으로 들어오는 전환 하나만 낸다. 11.1에 `lateMs` 14.9초·15.1초 경계 시험을 더한다.
6. **[중간] 표시 갱신도 `manualTick`에서.** `#watchManual`과 탭 제목 접두는 `manualTick`이 문자열이 바뀔 때만 직접 갱신한다(감지 `tick`의 `busy`·`grabFrame` 대기에 묶이지 않게). 제목 깜빡임 중에는 접두만 저장하고 깜빡임이 끝나면 `baseTitle()`이 반영한다.
7. **[중간] 빠진 정의.** 경고음: 미리 알림 `timer`(새 패턴, 같은 음 두 번), 끝·전환 `gone`. 카드 DOM id는 `manual-<id>`이고 `flash`도 같다. 진입점 `manualInit()`을 `main.js`가 부른다. Worker가 없어 `setInterval`로 대신할 때도 `manualTick`을 먼저 부른다.
8. **[낮음] 이름 중복.** 같은 이름이 있으면 기본 이름 뒤에 번호를 붙인다(`10분 타이머 2`). 루틴이 둘 이상이면 미리 알림 문구 앞에 루틴 이름을 붙인다(`사냥·회수 2, 회수 10초 전`). 구간 하한 10초의 근거에서 "8초 중복 규칙"은 빼고 "너무 짧은 구간은 알림이 겹친다"로 고친다.
9. **[낮음]** 성공 기준은 "알림 경로 진입 ±1초"(음성은 비프 뒤 `setTimeout`이라 숨은 탭에서 더 늦을 수 있다 [추정]). `manualFmt`는 `fmt`처럼 올림. `manualExport`·`manualImport`는 묶음 5가 쓰므로 유지한다.
