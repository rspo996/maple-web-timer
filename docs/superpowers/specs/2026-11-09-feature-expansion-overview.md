# 메이플 재획 알리미 기능 확장: 개요

작성 2026-11-09. 다섯 개 묶음 스펙의 공통 전제다. 묶음 스펙은 이 문서와 어긋나면 안 되고, 바꾸고 싶으면 그 스펙의 "열린 질문"에 적는다.

## 1. 배경

다른 메이플 타이머 도구들의 기능을 조사해, 이 알리미에 없는 것 중 사용자가 여덟 가지를 골랐다(2026-11-09). 조사 내용은 각 글 작성자의 설명을 읽은 것이며 도구를 직접 써 보지는 않았다.

| 기능 | 참고한 도구 | 출처 |
|---|---|---|
| 버프 종료 알림 확장 (유니온의 힘·부, 비약, 경험치 쿠폰) | maple-timer.com | [인벤 업데이트 글](https://www.inven.co.kr/board/maple/2304/47602) |
| 가까운 알림 묶기 (비슷한 때 끝나는 버프를 한 번에) | maple-timer.com | 위와 같음 |
| 사냥 멈춤 알림 (경험치가 일정 시간 안 변하면) | maple-timer.com "동꼽방지" | [인벤 소개글](https://www.inven.co.kr/board/maple/5974/6561583) |

## 3. 바꾸면 안 되는 전제

`PRODUCT.md`가 원본이다. 요약:

- 혼자 쓰는 개인 도구. 사냥 중에는 탭을 숨기고 소리·음성만 듣는다. 화면은 주로 설정할 때 본다.
- 화면 캡처(`getDisplayMedia`)만 쓴다. 게임 메모리 읽기, 키 입력 자동화, 클라이언트 변조, 게임 안 키 입력 감지는 하지 않는다.
- 데스크톱 Chrome·Edge만 지원한다.
- 화면 이미지는 브라우저 밖으로 보내지 않는다(서버·외부 API 없음). 이건 PRODUCT.md에서 "약속은 아닌 현재 상태"지만 이번 확장에서는 지킨다.
- 틀린 알림보다 확인이 먼저다(연속 프레임 확인 등 기존 원칙 유지).
- 정해 둔 알림 정책: 연결 끊김 재알림은 2번에서 멈춤, 미리 알림 뒤에는 꺼짐 알림 없음, 기본 음성 문구 유지(바꾸고 싶으면 내 소리 파일).
- 문구는 한국어 해요체, 짧고 귀로 들어도 알아듣게.

## 4. 공통 설계 방향 (묶음 1이 확정)

지금 코드(`index.html`, 약 800줄)의 사실:

- 감지 대상이 `DEFS`에 고정(솔 야누스 `buff`, 부스터 `countdown`, 룬 `rune`). 설정은 `localStorage`의 `maple-web-timer-v1`(대상 id별 객체), 화면 상태는 `maple-web-timer-ui`, 내 소리는 IndexedDB `maple-web-timer`/`sounds`(슬롯 키 `대상id.이벤트`, `sys.lost` 등).
- 감지 순수 함수 `stepDetector`, `stepCountdown`, `matchTemplate`(NCC), `ocrSevenSeg`가 첫 번째 `<script>`에 있다.
- 알림은 `notify(msg, sound, tag, slot)` 한 곳을 지난다. 내 소리가 있으면 그걸, 없으면 비프+음성. 비프·내 소리는 `beepEnd`로 순서대로 예약된다.
- 감지 주기는 Worker가 500ms마다 `tick()`을 부른다. 기본 아이콘의 여러 배율 검색이 비싸다(1920×1080에서 대상이 없을 때 솔 야누스 214~460ms, 부스터 약 275ms, 이 Mac에서 측정).

방향(추천, 묶음 1 스펙에서 확정하거나 열린 질문으로 남김):

- **대상 목록:** 고정 `DEFS` 대신 사용자가 추가·삭제할 수 있는 대상 목록. 각 대상은 `kind`를 가진다. 지금 있는 `buff`·`countdown`·`rune`에 더해 묶음 3이 `idle`(사냥 멈춤), 묶음 4가 `cooldown`(설치기)을 추가한다. 기존 v1 설정은 자동으로 옮긴다.
- **수동 타이머(묶음 2)** 는 화면 감지가 아니므로 대상 목록과 별도 패널·별도 모델로 두되, 알림은 같은 `notify` 경로를 탄다.
- **알림 경로:** 모든 알림은 하나의 경로로 모이고, 묶기(묶음 1)·볼륨 증폭·PIP(묶음 5)는 이 경로에 붙는다. 내 소리 슬롯 키는 `대상id.이벤트` 규칙을 유지한다. → 묶음 1에서 `notify`를 대체하는 `Alerts.fire(AlertReq)`·`Alerts.listen`·`Alerts.audioOut`으로 확정했다(묶음 1 스펙 7절, 14절).
- **파일 구성:** `index.html` 하나가 커져서 CSS와 스크립트를 몇 개 파일로 나눈다. 로컬 파일(`file://`)로 열어도 동작해야 하므로 ES 모듈이 아니라 일반 `<script src>`로 나눈다. 빌드 도구는 쓰지 않는다.
- **성능 예산:** 대상이 늘어도 한 번의 `tick()` 감지 시간이 주기(500ms)를 넘지 않아야 한다. 각 스펙은 자기 기능이 `tick()`에 더하는 비용을 적는다.

## 5. 스펙 작성 규칙

- 위치: `docs/superpowers/specs/`. 파일명은 2절 표를 따른다. 한국어로 쓴다.
- 꼭 들어갈 절: 목표, 범위와 범위 밖, 사용자 흐름과 화면(문구 포함), 데이터 모델과 저장(기존 데이터 이전 포함), 감지·계산 방법, 알림 동작, 오류·예외 상태, 성능, 테스트 계획(순수 함수 단위 테스트 + 가짜 화면 스트림으로 브라우저 확인), 추천 결정, 열린 질문.
- 사용자가 고르지 않은 것을 에이전트가 정했다면 "추천 결정"에 이유와 함께 적는다. 사용자 판단이 필요한 것은 "열린 질문"에 선택지와 함께 적는다.
- 코드 근거는 `index.html:행`으로, 확인한 것은 [확인], 추정은 [추정]으로 표시한다.
- 구현 코드는 쓰지 않는다(필요하면 인터페이스 수준의 짧은 시그니처만).

## 6. 사용자 결정 (2026-11-09)

| 질문 | 결정 |
|---|---|
| "미리 알림 뒤 꺼짐 알림 없음" 정책의 범위 | 모두 적용: 수동 타이머의 끝·구간 전환, 설치기의 다시 쓸 수 있음도 미리 알림을 울린 주기에는 울리지 않는다 |
| 사냥 멈춤 반복 | 처음 1번 + 2분 간격 2번 |
| 가까운 알림 묶기 | 기본 꺼짐. 켜면 당겨 알림 10초 |
| 나머지 열린 질문 | 각 스펙의 추천대로 |

각 스펙 끝의 "사용자 결정" 절에 반영했다.

## 7. 독립 검토 (2026-11-09)

다섯 스펙을 서브에이전트가 따로 검토했고, 지적을 원문·코드와 대조해 받아들인 것을 각 스펙 끝 "검토 반영" 절에 적었다. 대조 후 높음은 1건(묶음 1: 묶기를 켰을 때 부스터 미리 알림이 두 번 울림, `index.html:261` 확인)이고 나머지는 중간·낮음이다. 실제 게임 화면이 필요한 수치(사냥 멈춤 픽셀 기준, 설치기 밝기 기준, 기본 아이콘 감지 시간)는 여전히 [추정]이며 각 스펙이 구현 첫 단계에 측정하도록 정했다.
