# 묶음 1: 감지 대상 목록 + 버프 종료 알림 확장 + 가까운 알림 묶기 (+ 파일 분리)

작성 2026-11-09. 공통 전제는 `2026-11-09-feature-expansion-overview.md`(이하 개요)의 3절·5절을 따른다. 이 문서는 묶음 2~5가 꽂힐 공통 구조(대상 목록, 알림 경로, 저장 형식, 파일 구성)를 정한다.

표기: [확인] = 이 문서를 쓰며 `index.html` 행이나 실행 결과를 직접 확인. [추정] = 코드로 확인하지 못한 것. 행 번호는 작성 시점 `index.html`(803줄) 기준이다. 성능 숫자 중 "node 측정"은 `matchTemplate`을 임의 데이터로 node에서 돌린 값이며 브라우저 측정이 아니다.

## 1. 목표

1. 고정된 `DEFS` 3개(솔 야누스·부스터·룬)를 사용자가 추가·삭제·이름 변경·순서 변경할 수 있는 **감지 대상 목록**으로 바꾼다.
2. 유니온의 힘·유니온의 부·재물 획득의 비약·경험치 쿠폰 같은 버프를 기존 "영역 → 아이콘 드래그" 등록으로 추가해 종료 전 알림을 받는다.
3. 비슷한 때 끝나는 버프의 미리 알림을 한 번에 묶어 알린다.
4. 묶음 2~5가 공통으로 쓸 알림 경로·대상 종류 등록부·저장 형식·파일 구성을 만든다.
5. 대상이 8~10개로 늘어도 한 번의 `tick()`이 500ms 주기를 넘지 않게 한다.

## 2. 범위와 범위 밖

범위: 대상 모델, v1→v2 저장 이전, 카드·상태줄·미리보기의 다수 대상 대응, 알림 묶기, `Alerts.fire` 계약, 파일 분리, 성능 예산 장치.

범위 밖(다른 묶음): 수동 타이머(2), 사냥 멈춤 `idle`의 감지 방법(3), 설치기 쿨타임 `cooldown`의 감지 방법(4), 볼륨 증폭·PIP·백업 화면(5). 이 문서는 그 묶음이 꽂힐 자리(3.4 종류 등록부, 7절 알림 경로 계약)만 정한다.

## 3. 데이터 모델: 감지 대상 목록

### 3.1 현재 구조 [확인]

- `DEFS`가 코드에 고정(`index.html:269-276`). 이름·종류·영역/아이콘 안내문·기준값 기본값·기본 아이콘(`presets`)·기본 검색 영역(`presetArea`)·기본 배율(`presetScales`)을 함께 가진다.
- 사용자 설정은 `cfgs[id]`(`:279-281`)에 `enabled, area, tpl, frameW, frameH, threshold, durationSec, leadSec, repeatSec, kind`로 저장. 이름은 저장하지 않는다.
- 소리 모양은 `SOUNDS[d.id]`로 id에서 골라진다(`:425-426`: id가 `sol`/`booster`면 그 패턴, 아니면 kind로 대체). 새 id를 만들면 kind 기본값으로 떨어진다.
- 슬롯 키는 `id.이벤트`이고 `previewSlot`이 `'.'`로 쪼갠다(`:468`). id에 `.`이 있으면 깨진다.

### 3.2 대상(Target) 형식

저장되는 것만 적는다. 코드에 있는 것(기본 아이콘 이미지, 검색 영역 함수)은 저장하지 않는다.

```
Target = {
  id: string,            // 3.3 규칙
  kind: 'buff'|'countdown'|'rune'|'idle'|'cooldown',
  name: string,          // 표시·음성에 쓰는 이름
  preset: 'sol'|'booster'|null,   // 내장 기본 아이콘 세트 키. null이면 직접 등록만 가능
  enabled: boolean,
  threshold: number,     // 0.40–0.98, 일치도 기준값 (기존 슬라이더 범위 :316)
  area: {x,y,w,h}|null,  // 직접 등록한 검색 영역 (원본 프레임 좌표)
  tpl: {url,w,h}|null,   // 직접 등록한 아이콘 (PNG data URL). null+preset이면 기본 아이콘 사용
  frameW: number, frameH: number,   // 등록 당시 프레임 크기. 0이면 미등록
  hint: {scale:number}|null,        // 9.3 배율 고정. 기본 아이콘 검색을 줄이는 캐시. 지워도 동작에 영향 없음
  p: object              // 종류별 매개변수 (3.4)
}
```

공통 필드와 종류별 필드를 `p`로 나눈 이유: 묶음 3·4가 `p`에 자기 필드를 넣어도 공통 코드(목록, 저장, 이전, 백업)를 건드리지 않게 하려는 것이다.

종류별 `p`:

| kind | p | 기본값 | 근거 |
|---|---|---|---|
| `buff` | `durationSec:number|null`, `leadSec:number` | `null`(자동 학습), 10 | `:280`, `:331-337` |
| `countdown` | `leadSec:number` | 10 | `:280`, `:336` |
| `rune` | `repeatSec:number` | 60 (0이면 반복 끔) | `:280`, `:339-340` |
| `idle` (예약) | 묶음 3이 정의 | | |
| `cooldown` (예약) | 묶음 4가 정의 | | |

범위 제한: `leadSec` 1–120(`:337`), `repeatSec` 0–600(`:340`), `durationSec`는 `leadSec`보다 커야 한다(5.4 입력 검사).

### 3.3 id 규칙·순서·켜기/끄기·이름

- 내장 3개는 기존 id `sol`, `booster`, `rune`을 그대로 쓴다. 기존 슬롯 키(`sol.pre` 등)를 이전 없이 이어가기 위해서다.
- 새 대상 id는 `u` + 단조 증가 숫자(`u1`, `u2`, …). 증가 카운터 `seq`는 저장소에 둔다. **삭제한 id는 다시 쓰지 않는다.** 그래서 지워진 대상의 내 소리 슬롯이 새 대상에 잘못 붙는 일이 없다.
- 대상 id 형식은 `^(sol|booster|rune|u\d+)$`. 이 밖의 접두어는 다른 묶음 몫으로 예약한다: `sys`(연결 문제, 기존), `grp`(묶음 알림, 이 문서), `manual`(수동 타이머의 내 소리 슬롯 `manual.pre` 등, 묶음 2), `m\d+`(수동 타이머 개별 id. 알림의 `id`·`tag`에만 쓰고 슬롯에는 쓰지 않음, 묶음 2). 사냥 멈춤(묶음 3)과 설치기(묶음 4)도 일반 대상이므로 `u\d+` id를 쓴다. id에 `.`은 들어갈 수 없다.
- 순서는 `targets` 배열 순서가 곧 순서다. 카드, 상태줄, 감지 순서, 소리 설정 그룹이 이 순서를 따른다. 순서 변경 UI는 드래그가 아니라 카드 펼침 영역의 `위로`/`아래로` 버튼(키보드로도 됨).
- 켜기/끄기는 기존 `사용` 체크박스(`:306`)를 유지한다. 꺼진 대상은 감지·알림·묶기 후보에서 모두 빠진다. **끄는 순간 그 대상의 상태를 `newState()`로 초기화한다**: 지금은 끄고 켤 때 `st.present`/`presentAt`이 낡은 채 이어진다 [확인: `:327`은 `c.enabled`만 바꾸고 `states`는 건드리지 않음].
- 이름: 1–12자, 앞뒤 공백 제거, 다른 대상과 **같은 이름 금지**(음성으로 구분 못 한다). 이름을 바꿔도 id·슬롯은 그대로다. 이름은 음성 문구(`${name} 10초 전`, `:407`)에 그대로 들어가므로 받침 규칙이 필요한 곳은 기존 `eunNeun`/`eulReul`(`:290-291`)을 쓴다.
- 대상 수 상한 12개. 이유는 9.3.

### 3.4 종류 등록부 `KINDS` (묶음 3·4가 꽂히는 자리)

종류별 동작을 `if(kind===...)`로 흩지 않고 등록부 한 곳에 둔다. 지금은 `buildCards`(`:310-316`), `renderCard`(`:360-370`), `tick`(`:708-712`), `stepDetector`(`:181-208`)에 분기가 흩어져 있다 [확인].

```
KINDS[kind] = {
  label: string,                       // '버프' 등. 대상 추가 메뉴·소리 설정에 표시
  defaults(): p,                       // 새 대상의 p
  needsTemplate: boolean,              // 직접 등록(영역→아이콘)이 필요한가. buff/rune: true, countdown: preset 있으면 생략 가능
  trackSeen: boolean,                  // "아직 못 찾음" 표시 여부. buff/countdown true, rune false (:542)
  events: [{ key, label, beep, group, msg(t, info) }],
                                       // key: 슬롯 이벤트 이름('pre','gone','appear','remind','unread',…)
                                       // beep: SOUNDS 키. group: null | 'pre' | 'gone'  (6.2)
                                       // msg(t, info): 해요체 한 줄 문구. info는 Event에 붙은 값(경과 초 등, 없으면 {})
  register: { steps: ('area'|'icon')[], save(t, rects, snap): void },
                                       // 등록 드래그 단계. buff/rune ['area','icon'], idle ['area'], cooldown ['icon'](영역 자동)
  isRegistered(t): boolean,            // 지금의 needsRegister 반대. 기본: tpl 또는 preset이 있으면 true
  needsReregister(t, frame): boolean,  // 기본: frameW/H가 현재 프레임과 다르면 true (:296)
  maxInstances: number,                // 기본 12(전체 상한). idle은 1
  onSkip: boolean,                     // true면 감지를 건너뛴 틱에도 step(t, st, null, null, now)를 부른다 (idle)
  status(t, st, now): {text, cls, sub},  // 카드 상태 문구 (renderCard 분기를 대신)
  stripState(t, st, now): string,        // 상태줄 값 'ok'|'off'|'reg'|'rereg'|'unseen'|종류별 값 (5.6)
  detect(t, source, ctx): object|null,   // 화면에서 찾기. 반환형은 종류별(템플릿 종류는 {score,pos}, 공용 detectTemplate)
  step(t, st, det, source, now): Event[],     // 상태기계. Event = string | {key, info}. 기존 stepDetector/stepCountdown을 감싼다
  remainSec(t, st, now): number|null,         // 끝날 때까지 추정 남은 초. 묶기의 당겨 알림(6.3)이 씀. 모르면 null
  cardFields(t): FieldSpec[],                 // 카드에 보일 입력칸 (지속시간, 미리 알림, 반복 알림, …)
  cost(t): number                             // 대략 감지 비용 ms 추정 (9.2). 예산 표시용
}
```

묶음 3(`idle`)과 4(`cooldown`)는 이 객체를 하나씩 추가하고, 필요한 슬롯 이벤트(`idle.stop`, `cooldown.ready` 같은 이름은 그 묶음이 정한다)를 `events`로 선언한다. 소리 설정 목록(`SLOTS`)은 `events`에서 자동으로 만들어진다(4.4).

### 3.5 내장 기본 세트(`PRESETS`)

`preset` 키가 가리키는 코드 상수. 저장하지 않는다.

```
PRESETS.sol     = { kind:'buff',      name:'솔 야누스', threshold:.75, icons:[3개 data URL, w:32,h:32,crop:2],
                    area: f=>{x:.35w, y:0, w:.65w, h:.3h}, scales:[1,1.25,1.5], areaLabel:'버프창 영역', iconLabel:'솔 야누스 아이콘' }   // :270-271, :646, :652
PRESETS.booster = { kind:'countdown', name:'부스터',   threshold:.7,  icons:[1개, w:65,h:19,crop:0],
                    area: f=>{x:.2w, y:0, w:.6w, h:.3h}, scales:[.8,1,1.25,1.5], areaLabel:'남은시간 타이머 주변', iconLabel:'“◷ 남은시간” 글자' }  // :272-274
```

- `tpl`이 있으면 직접 등록이 우선, 없고 `preset`이 있으면 기본 아이콘(지금의 `usingPreset`, `:648`).
- `기본 아이콘으로 되돌리기` 버튼은 `preset`이 있는 대상에만 보인다(지금의 `:322`, `:352`).
- 내장 대상도 삭제할 수 있다. 삭제하면 `대상 추가` 메뉴의 "기본 제공" 칸에 다시 나타나고, 되돌리면 기본값으로 새로 만들어진다(id는 원래 `sol`/`booster` 그대로 복원 가능: 현재 목록에 없을 때만).
- 룬은 기본 아이콘이 없고(`:275`) `preset:null`이다. 룬을 여러 개(다른 맵의 룬 등) 만들 이유는 없다고 보고 "기본 제공"에 둔다.

기본 시작 목록(저장소가 비어 있는 새 사용자): `sol`, `booster`, `rune` 순서의 3개. 지금 첫 화면과 같다.

## 4. 저장과 이전

### 4.1 새 키

| 키 | 위치 | 내용 |
|---|---|---|
| `maple-web-timer-v2` | localStorage | `{ver:2, seq, targets:Target[], group:{on:false, windowSec:10}}` |
| `maple-web-timer-v1` | localStorage | 이전 형식. **지우지 않는다**(되돌릴 길). 새 코드는 읽기만 한다 |
| `maple-web-timer-ui` | localStorage | 그대로. 키 추가: `open:{[id]:boolean}`(카드 펼침 상태), `stripOpen:boolean` |
| IndexedDB `maple-web-timer`/`sounds` | | DB 이름·버전·스토어 그대로(`:450`). 키만 4.4 규칙 |

`group` 설정을 저장소에 두는 이유: 묶음 5의 백업이 한 JSON으로 다루기 쉽다. 음량·음성 켜기(`#vol`, `#voice`)는 지금 저장되지 않는다 [확인: localStorage 사용처는 `:279, :282, :293, :294` 뿐]. 저장 여부는 묶음 5가 정한다.

### 4.2 v1 → v2 이전 (첫 로드 한 번)

조건: `v2`가 없고 `v1`이 있을 때만. 순서:

1. `v1`을 파싱한다. 실패하면 이전하지 않고 기본 시작 목록으로 시작한다(v1은 건드리지 않음).
2. **부스터 재설정을 먼저 적용**: `v1.booster`가 있고 `ver!==2`이면 `tpl=null, area=null, frameW=frameH=0, threshold=0.7`로 만든다(현재 `:281`과 같은 동작). 이후 v2에서는 `ver` 필드가 필요 없다(재설정 이력은 이 이전에서 끝난다).
3. 내장 3개를 `sol`, `booster`, `rune` 순서로 만든다. 각 필드 매핑:

| v1 필드 | v2 | 비고 |
|---|---|---|
| (DEFS의 name) | `name` | `솔 야누스`/`부스터`/`룬` |
| (DEFS의 kind) | `kind`, `preset` | `sol`→`buff`/`sol`, `booster`→`countdown`/`booster`, `rune`→`rune`/null |
| `enabled` | `enabled` | 없으면 true |
| `threshold` | `threshold` | 없으면 `PRESETS` 기본값 또는 룬 0.8(`:275`) |
| `area`, `tpl`, `frameW`, `frameH` | 같은 이름 | 그대로 |
| `durationSec` | `p.durationSec` | sol만. 없으면 null |
| `leadSec` | `p.leadSec` | sol·booster만. 룬의 `leadSec`는 쓰이지 않으므로 버림 |
| `repeatSec` | `p.repeatSec` | 룬만. 없으면 60 |
| `kind` (v1에 저장된 것) | 무시 | DEFS 값이 기준 |
| `ver` | 2단계에서 소비 후 버림 | |

4. `seq`=0, `group={on:false, windowSec:10}`(묶기는 기본 꺼짐, 사용자 결정 15절).
5. `v2`를 쓴다. 쓰기에 실패하면(용량 초과 등) 메모리의 목록으로 계속 동작하고 알림줄에 "설정을 저장하지 못했어요"를 띄운다.

v1에 알 수 없는 id가 있어도(과거 실험 등) 무시한다. 이전은 멱등이다: `v2`가 있으면 `v1`은 다시 읽지 않는다.

되돌아가는 경우(이전 버전 `index.html`로 열기): 이전 버전은 `v1`을 읽으므로 이전 시점의 설정으로 동작한다. v2에서 바꾼 것은 반영되지 않는다. 혼자 쓰는 도구이므로 허용한다.

### 4.3 로드 시 검사(`normalizeTarget`)

`v2` 로드 때마다 각 대상에 적용: 알 수 없는 필드 보존, 범위 밖 값은 clamp, `kind`가 `KINDS`에 없으면 **삭제하지 않고** `enabled:false`로 두며 카드에 "이 버전에서 지원하지 않는 종류예요"만 표시(미래 버전 데이터 보호). 중복 id는 뒤의 것을 버린다. `seq`는 `max(seq, 가장 큰 u번호)`로 올린다.

### 4.4 내 소리 슬롯(IndexedDB)

- 슬롯 키 = `대상id.이벤트`. 이벤트 이름은 `KINDS[kind].events[].key`. 시스템은 `sys.lost`, `sys.stall`(그대로). 묶음 알림은 `grp.pre`, `grp.gone`(새로 추가).
- `SLOTS` 상수 배열(`:435-445`)을 없애고 **`slotsOf(targets)`로 계산**한다: 대상 순서대로 `{key, group:대상 이름, label:이벤트 label}` + 묶음 슬롯 2개 + 수동 타이머 슬롯 4개(묶음 2: `manual.pre`, `manual.end`, `manual.next1`, `manual.next2`) + 시스템 슬롯 2개. 대상이 추가·삭제·개명될 때 소리 설정 화면(`buildSounds`, `:490`)을 다시 만든다. 지금 `loadSounds`가 `SLOTS`에 없는 키를 버리는 동작(`:518`)은 4.5의 정리 규칙으로 바꾼다.
- `previewSlot`은 `key.split('.')`로 id를 찾아 `defOf(id)`를 부른다(`:468-470`). 대상 목록에서 `id`를 찾고 `KINDS[...].events`에서 `msg`를 얻도록 바꾼다. 못 찾으면 소리 미리듣기만 한다.

### 4.5 대상 삭제와 슬롯

1. 삭제 확인: `"유니온의 힘" 대상을 지울까요? 내 소리 2개도 함께 지워져요.` (내 소리가 없으면 뒷문장 생략)
2. 지우면 목록에서 즉시 빼고, 메모리에 대상·슬롯 파일을 **10초간 보관**하며 토스트로 `지웠어요 · 되돌리기`를 보인다. 되돌리기를 누르면 같은 id·같은 위치로 복원한다.
3. 10초가 지나면 IndexedDB의 그 대상 슬롯 키들을 지운다.
4. 10초 안에 탭이 닫히면 슬롯이 남는다. 다음 로드의 **고아 정리**가 처리한다: 키의 id가 `sys`/`grp`/`manual`/`m\d+` 예약 접두어도 아니고 현재 `targets`에도 없으면 삭제한다. 정리는 `v2`를 정상 파싱했을 때만 수행한다(저장소가 비었거나 깨져서 기본 목록으로 시작한 경우에는 소리를 지우지 않음).
5. id를 재사용하지 않으므로(3.3) 고아 슬롯이 다른 대상에 붙는 일은 없다.

용량: 슬롯 파일 5MB 제한은 슬롯당이다(`:446`). 대상이 12개, 슬롯이 대상당 2~3개면 이론상 최대 수백 MB다. 지금과 같은 슬롯당 제한만 유지하고 총량 제한은 두지 않는다(혼자 쓰는 도구). 용량 초과 오류는 기존 `soundNote` 경로로 보인다(`:482`).

## 5. 버프 확장 UX

### 5.1 대상 추가 흐름

카드 목록 위에 `+ 대상 추가` 버튼. 누르면 메뉴:

```
기본 제공 (목록에 없는 것만)      솔 야누스 · 부스터 · 룬
버프 직접 등록                    유니온의 힘 · 유니온의 부 · 재물 획득의 비약 · 경험치 쿠폰 · 이름 직접 입력…
```

- "버프 직접 등록"의 이름 칸은 **이름만 채운다.** 지속시간·기준값·아이콘은 아무것도 미리 채우지 않는다. 이름은 개요에 적힌 버프 이름이며 게임 내 지속시간은 확인한 바 없다(5.3).
- 이름을 고르면 `kind:'buff'`, `preset:null`, `enabled:true`, `threshold:0.75`(솔 야누스 기본과 같음, `:270`), `p:{durationSec:null, leadSec:10}`인 대상이 만들어지고 카드가 펼쳐진다.
- 화면이 연결되어 있으면 곧바로 등록 단계로 들어간다(`startRegister`, `:761`). 연결 전이면 카드에 `등록 필요 · 게임 화면을 연결한 뒤 등록할 수 있어요`(기존 문구 `:357`, `:762` 계열)를 보이고 상태줄에 `등록하기` 버튼이 뜬다.
- 방금 만든 대상의 첫 등록을 `Esc`/`취소`하면 그 대상을 자동으로 지운다(빈 "등록 필요" 카드가 쌓이지 않게). 이미 등록된 대상의 재등록 취소는 아무것도 바꾸지 않는다(현재 동작).
- 안내 문구: 영역 단계 `① 버프창 영역을 넉넉하게 드래그하세요`, 아이콘 단계 `② ${이름} 아이콘 하나만 꼭 맞게 드래그하세요`(기존 `:772-773` 형식에 이름만 대입. `areaLabel`은 buff의 기본값 `버프창 영역`).

### 5.2 등록 때 도움

버프 아이콘은 버프창에서 줄을 이루고 다른 버프와 같은 줄에 있다. 지금 등록은 영역을 먼저 넓게 잡게 되어 있어(`:781-792`) 그대로 쓸 수 있다. 추가로:

- 영역을 다른 대상의 영역과 같게 잡는 것은 허용한다(같은 버프창을 공유하는 것이 정상). 아이콘 크기가 6px 미만이면 무시하는 기존 규칙(`:783`) 유지.
- 같은 아이콘을 두 대상에 등록하는 것은 막지 않는다. 다만 아이콘 단계 직후 **다른 대상의 템플릿과 같은 위치·같은 이미지로 일치도 0.95 이상이면** 노트로 `${다른이름}과 같은 아이콘 같아요`를 보인다 [추정: 실수 방지용. 오탐이어도 등록은 진행].

### 5.3 지속시간

- 입력은 기존 `분:초` 칸(`:313`, `parseDur` `:287`). `30`처럼 숫자만 쓰면 분으로 읽는다(기존 동작 유지).
- 칸을 비우면 **자동 학습**: 한 번 켜지는 것을 보고 꺼질 때 길이를 기억(`:192-195`). 15초 미만은 학습하지 않는다(`d>=15`).
- 기본값은 두지 않는다 [추천]. 이유: 게임 안 지속시간은 확인하지 못했고(조사 안 함), 틀린 값이 있으면 틀린 시각에 알림이 울린다(PRODUCT 원칙 3). 학습 또는 사용자가 직접 입력하는 값만 쓴다. 처음 한 주기는 "켜짐 · 학습 중"으로 보이고 알림이 없다는 점을 카드 부제로 알린다(기존 `:369` 문구).
- 학습 값이 틀릴 수 있는 경우 [추정]: 버프를 도중에 직접 취소하면 짧은 값이 학습된다. 학습이 끝나면 카드에 `학습한 시간 12:00 · 맞지 않으면 직접 고치세요`를 한 번 보이고 칸에 채워진다(이미 `:711`에서 칸을 채움).

### 5.4 입력 검사

- 지속시간 ≤ 미리 알림 초이면 켜지자마자 `pre`가 울린다(`:201-204`, `now>=endAt-lead*1000`) [확인: 코드상 그렇다]. 그래서 `durationSec`가 `leadSec` 이하면 거절하고 `미리 알림(10초)보다 길게 입력해 주세요`.
- `leadSec`를 `durationSec` 이상으로 바꾸는 것도 같은 이유로 거절한다.
- `parseDur`가 `undefined`(형식 오류, `:287`)이면 기존처럼 이전 값으로 되돌린다.

### 5.5 카드 UI (대상 8~10개)

현재 카드는 한 장 약 230px 높이를 가정하면 10개에 2300px 이상이다 [추정: 렌더 높이는 측정하지 않음]. 카드 열이 길어지면 옆 설정(미리보기 아래 설명서·소리)이 아래로 밀리므로 카드를 **두 모드**로 만든다.

- **접힌 카드**(기본, 한 줄 약 48px): `[썸네일 32px] 이름  상태 문구(예: 남은 시간 03:12)  [사용 체크]  [펼치기 ▾]`. 상태 색(켜짐/알림/꺼짐)은 현재 `.status` 클래스 규칙 그대로.
- **펼친 카드**: 지금의 카드와 같은 내용 + `이름 바꾸기`, `위로`/`아래로`, `삭제` 버튼. 종류별 칸은 `KINDS[kind].cardFields`에서 만든다.
- 접기 상태는 `ui.open[id]`에 저장한다. 새로 만든 대상과 `등록 필요`/`다시 등록 필요` 대상은 처음에 펼쳐 둔다. 사용자가 접은 것은 자동으로 펼치지 않는다(알림이 울려서 카드가 움직이면 헷갈린다). 알림 깜빡임(`.flash`, `:63`)은 접힌 카드에도 적용된다.
- 한 줄 카드의 `상태 문구`는 `renderCard`가 이미 계산하는 `text`를 쓴다(`:372`).
- 미리보기 캔버스(`drawPreview`, `:733-749`)는 모든 대상의 점선 영역과 라벨을 그리는데 10개면 겹친다. 점선 영역과 라벨은 **펼친 카드의 대상**과 일치도 박스를 표시 중인 대상만 그린다. 일치 박스(`st.pos`)는 모든 대상에 계속 그린다(겹침 회피 로직 `:744` 유지).
- 헤더 부제 `솔 야누스 · 부스터 · 룬`(`:93`)은 `감지 대상 N개`로 바꾼다.
- 설명서(`:125-129`)의 "솔 야누스와 부스터는 따로 등록하지 않아도…" 문구는 유지하되 `+ 대상 추가`로 버프를 늘리는 방법을 한 줄 추가한다: `다른 버프는 “+ 대상 추가”에서 이름을 고르고 영역 → 아이콘 순서로 등록하세요.`

### 5.6 상태줄(`renderWatch`)

지금은 대상 이름을 `·`로 이어 모두 나열한다(`:541-551`) [확인]. 10개면 두 줄 이상으로 길어져 탭을 숨기기 전 한눈에 확인한다는 목적을 해친다.

규칙:

- 켜진 대상이 5개 이하이면 지금 그대로 모두 나열한다.
- 6개 이상이면 **문제 있는 대상만 개별로** 보인다(`등록하기`/`다시 등록` 버튼, `아직 못 찾음`, `꺼둠`). 정상 대상은 `정상 7개`로 묶고 눌러서 이름 목록을 펼친다(`ui.stripOpen`).
- 다시 등록이 3개 이상 필요하면 개별 버튼 대신 `다시 등록 4개 · 차례로 등록` 버튼 하나로 묶는다(10절 해상도 변경).
- `renderWatch`의 `watchKey` 캐시(`:543-544`)는 새 표시 규칙을 반영해 키를 만든다(매 틱 스크린 리더가 다시 읽지 않게 하는 기존 목적 유지).
- 이름이 같은 `unseen` 판정은 `KINDS[kind].trackSeen`으로 일반화(`:542`는 `d.kind!=='rune'`).
- 연결 안 됨 상태에서는 대상 목록을 상태줄에 보이지 않는 현재 동작 유지(`:541`의 `src ?`).

## 6. 알림 묶기

### 6.1 지금의 알림 [확인]

- 한 대상당 `fire`(`:427`) → `notify`(`:418`): 내 소리가 있으면 그것, 없으면 `beep`(소리 패턴) 뒤 `speak`(음성). 토스트(6초), 탭 제목 깜빡임, 숨겨진 탭이면 `Notification`.
- 소리는 `beepEnd`(`:384`)로 순서대로 이어 예약되어 겹치지 않는다. 음성은 같은 문구 8초 중복 억제(`:401`), 큐가 15초 넘게 막히면 비운다(`:402`).
- 가까운 시각에 둘이 끝나면 비프+음성이 차례로 두 번 울린다. 예: 솔 야누스 `pre`와 유니온의 힘 `pre`가 3초 차이면 비프(약 0.8초)+음성(약 1.5초) 뒤에 다시 비프+음성이 이어진다 [추정: 음성 길이는 측정 안 함].

### 6.2 무엇을 묶나

| 묶음 종류(`group`) | 대상 이벤트 | 묶기 방식 |
|---|---|---|
| `'pre'` | `buff`·`countdown`의 `pre`(미리 알림), 묶음 4 `cooldown`의 `pre`(설치기 사라지기 전) | 같은 틱에 모인 것 + **당겨 알림**(6.3) |
| `'gone'` | `buff`·`countdown`의 `gone`(꺼짐: 미리 알림을 못 울린 경우) | 첫 건 뒤 2초 안에 오는 것 |
| 묶지 않음 | 룬 `appear`/`remind`, `unread`, 시스템(`sys.*`), 묶음 3 `idle`의 `alarm`, 묶음 4 `cooldown`의 `ready`·`unread`, 수동 타이머 | 개별. 룬은 위치를 찾아야 하는 긴급 알림이라 섞지 않는다 [추천] |

`pre`와 `gone`은 서로 섞지 않는다. 묶음 3·4·2가 자기 이벤트를 묶고 싶으면 `events[].group`에 `'pre'`/`'gone'`을 지정한다(새 종류의 묶음은 이 문서 범위 밖).

### 6.3 당겨 알림(pull-forward)

같은 틱에 `pre`가 겹치는 경우만으로는 3초 이상 어긋난 버프를 못 묶는다. 한편 첫 알림을 N초 기다리면 미리 알림의 의미(10초 전)가 깎인다. 그래서 `pre`는 **기다리지 않고**, 첫 `pre`가 나는 순간에 곧 끝날 다른 대상을 같이 알린다.

- 틱 끝에서 `pre` 이벤트가 하나라도 나왔고 묶기가 켜져 있으면, 켜진 대상 Y 중 종류의 `events`에 `group:'pre'` 이벤트가 있고(지금은 `buff`·`countdown`·`cooldown`) 아직 `alertedPre`가 아니며 `remainSec(Y) <= Y.p.leadSec + windowSec`인 것을 같이 묶는다. 묶인 Y의 `st.alertedPre`는 true로 해 이후 `pre`와 `gone`이 다시 울리지 않게 한다(PRODUCT 정책 "미리 알림 뒤에는 꺼짐 알림 없음" 유지).
- `windowSec` 기본 10초. 사용자 선택지: 끄기·5초·10초·20초(열린 질문 2).
- `remainSec`: 버프는 `appearedAt + durationSec*1000 - now`(`:202`와 같은 식), 카운트다운은 `st.remain - (now - st.remainAt)/1000`(`:366`과 같은 식). 켜진 시점을 모르거나(`appearedAt==null`) 지속시간이 없으면 `null`이라 당겨지지 않는다.
- 묶인 것이 하나뿐이면(당겨올 대상 없음) 지금과 똑같이 개별 알림이다.

### 6.4 소리·음성·토스트

묶인 알림(2개 이상) 한 번에 대해:

| 항목 | 동작 |
|---|---|
| 소리 | `grp.pre`(또는 `grp.gone`)에 내 소리가 있으면 **그것 하나만** 재생(기본 비프+음성 대체. `:419`와 같은 규칙). 없으면 새 소리 패턴 `multi`(예: 같은 음 세 번 + 높은 음, 정확한 음은 구현에서 정함) 뒤 합친 음성 |
| 멤버 개별 소리 | 재생하지 않는다(여러 번 울리지 않으려는 목적). 멤버에 내 소리가 있어도 묶인 알림에서는 쓰이지 않는다. 소리 설정의 묶음 슬롯 설명에 이 사실을 적는다(열린 질문 3) |
| `beepEnd` 순서 | 묶인 알림은 하나의 소리 덩어리로 `beepEnd`에 이어 예약한다. 앞서 울린 다른 알림(예: 룬)이 끝난 뒤에 이어 울린다 |
| 음성 문구 | `pre`: `A, B 곧 끝나요`. `gone`: `A, B 꺼졌어요`. 이름은 남은 시간이 짧은 순(같으면 목록 순서). 4개 이상: `4개 곧 끝나요` / `4개 꺼졌어요`(설치기가 섞일 수 있어 "버프"라고 하지 않음). 이름 뒤 조사 없음(받침 규칙을 피함). 숫자 초는 말하지 않는다(당겨진 대상의 남은 시간이 서로 달라서 한 숫자가 틀린다) |
| 토스트 | 같은 문구 한 줄. 하나뿐 |
| 탭 제목 | `⚠ A, B 곧 끝나요`(기존 깜빡임 규칙 `:421-422`) |
| 브라우저 알림 | 한 번. `tag:'grp.pre'`, `renotify:true` |
| 카드 깜빡임 | 묶인 멤버 카드 각각(`.flash`) |
| 음성 중복 억제 | 합친 문구도 기존 8초 규칙(`:401`)을 적용한다. 멤버 구성이 다르면 문구가 다르다 |

정책과의 관계: (1) 연결 끊김 재알림 2회 제한은 `sys.*`이고 묶지 않으므로 영향 없음. (2) 묶인 멤버는 `alertedPre`가 되어 꺼짐 알림이 없다. (3) 기본 음성 문구(`솔 야누스 10초 전` 등) 개별 알림은 그대로다. 합친 문구는 묶인 경우에만 쓰는 새 문구이며, 바꾸고 싶으면 `grp.pre` 내 소리 파일로 바꾼다(정책과 같은 방식).

### 6.5 테스트 버튼

대상 카드의 `알림 테스트`(`:344`)는 `src:'test'`로 불러 **묶지 않고** 개별 알림을 재생한다. 소리 설정에는 `묶음 알림 · 미리 알림`/`꺼짐` 두 슬롯이 있고 `듣기`는 켜진 버프 앞 두 개의 실제 이름으로 합친 문구를 재생한다(없으면 `A, B`가 아닌 `유니온의 힘, 유니온의 부` 예시 문구).

## 7. 알림 경로 계약 `Alerts.fire`

묶음 2(수동 타이머)가 호출하고 묶음 5(볼륨 증폭·PIP)가 붙는 단 하나의 경로. 지금의 `notify`(`:418`), `fire`(`:427`), `fireSystem`(`:432`)을 대체한다.

### 7.1 요청 형식

```
AlertReq = {
  src:   'target' | 'manual' | 'system' | 'test',
  id:    string,         // 소유자 id: 대상 id, 'sys', 수동 타이머 'm3'. 슬롯·카드 깜빡임·tag에 쓴다
  event: string,         // 'pre' | 'gone' | 'appear' | 'remind' | 'unread' | 'lost' | 'stall' | 'back' | 묶음 2~4의 이벤트
  text:  string,         // 해요체 한 줄. 음성·토스트·탭 제목·브라우저 알림에 쓴다
  beep:  string | null,  // SOUNDS 키. null이면 비프 없이 음성만
  slot:  string | null,  // 내 소리 슬롯 키. 기본 `${id}.${event}`
  mode:  'full' | 'voice',   // 'voice'는 지금의 'back' 처럼 음성만 (:432)
  group: null | { cls:'pre'|'gone', label:string, rank:number },
                         // label: 묶인 문구에 들어갈 이름. rank: 남은 초(작을수록 먼저)
  flash: string | null,  // 깜빡일 카드 DOM id. 기본 `card-${id}`
}
```

`beep`가 가리키는 패턴은 `SOUNDS`(`:377-383`)에서 온다. 지금 `sol`/`booster`/`gone`/`rune`/`system`에 `buff`(=sol과 같은 모양), `multi`를 더한다. 새 버프의 `beep` 기본값은 `buff`이며 대상별 선택 UI는 두지 않는다(열린 질문 6).

### 7.2 함수

```
Alerts.fire(req: AlertReq): void
Alerts.flush(now: number): void              // tick() 끝에서만 호출. 묶음 대기열을 비운다
Alerts.listen(fn: (rec: AlertRec) => void): () => void    // 재생 직전·직후 구독. 반환값은 해제 함수
Alerts.audioOut(): AudioNode                 // 모든 비프·내 소리가 연결되는 마지막 노드 (기본 actx.destination)

AlertRec = { at:number, src, ids:string[], event, text, grouped:boolean, custom:boolean }
```

동작 순서:

1. `src==='test'`·`system`·`group==null`이면 즉시 전달(`deliver`)한다.
2. `group`이 있으면 대기열에 넣는다(종류별 `cls`). `Alerts.flush(now)`에서: `pre`는 같은 틱 안에서 곧바로(대기 0), `gone`은 첫 항목이 들어온 지 2초가 지났을 때 비운다. 비울 때 멤버가 1개면 개별 알림, 2개 이상이면 묶인 알림 하나(6.4)로 전달한다.
3. `deliver`는 기존 `notify` 본문과 같다: 내 소리 슬롯 → 없으면 `beep`+`speak`, 토스트, 탭 제목, `Notification`, 카드 깜빡임. 끝나면 `Alerts.listen` 구독자에게 `AlertRec`를 보낸다.

**`flush`를 `tick()` 끝에서만 부르는 이유**: 묶음을 기다리는 데 `setTimeout`을 쓰지 않는다. 사냥 중에는 탭이 숨겨지는데, 숨겨진 탭의 메인 스레드 타이머는 느려질 수 있다 [추정: Chrome 백그라운드 타이머 제한. 이 코드가 `tick`을 Worker로 돌리는 이유와 같음 `:794-800`]. Worker가 부르는 `tick`에서만 시간을 판단하면 영향이 없다. 단 기존 코드에서 비프 뒤 음성을 `setTimeout`으로 미루는 부분(`playDefault`, `:416`)은 그대로 남아 있다 [확인: `:416`]. 오디오가 재생 중이면 제한을 덜 받을 수 있으나 확인하지 못했다.

묶음 2의 수동 타이머는 자기 시계를 `tick()`에서 평가하고 `Alerts.fire`로 알린다(`group:null` 권장). 묶음 5는 `Alerts.audioOut()`에 `GainNode`를 꽂아 증폭하고(`:394`, `:459`의 `actx.destination` 직결을 이 함수로 바꿈) `Alerts.listen`으로 PIP 깜빡임을 건다. 음성(TTS)은 `SpeechSynthesisUtterance.volume`이 1 이하이므로 증폭 대상이 아니다 [확인: `:403`은 `volume=+$('#vol').value`, 상한 1은 Web Speech 사양]. 이 한계는 묶음 5가 다룬다.

### 7.3 호출하는 쪽의 변화

- 대상 알림: `fireTarget(t, evKey)`가 `KINDS[t.kind].events`에서 `msg`, `beep`, `group`을 읽어 `AlertReq`를 만든다. 지금 `MSG`(`:406-412`)와 `soundName`(`:425-426`)이 `events`로 옮겨 간다.
- `tick`(`:702-717`)은 대상별 이벤트를 **모은 뒤**(배열) 6.3의 당겨 알림을 계산하고 `Alerts.fire`를 부른다. 이벤트를 즉시 부르던 구조를 한 단계 늦추는 것이다.
- 시스템: `fireSystem(kind)`(`:432`)는 `Alerts.fire({src:'system', id:'sys', event:kind, text:SYS_MSG[kind], beep:'system', slot:'sys.'+kind, mode: kind==='back'?'voice':'full'})`.

### 8.2 전역 규칙

- 별도 이름공간을 만들지 않는다. 함수 선언은 전역에 남고, 최상위 `const`/`let`은 같은 문서의 다른 클래식 스크립트에서 이름으로 보인다 [확인: 클래식 스크립트의 전역 렉시컬 환경 공유는 웹 표준 동작. 현재 두 `<script>` 블록이 이미 `fmt` 등을 이렇게 공유하지는 않지만(순수 함수 블록 `:147-265`와 앱 블록 `:267-801`) 앱 블록에서 앞 블록의 함수를 호출하고 있음 `:181, :655`].
- 최상위에서 즉시 실행되는 코드는 `main.js`에만 둔다. 다른 파일은 정의만 한다. 이렇게 하면 로드 순서 오류는 `main.js` 실행 시점의 정의 누락으로 한 번에 드러난다.
- 이어 붙이는 객체 전역은 `KINDS`, `PRESETS`, `Alerts` 3개만 새로 만든다.
- 순수 함수 파일(`match.js`, `detect-core.js`, `targets.js`의 순수 부분, `alerts.js`의 `planGroup`/`groupText`, `util.js`의 `parseDur`)은 끝에 `if(typeof module==='object') module.exports={...}`를 둔다. 브라우저에서는 무시되고 node에서 `require`로 테스트할 수 있다.

### 8.3 주의점

- **기본 아이콘은 JS 문자열(data URL)로 둔다.** 별도 PNG 파일로 빼서 `new Image().src='icons/x.png'`로 읽으면 `file://`에서 캔버스가 오염되어 `getImageData`가 실패할 수 있다 [추정: Chrome이 `file://` 이미지를 교차 출처로 취급하는 동작. 이 저장소에서는 확인하지 못함. 데이터 URL은 `:644`에서 이미 쓰이고 있고 동작함]. 그래서 `preset-data.js`로만 분리한다.
- Worker는 `Blob` URL로 만들므로(`:798`) 파일이 나뉘어도 영향이 없다 [확인].
- 로드 실패(파일 누락) 시 빈 화면이 되지 않도록 `index.html`에 `<noscript>`가 아니라, `main.js`가 필수 전역(`KINDS`, `Alerts`, `matchTemplate` 등)이 있는지 확인해 없으면 `#empty` 자리에 `파일이 빠졌어요: js/targets.js`처럼 어느 것이 없는지 보인다.
- 로컬 저장소(`localStorage`, IndexedDB)의 원본(origin)은 `index.html`을 여는 방식(`file://` 경로/호스팅 주소)에 따라 갈린다. 파일을 나눠도 `index.html`의 경로가 바뀌지 않는 한 달라지지 않는다 [추정]. 호스팅 여부는 PRODUCT.md에서 미정이다.

## 9. 성능

### 9.1 현재 `tick()`의 비용 구조 [확인]

- `tick`은 대상마다 `detect`를 **차례로 동기 실행**한다(`:702-717`). 한 틱 시간은 대상 비용의 합이다. `busy` 플래그(`:691`)가 있어 틱이 500ms를 넘으면 다음 틱은 건너뛴다(밀리는 것이 아니라 빠진다).
- 상태기계는 틱 횟수로 시간을 센다: 켜짐 2회, 꺼짐 4회 연속(`:181`), 학습 길이 보정이 `need.off*0.5`초(`:193`). 틱이 느려져 건너뛰면 "꺼짐 판정" 시간이 2초보다 길어지고 학습값에 오차가 생긴다 [확인: 코드가 틱=0.5초를 가정].
- `matchTemplate`은 호출마다 `Float64Array` 두 개를 새로 만든다(`:163`) [확인]. 546×142 영역이면 약 1.2MB씩이다.

### 9.2 대상 하나가 추가하는 비용

비용은 대략 `(영역 너비×k)×(영역 높이×k)×(아이콘 픽셀 수)`에 비례한다. `k`는 템플릿 짧은 변이 14픽셀이 되도록 줄이는 배율이다(`scaleFor`, `:635`). 임의 데이터로 `matchTemplate`만 node에서 측정한 값(이 Mac, 한 번 호출 평균):

| 경우 | 영역(원본 기준) | 비용 | 출처 |
|---|---|---|---|
| 직접 등록 버프, 영역 600×100, 아이콘 32px | 262×44 축소 후 | 약 1 ms | node 측정 |
| 직접 등록 버프, 영역을 넓게(1248×324) | 546×142 | 약 9 ms | node 측정 |
| 직접 등록 룬, 미니맵 300×200, 아이콘 12px | k=1 | 약 6 ms | node 측정 |
| 직접 등록 룬, 400×300 | | 약 11 ms | node 측정 |
| 부스터형 글자(65×19)를 큰 영역(1152×324)에 직접 등록, 배율 1 | 849×239 | 약 76 ms | node 측정 |
| 솔 야누스 기본 아이콘(3종×3배율=9번 검색), 영역 1248×324 | | 합 약 80 ms | node 측정(배율 1/1.25/1.5: 약 14/8/5 ms ×3종) |
| 부스터 기본(배율 4종), 영역 1152×324 | | 합 약 276 ms | node 측정(배율 0.8/1/1.25/1.5: 약 121/76/47/32 ms) |

해석:

- **직접 등록한 템플릿은 싸다**(1~11 ms). 사용자가 영역을 좁게 잡을수록 더 싸다. 버프를 늘리는 일은 직접 등록이므로 대상 10개가 모두 직접 등록한 버프여도 합이 수십 ms 수준이다 [추정: 영역을 좁게/보통으로 잡았다고 가정. 영역을 모두 넓게 잡으면 90 ms 내외].
- **기본 아이콘 대상은 비싸다.** 부스터 기본값 약 276 ms는 개요에서 측정한 약 275 ms와 맞는다 [확인: 개요 수치와 node 측정이 일치]. 솔 야누스는 개요 수치(214~460 ms)와 node 측정(약 80 ms)이 크게 어긋난다. 차이는 브라우저의 `drawImage`/`getImageData` 비용이나 실제 화면 데이터일 가능성이 있으나 [추정] 확인하지 못했다. 구현 첫 작업으로 `detect`를 단계별(`drawImage`, `getImageData`, `toGray`, 적분 영상, 검색)로 `performance.now()`로 재서 어긋난 이유를 먼저 확인한다.
- 숫자 읽기(`ocrSevenSeg`)와 `isBlank`(64×36)는 대상 수와 관계없이 대상 하나·프레임 하나 비용이다(부스터 `readTimer`는 켜져 있을 때만, `:708`).

### 9.3 예산과 장치

예산: 한 틱 전체 500 ms 중 **감지 합계 ≤ 300 ms**(나머지는 프레임 가져오기, 빈 화면 검사, 그리기, GC 몫으로 남김) [추천: 근거는 9.2의 측정이 모두 느슨한 환경에서의 값이라 여유를 둔 것].

1. **측정 표시**: `detect` 호출마다 `performance.now()`로 시간을 재어 대상별 지수 이동 평균을 낸다. 펼친 카드 아래에 `감지 4 ms`(일치도 옆)를 표시한다. 상태줄에 틱 전체 평균이 450 ms를 20틱 넘게 넘으면 `감지가 느려요 (평균 N ms) · 사용 안 하는 대상은 꺼 주세요`를 알린다.
2. **배율 고정**(`hint.scale`): 기본 아이콘이 한 번 기준값을 넘기면 그 배율을 `hint`로 저장한다. 이후 대상이 **확실히 없는 상태**(`!present && offStreak>=4`)에서는 그 배율의 아이콘만 검색한다(솔 야누스 9→3번, 부스터 4→1번). 10번에 한 번은 전체 후보를 검색해 UI 배율이 바뀐 경우를 놓치지 않는다. 대상이 켜져 있는 동안은 지금처럼 맞은 후보부터 찾고 기준값을 넘으면 바로 멈춘다(`:665`). 추정 비용: 부스터 약 276→76 ms, 솔 야누스 약 80→41 ms [추정: node 측정값에서 계산].
3. **확실히 없는 대상의 격틱 검색**: 위 조건에 해당하는 대상은 두 틱에 한 번만 검색한다. 켜짐 판정 2회 연속이 1초가 되어 켜짐을 알아채는 시각이 최대 0.5초 늦는다. 켜진 동안(꺼짐 판정 4회 연속)은 매 틱 검색하므로 꺼짐/미리 알림 시각에는 영향이 없다. 1·2로도 합이 예산을 넘을 때만 켠다(비용 EMA 합 > 300 ms).
4. **버퍼 재사용**: `matchTemplate`의 적분 배열을 크기가 같으면 재사용한다(`:163`의 매번 할당 제거). 알고리즘은 바꾸지 않는다.
5. **상한**: 대상 12개(3.3). 12개가 모두 넓은 영역의 기본 아이콘형이 되는 경우는 없다(기본 아이콘형은 내장 2종뿐).

대상 하나를 추가하기 전에 `KINDS[kind].cost(t)`로 현재 합 + 새 대상의 추정 비용이 300 ms를 넘으면 추가는 허용하되 `이 대상을 켜면 감지가 느려질 수 있어요 (추정 N ms)`를 카드에 보인다.

카드 갱신 비용: 보이는 탭에서만 `renderCard`를 틱마다 부른다(`:716`). 접힌 카드는 문구 하나만 쓰도록 하고, `textContent`가 같으면 쓰지 않는다. 10개 카드의 DOM 쓰기는 감지에 비해 작다 [추정].

### 11.2 브라우저 검사 (가짜 `getDisplayMedia`)

`getDisplayMedia`를 덮어써 `<canvas>.captureStream(5)`를 돌려주는 하네스 페이지 스크립트를 먼저 주입한다. 캔버스에는 1920×1080 배경(밝기 8 이상, `isBlank` 회피 `:682-688`)에 합성 아이콘(서로 다른 무늬의 32×32 사각형 여러 개)을 버프 줄처럼 그리고, 시나리오에 따라 그리거나 지운다. `Date.now`를 덮어 시간을 앞당긴 채 `tick()`을 직접 부른다(`wk.onmessage=tick`, `:799`). `SpeechSynthesis.speak`와 `AudioContext.createOscillator`를 가로채 호출 문구·횟수를 센다.

1. **이전**: 페이지 로드 전에 v1 샘플(`tpl`, `durationSec`, `booster.ver` 없음 포함)을 `localStorage`에 넣고 로드 → 카드 3장·`v2` 저장 확인, `v1`은 그대로.
2. **버프 추가**: `+ 대상 추가` → `유니온의 힘` → 합성 프레임에서 포인터 이벤트로 영역→아이콘 드래그 → 카드 `켜짐`/일치도 ~1.0. 아이콘을 지우고 4틱 뒤 `꺼져 있음`.
3. **지속시간·미리 알림**: 지속시간 `1:00`, 미리 알림 10초 → 켜진 뒤 시각을 50초 앞당기면 `유니온의 힘 10초 전`이 한 번 울리고 이후 꺼짐 알림이 없다.
4. **묶기**: 버프 둘을 3초 차이로 켠다 → 음성 호출이 `A, B 곧 끝나요` 한 번, 토스트 한 번, 두 카드 깜빡임. 11초 차이는 개별 두 번. `windowSec` 끄기에서는 개별.
5. **내 소리 + 묶기**: `grp.pre`에 합성 WAV를 넣으면 비프·음성 없이 그 소리만. 멤버 슬롯만 있고 `grp.pre`가 없으면 기본 묶음 알림이 나온다.
6. **정책**: 연결 끊김은 즉시 1번 + 2분 간격 2번에서 멈춤(시각 앞당김). 묶음이 룬 `appear`를 삼키지 않는다.
7. **삭제·되돌리기**: 내 소리가 있는 대상을 삭제 → 10초 안에 되돌리기 → 슬롯 복원. 10초 뒤에는 IndexedDB에서 키가 사라진다. 새로고침으로 고아 정리 확인.
8. **다수 대상**: 대상 10개(합성 아이콘 10종)를 등록 → 카드 접힘 높이·상태줄이 `정상 10개`로 한 줄인지, 스크롤 위치·소리 설정 목록이 정상인지.
9. **성능**: 1920×1080 합성 프레임에서 (a) 직접 등록 10개 (b) 내장 2종 + 직접 등록 8개 (c) 내장 2종이 모두 없는 상태에서 틱 시간(`performance.now()`)을 100틱 측정해 평균/최대를 기록한다. 기준: (a)(b)는 평균 ≤ 300 ms, (c)는 배율 고정 전/후를 비교해 줄어드는지 본다.
10. **해상도 변경**: 캔버스를 1280×720으로 바꾸면 모두 `다시 등록 필요` → 상태줄 `차례로 등록`으로 하나씩 등록.
11. **파일 분리**: `file://`로 `index.html`을 열어 콘솔 오류 없음, 기본 아이콘 검색 동작(오염 오류 없음 8.3), 전역 누락 안내문 확인(스크립트 한 개를 지운 사본).

## 16. 검토 반영 (2026-11-09)

독립 검토 결과를 원문·코드와 대조해 받아들인 것. 본문과 다르면 이 절이 우선한다. 심각도는 검토자 판정이 아니라 대조 후 다시 매긴 값이다.

1. **[높음, 묶기를 켰을 때만] 부스터 당겨 알림 뒤 미리 알림이 다시 울림.** `stepCountdown`은 읽은 값이 `leadSec+5`보다 크면 `alertedPre`를 끈다 [확인 `index.html:261`]. 당겨 알림은 남은 시간 `leadSec+windowSec`(기본 20초) 안에서 일어나므로, 당긴 직후 19초를 읽으면 플래그가 꺼져 10초에 `pre`가 또 울린다. 수정: 종류 공통 함수 `KINDS[k].markPre(st, now)`를 두고 당겨 알림과 자체 `pre`가 모두 이것을 부른다. 카운트다운의 `markPre`는 `alertedPre=true`와 `st.preMarkRemain=remainSec`를 기록하고, `stepCountdown`의 재무장 조건을 `value > max(leadSec, preMarkRemain) + 5`로 바꾼다(부스터를 새로 썼을 때만 재무장). 11.1에 "카운트다운 당김 뒤 19초 읽기 → `pre` 없음", 11.2에 같은 브라우저 시나리오를 더한다.
2. **[중간] 묶기 설정의 화면과 읽는 경로.** `Alerts.configure({on, windowSec})`를 둔다. `on=false`이면 `Alerts.fire`는 `group`을 무시하고 즉시 전달한다(`gone`의 2초 대기도 없음). 화면: 소리 설정 패널 맨 위 한 줄 `가까운 알림 묶기 [끔 | 5초 | 10초 | 20초]`(하나만 선택, `끔`=`on:false`, 기본 `끔`). 바꾸는 즉시 저장하고 `configure`를 부른다. `windowSec`의 "0=끔" 의미는 쓰지 않는다. 11.2의 묶기 시나리오는 먼저 묶기를 켠다.
3. **[중간] `KINDS.step`과 기존 상태기계의 연결.** 기존 순수 함수(`stepDetector`, `stepCountdown`)의 시그니처는 바꾸지 않고, 내장 종류의 `step`이 `cfgView(t)={kind:t.kind, ...t.p}`를 넘기는 얇은 감싸개가 된다(회귀 테스트는 감싸개 전후 같은 이벤트). `Event`는 `string | {key, info} | {effect:'learn', durationSec}`. `effect`는 `KINDS[k].applyEffect(t, ev)`가 처리한다(버프: `p.durationSec` 저장, 카드 칸 갱신). **`KINDS[k].events`에 `key`가 있는 이벤트만 `Alerts.fire`로 간다.** 그 밖의 키(`appear-unknown`, 묶음 3의 내부 이벤트 등)는 무시한다. 룬 감싸개가 `appear-unknown`을 `appear`로 바꾼다(지금 `:712`의 규칙).
4. **[중간] 저장 이전 규칙의 모순.** 4.2("v2가 없을 때만 v1 이전")에 맞춰 10절을 고쳤다: v2가 깨졌거나 `ver>2`이면 원문을 `-v2-broken`에 보관하고 v1 이전 없이 기본 목록으로 시작한다.
5. **[중간] `loadStore` 반환값.** `loadStore(): {store, status:'ok'|'migrated'|'fresh'|'broken', saveFailed:boolean}`. 고아 정리(4.5)는 `status`가 `ok`·`migrated`일 때만. `targetSnapshot`은 순수 함수 `targetSnapshot(targets, states, ctx, now)`(`targets.js`)와 전역을 묶는 `snapshotNow()`(`ui-watch.js`)로 나눈다.
6. **[중간] `Alerts`의 오디오 준비와 구독 시점.** `Alerts.audioOut()`은 `unlockAudio()`로 `actx`가 생긴 뒤에만 노드를 돌려주고 그 전에는 `null`이다. 묶음 5의 마스터 체인은 `Alerts.onAudioReady(fn)`에서 만든다. `listen` 콜백은 `deliver`가 끝난 직후 한 번 불린다. `AlertRec.custom`은 내 소리 파일을 썼는지다. `flush(now)`는 `tick()`의 `finally` 안에서 부르고, `busy`로 `tick`이 건너뛰어진 메시지에서도 `main.js`가 부른다.
7. **[중간] 오래된 프레임 표시와 건너뛴 틱.** `grab()`은 `{frame, fresh}`를 돌려준다. 숨은 탭에서 `grabFrame`이 시간 초과면 지금처럼 `frame:null`이고, 시간 초과가 아닌 오류로 `video`에 대체되면 `fresh:false`다 [확인 `index.html:578-582`]. `onSkip` 종류도 `enabled=false`이면 `step`을 부르지 않는다(꺼면 상태 초기화, 3.3).
8. **[중간] 즉시 실행 코드와 공유 전역의 위치.** 각 파일은 정의와 `init*()`만 두고 `main.js`가 `initCapture() → initRegister() → initCards() → initSounds() → (묶음 2·5의 init) → Worker 시작` 순서로 부른다. 공유 전역의 소유: `src`·`frame`·`health`는 `capture.js`, `states`는 `detect-run.js`, `reg`는 `register.js`, 대상 저장소는 `targets.js`. 8.2의 인용 행은 `:668`(`matchTemplate` 호출)·`:707`(`stepDetector` 호출), 6.3의 남은 시간 식은 `:367`이 맞다.
9. **[중간] 성능 장치는 측정 뒤로 미룬다.** 1차 범위는 9.3의 ① 대상별 시간 표시와 ④ 버퍼 재사용만. 배율 고정·격틱 검색·`cost()` 경고는 실제 측정(솔 야누스가 왜 node 80ms 대 브라우저 214~460ms인지) 뒤 따로 정한다. `hint`는 저장 형식에서 빼고 메모리 캐시로 둔다. 5.2의 "같은 아이콘 안내"는 뺀다.
10. **[중간] 등록 검사 훅.** 묶음 3·4의 요청으로 `register.validate(t, rects, snap): string|null`을 더한다. 문자열을 돌려주면 저장하지 않고 배너에 그 이유를 보인 뒤 다시 드래그하게 한다.
11. **[낮음]** `remainSec`는 `alertedPre`이거나 주기가 끝났으면 `null`을 돌려준다(이미 끝난 대상이 당겨지지 않게). 내장 대상을 되돌릴 때 같은 이름이 있으면 `솔 야누스 (기본)`처럼 붙인다. 11.2에 "다른 폴더로 복사한 `index.html`에서 설정이 공유되는지" 확인을 더한다(`file://` 저장소 원본은 [추정]). `planGroup` 입력은 `(targets, states, KINDS, now)`.
