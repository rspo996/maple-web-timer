# 사냥 멈춤 알림 (묶음 3) 구현 계획

**목표:** 경험치 막대·숫자 영역이 정한 시간 동안 안 바뀌면 소리·음성으로 알린다(스펙 `2026-11-09-3-idle-alert-design.md`, 15·16·17절이 본문보다 우선). 새 대상 종류 `idle`, 인스턴스 1개.

**실행 방식:** 메인 세션에서 직접 구현(사용자 결정). 태스크마다 실패하는 시험 → 구현 → `node --test`·브라우저 시나리오 → 커밋.

## 1. `KINDS` 공통 확장 (묶음 4도 쓴다)

| 필드 | 기본 | 용도 |
|---|---|---|
| `usesThreshold` | `true` | `false`면 카드의 기준값 슬라이더를 뺀다 |
| `scoreRow(t, st, now)` | 없음 | `{label, text}`. 없으면 지금의 일치도 줄 |
| `thumb(t)` | 없음 | 카드 썸네일 URL. 없으면 `tpl` 또는 내장 아이콘 |
| `actions[].visible(t, st)` | 항상 | 동작 버튼을 보일지 |
| `register.stepText{area,icon}` | 없음 | 등록 배너의 단계 문구 |
| `register.doneNote(t)` | 없음 | 등록 뒤 상태줄 문구 |
| `previewLabel(t, st)` | 없음 | 미리보기 캔버스의 박스와 라벨 `{rect, text, hit, color}` |
| `stripText(t, st, state)` | 없음 | 상태줄 글자(`snooze`·`idle` 같은 종류별 값) |
| `menuLabel`, `defaultName` | 없음 | 대상 추가 메뉴 '다른 알림'에 보일 이름과 새 대상 이름 |
| `events[].noSlot` | `false` | 내 소리 슬롯을 만들지 않는 알림 |

## 2. 정한 것

1. **영역 계속 변함 경고(17-4):** 상태가 새로 시작된 뒤(연결·등록·켜기) 첫 유효 샘플부터 10초 동안 틱의 절반 넘게 변하면 상태줄에 경고한다. 스펙은 "등록 직후"인데, 상태가 새로 시작되는 모든 경우에 하면 연결 직후에도 잡을 수 있어 넓혔다.
2. **감시 중 계속 변함:** 최근 60초 유효 샘플이 100개 이상이고 90% 넘게 변하면 '계속 변함'이 되고 음성으로 한 번 알린다(슬롯 없음, `noSlot`). 70% 아래로 내려가야 풀린다(경계에서 반복해 말하지 않게).
3. **3번 울린 뒤**에는 변화가 확정될 때만 다시 준비한다(17-6). 끊김(`gap`)으로는 풀지 않는다.
4. **변화 기준(`minPx`)은 숫자 칸(3~60)** 으로 둔다. 스펙 4.3의 슬라이더 대신 카드의 기존 입력 칸 형식을 쓴다.
5. **등록 배너 문구:** `사냥 멈춤 ① 경험치 막대와 숫자를 한 번에 꼭 맞게 드래그하세요 · 경험치 숫자나 퍼센트가 영역에 들어가야 해요`.
6. **썸네일**은 너비 200px 이하 PNG로 `p.thumb`에 저장한다.

## 태스크

1. **순수 함수:** `lumaDiffCount`(같음 0, 24 미만 0, 24 셈, 8개만 다름 8), `stepIdle`(계속 변하면 안 울림, 120초에 1번, 반복 2번 뒤 멈춤, `repeatSec=0`이면 1번, 재무장, 번쩍임 무시, `null`이 끼면 처음부터, 울린 뒤 `null`이면 watch, 3번 뒤 `null`로는 재무장 안 함, 쉬기 10분·변할 때까지(15초 무시)·쉬기 중 `null`이어도 시간 점검·시작하면 횟수 초기화, 첫 샘플은 rebase만), `idleText`(45초·90초·240초), `idleStats`(60초 최대·중앙값·확정 횟수).
2. **종류 정의와 공통 확장:** `KINDS.idle`(`isRegistered`, `needsReregister`, `validate` 40×6·높이 8%·너비 40%, `save`, `normalizeP`, `cardFields`, `status` 표 4.3, `stripState`·`stripText`, `events` `alarm`·`busy`, `actions` 쉬기 3종·쉬기 끝내기), `addKindTarget`, `slotsOf`의 `noSlot`, `summarizeStrip`의 `stripText`. 시험은 `tests/idle.test.js`·`tests/targets.test.js`.
3. **화면 연결:** 카드·메뉴·등록·미리보기·상태줄·`SOUNDS.idle`·설명서. 브라우저 시나리오 `tests/browser/idle.mjs`: 메뉴 추가와 상한, 작은 영역 거절, 등록, 정지 → 알림(삼각파) → 반복 2번 → 그 뒤 없음, 변화 → 재무장과 '다시 변했어요', 검은 화면 → 처음부터, 쉬기, 상태줄 '경험치 그대로'·'쉬는 중', 스크린샷 모드에서는 쉼, 해상도 변경 → 다시 등록.
4. **최종 확인:** 모든 단위 시험과 묶음 1·2 시나리오 전부.

## 손으로 볼 것

- 실제 게임 화면에서 경험치가 오를 때 `changedPx`가 몇인지, 정지 화면의 압축 잡음, 높이 8%·너비 40% 상한이 맞는지(스펙 13.2 끝). 숨은 탭의 `video` 대체 프레임이 오래된 프레임인지(6.1).
